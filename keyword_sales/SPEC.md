# 키워드 판매 분석 — 구현 사양

POC 화면: `keyword_sales/index.html` (정적 파일, 목업 데이터로 동작)
작성일 2026-09-07 · 개정 2026-09-08 (2차)

---

## 1. 이 화면이 푸는 문제

**매출부서가 특정 키워드 관련 상품의 판매를 조회해 확인하고, 엑셀로 내려받아 외부에
제공하는 것**이 목적이다. 지금은 검색 결과와 판매 데이터를 따로 뽑아 수작업으로 합치고 있다.

목적이 외부 제공이라 일반 분석 화면과 우선순위가 다르다:

- **화면의 결과물은 파일이다** → 조회는 확인용이고, 완성물은 엑셀이다. 화면은 표와
  내보내기 컨트롤이 중심이며 대시보드형 요약 카드는 두지 않는다.
- **틀린 숫자를 되돌릴 수 없다** → 검색어 관련성 AI 판별로 오탐을 걸러낸다.
  `필사` 검색은 판별 적용 여부에 따라 대상이 17종 ↔ 11종으로 갈린다.
- **나중에 "그 숫자 어떻게 나왔냐"에 답해야 한다** → 산출 조건을 파일 안에 함께 남긴다.
- **사내 정보가 외부로 나가면 안 된다** → 내보내는 파일을 대외 제공용 한 종류로 고정하고,
  전시분류·판매상태·판정 근거·공급률은 파일에 넣지 않는다.

**총 판매량·총 매출 같은 합계 KPI는 화면에 두지 않는다.** 집계 모수(상세 조건·AI 판별)에
따라 값이 크게 흔들리는데, 큰 글씨로 박아 두면 그 숫자만 그대로 인용된다. 합계가 필요하면
엑셀에서 열 합계로 만든다.

**핵심 제약:** 검색 API 응답에는 판매량·매출이 없다. 상품번호(`itemId`)를 조인 키로
판매 데이터를 별도 조회해야 한다.

## 2. 파이프라인 — 순서가 중요하다

```
① 검색 API        키워드 → 상품 목록 (상품번호 포함)
② 상세 조건        분야·태그·재검색으로 모수를 먼저 좁힌다 (§5.1)
③ 판매 집계        상품번호 × 기간 → 판매량 / 매출
④ 정렬·순위        상품 정렬(§4.1) 기준으로 세우고 번호를 매긴다
⑤ AI 관련성 판별   **엑셀 다운로드 시점에만** 호출. '필사' 검색에 걸린
                  '필사적인 밤'을 근거와 함께 무관으로 판정
⑥ 엑셀             대외 제공용은 무관 판정을 뺀 전건
```

**AI 판별이 ⑤에 있는 것이 이 개정의 핵심이다.** 검색할 때마다 LLM을 태우면 조회만 하는
사용자에게 지연·비용이 그대로 전가된다. 판별이 실제로 필요한 시점은 **파일이 외부로
나가는 순간**이므로, 다운로드 직전에 체크박스(기본 켬)로 실행 여부를 고르게 한다.
결과는 파일뿐 아니라 화면 표의 `관련성` 열에도 반영되어 판정을 눈으로 확인할 수 있다.

판별 결과는 `(키워드, 상품번호)` 단위로 캐시되므로 같은 키워드를 다시 내려받을 때는
호출이 없다. 판별 뒤 상세 조건을 넓혀 새 상품이 들어오면 **그 상품만 추가로** 판별한다 —
판별되지 않은 상품의 기본값이 `관련`이라, 그냥 두면 검수 없이 대외 파일에 실린다.

'필사' 키워드가 문제를 그대로 보여준다 — 검색 결과에 『필사의 추격』·『필사적인 밤』
같은 오탐이 섞이고, 그중 일부는 판매량 상위권이다. 2026-01-01~09-07 기준 검색 17종 중
**6종이 무관**으로 판정되어 대외 파일에는 11종만 실린다.

## 3. 서버 계약

### 3.1 검색

```
GET /api/keyword-sales/search
    ?query = 인공지능            (필수)
    &page = 1 &pageSize = 200    (전건 조회 — §4 페이징 참고)
```

상품군·정렬은 파라미터로 넘기지 않는다. **상품군은 좌측 상세 조건에서 거르고**(§5.1),
정렬은 전건을 받아 **화면에서** 다시 세운다(§4.1) — 서버 정렬로는 상세 조건·판매 집계
이후의 순서를 만들 수 없다.

`GET /v1/goods/itemList` 프록시. 응답 봉투를 그대로 전달한다.

```jsonc
{ "success": true, "message": "OK", "errorCode": null,
  "data": {
    "meta": { "apiTitle": "...", "query": "인공지능", "total": 214, "page": 1, "pageSize": 20 },
    "data": { "items": [ { "sortOrder": 1, "itemId": "194483933", "title": "...",
      "subTitle": "...", "author": "...", "publisher": "...", "isbn13": "...", "ean": "...",
      "shopPrice": 32000, "salePrice": 28800, "supplyRate": 68, "publishDate": "2026-08-05",
      "itemStatus": "판매중", "dispCategory": "001001003032", "dispCategoryName": "...",
      "starScore": 4909, "reviewCount": 11, "goodsStatGbSort": 2,
      "goodsGroup": "국내도서",
      "hashtags": ["청년패스", "인공지능", "노동"],
      "cover": "...", "link": "..." } ] }
  } }
```

- `goodsGroup`: 상품군(`국내도서` / `eBook` / `외국도서` …). 좌측 분야 트리의 최상위다.
- 표지: `https://image.yes24.com/goods/{itemId}/L`
- 상세: `https://www.yes24.com/product/goods/{itemId}`
- 실패: `errorCode` = `SEARCH_001`(결과 없음) / `INVALID_PARAM`
- `hashtags`: 사내 검색 응답의 `해시태그` 필드(공백 구분 문자열)를 배열로 파싱해 전달한다.
  화면에서 **검색 키워드와 일치하는 태그를 강조**해 "왜 이 상품이 걸렸는지"를 보여주고,
  AI 관련성 판정의 입력으로도 넘긴다 — 제목·부제만으로 애매한 상품의 판단 근거가 된다.
  (태그 운영 현황은 `tag_monitoring` POC 참고. `청년패스`만 달린 상품은 미태깅 취급)

### 3.2 AI 관련성 판별 (내부 AI API 경유)

**호출 시점은 엑셀 다운로드 직전**이며, 화면의 `검색어 관련성 AI 판별` 체크박스가
켜져 있을 때만 호출한다(기본 켬). 검색 시점에는 호출하지 않는다.

```
POST /api/keyword-sales/relevance
{ "query": "필사",
  "items": [ { "itemId", "title", "subTitle", "author", "publisher", "dispCategoryName" } ] }

→ { "rows": [ { "itemId": "195330019", "verdict": "excluded",
                "confidence": 0.95,
                "reason": "제목의 필사는 필사적(必死的)의 일부로 쓰였을 뿐, 필사 행위와 무관한 장편소설이다." } ] }
```

구현 시 반드시 지킬 것:

- **배치 1회 호출.** 상품 1건당 1회 호출 금지 — 200종이면 지연·비용이 선형으로 터진다.
- **응답은 `itemId`로 매칭.** 순서·개수가 요청과 다를 수 있으므로 인덱스를 신뢰하지 않는다.
- **누락은 보수적으로 처리.** 응답에 없는 `itemId`는 `relevant` + `confidence: null`.
  (놓치는 쪽보다 남기는 쪽이 안전 — 담당자가 화면에서 직접 제외할 수 있다)
- **`(query, itemId)` 키로 캐싱.** 같은 키워드 재검색 시 재판정하지 않는다.
- `confidence < 0.7`은 화면 `관련성` 열에 `검토 필요` 배지로 표시한다.
- **판별 대상은 상세 조건을 통과한 상품**이다. 검색 전건이 아니라 `scoped` 집합을 보낸다 —
  실서비스 규모(`인공지능` 6,919종)에서 전건을 보내면 비용이 그대로 커진다.

### 3.3 판매 집계

```
POST /api/keyword-sales/stats
{ "itemIds": ["194483933", ...], "from": "2026-01-01", "to": "2026-09-07" }

→ { "rows":  [ { "itemId", "qty", "amount" } ],
    "base":  [ { "itemId", "qty", "amount" } ],     // 비교 구간 (전년 동기 또는 직전 동기간)
    "total": { "qty", "amount" } }
```

- 조인 키는 **상품번호(`itemId` = `GOODS_NO`)** — `ebook_solo_pub/SPEC.md`와 동일한 키다.
- 매출액 = `판매량 × 판매가`(정가 아님).
- `base` 구간은 §4의 비교 구간 규칙을 따른다 (1년 이하 → 전년 동기, 초과 → 직전 동기간).
- **`itemIds`는 검색 결과 전체를 보낸다.** 화면 `pageSize`(20)와 무관하게 순위가 정확하려면
  전체 집합의 판매량이 필요하다. 상한이 필요하면 `statsLimit`(예: 200)을 별도로 둔다.
- **집계 단위(일/주/월/연) 개념은 없다.** 화면은 조회 기간의 **합계**만 쓴다. 기간 내
  구간별 분해는 차트를 제거하면서 함께 없앴으므로(§6) 응답에 버킷 배열이 필요 없다.
  나중에 월·연 추이 차트를 되살린다면 그때 `unit` + `buckets`를 추가한다.
- 기간은 화면에서 날짜 입력과 프리셋(`올해 / 최근 1년 / 최근 3년 / 최근 10년`)으로 지정한다.

## 4. 클라이언트 계산

순위·점유율·증감률은 **서버가 아니라 화면에서** 계산한다 — 상세 조건, 정렬, AI 판별
적용 여부에 따라 모수와 순서가 바뀌기 때문이다.

| 항목 | 계산 |
|---|---|
| 번호·순위 | 상세 조건을 통과한 집합을 현재 정렬로 세운 순서 (1부터) |
| 증감률 | `(현재 − 비교구간) ÷ 비교구간`. 비교구간 판매량이 0이면 `신규` (엑셀 전용) |
| 점유율 | 해당 상품 ÷ **파일에 담긴 상품** 합계, 분자·분모 모두 순위축 (엑셀 전용) |

**첫 열의 라벨은 정렬에 따라 바뀐다** — `판매량순`·`매출순`이면 `순위`, 상품 기준 정렬
(인기도·정확도·신상품·등록일·가격·평점·리뷰)이면 `번호`다. 가격순으로 세워 놓고 1, 2, 3을
`순위`라고 부르면 판매 순위로 읽힌다.

**순위축(`rankKey`)** 은 `매출순`이면 매출, 그 외에는 판매량이다. 점유율은 이 축을 따른다 —
판매량으로 순위를 매기면서 매출 점유율을 보여주면 1위의 점유율이 2위보다 낮게 나온다.
엑셀 헤더도 `판매량 점유율` / `매출 점유율`로 바뀐다.

**점유율의 모수는 "그 파일에 담긴 상품"이다.** AI 판별을 적용하면 무관 판정을 뺀 집합,
적용하지 않으면 전건이라 두 파일의 점유율이 다르다. 산출 조건 시트의 `파일에 담긴 상품`이
그 모수를 명시한다.

**비교 구간**은 조회 기간 길이에 따라 자동으로 정해진다 — 1년(366일) 이하면 **전년 동기**
(같은 구간을 1년 전으로 이동), 그보다 길면 **직전 동일 길이 기간**. `전년 동기 판매량`과
`증감률`은 **엑셀에만** 있다. 화면 표에서는 뺐다 — 확인 단계에서 보는 값이 아니라
기사에 쓰이는 값이고, 열이 늘면 표가 노트북 폭을 넘긴다.

전체/분야 내 순위가 필요해지면 `stats` 응답에 `catRank`를 추가해 확장한다.

### 4.1 상품 정렬

정렬 목록은 **YES24 상품검색(`www.yes24.com/product/search`)이 제공하는 8종을 그대로**
쓰고, 이 화면의 목적인 판매 기준 2종을 앞에 둔다. 사용자가 이미 아는 이름이라 설명이 필요
없고, 나중에 검색 API의 `sort` 파라미터로 넘길 때 매핑이 1:1이다.

| 그룹 | 옵션 | 기준 |
|---|---|---|
| 판매 기준 | 판매량순(기본) / 매출순 | 조회 기간 집계값 |
| 상품 기준 | 인기도순 | 검색 응답 순서(`sortOrder`) |
| | 정확도순 | 키워드가 걸린 위치 점수 (태그 4 > 제목 2 > 제목 첫머리 +1 > 부제 1) |
| | 신상품순 | `publishDate` 내림차순 |
| | 등록일순 | 실 API는 `REG_DTS`. 목업에는 등록일이 없어 상품번호(채번 순서)로 대용 |
| | 최저가순 / 최고가순 | `salePrice` |
| | 평점순 | `starScore` |
| | 리뷰순 | `reviewCount` |

표의 `판매량`·`매출` 헤더를 클릭하면 셀렉트가 그 값으로 함께 바뀐다 — 정렬 상태가 두
군데로 갈라지지 않게 한 곳(`S.sort`)에서만 관리한다.

### 페이징

**페이징은 표시 단위일 뿐, 집계 모수가 아니다.** 검색 API의 `page`/`pageSize`로 20건만
받아 오면 그 20건 안에서의 순위가 되어 전부 틀린다. 그래서:

- `search`는 검색 결과 **전건**(상한 `statsLimit`, 예: 200)을 받고, `relevance`·`stats`도
  전건에 대해 수행한다.
- 순위·점유율을 전건 기준으로 계산한 **뒤에** 화면에서 잘라 보여준다.
- 엑셀 다운로드는 **현재 페이지가 아니라 전건**을 내보낸다.
- 페이지는 검색·기간·정렬·상세 조건이 바뀌면 1페이지로 되돌린다.
- 페이지당 10/20/50/100건(기본 20).

## 5. 화면 동작

1. 검색 응답 도착 → **표를 즉시 렌더** (AI 호출 없음)
2. 좌측 상세 조건·기간·정렬로 대상을 다듬는다
3. `엑셀 다운로드` 클릭
   - 체크박스 켬 → 버튼이 `관련성 판별 중…`으로 바뀌고 `relevance` 배치 1회 호출 →
     결과가 표의 `관련성` 열과 상단 결과 바에 반영된 **뒤에** 파일이 만들어진다
   - 체크박스 끔 → 즉시 파일 생성. 이미 판별한 결과가 있어도 **파일에는 반영하지 않는다**
     (체크박스 설명에 "해제하면 검색 결과 전건이 그대로"라고 적어 둔 대로 동작해야 한다)

**화면 구성**

```
검색줄  [키워드 ────] │ [조회 기간 from ~ to] [올해][1년][3년][10년]   [검색]
┌ 상세 조건 ┬ 상품 목록 카드 ─────────────────────────┐
│ 재검색    │ 헤더: 건수 · 상품 정렬 셀렉트            │
│ 분야      │ 내보내기 바: [v] AI 판별 · 엑셀 다운로드 │
│ 상품태그  │ AI 판별 결과 바 (판별 후에만)            │
│           │ 표 + 페이저                              │
└───────────┴──────────────────────────────────────────┘
```

**화면은 검색줄과 목록, 둘뿐이다.** 이용 가이드 카드와 산출 조건 카드는 뺐다 —
조회 중에 필요한 정보는 좌측 상세 조건과 목록 헤더 요약(`검색 n종 · 조건 적용 n종 · 기간`)에
이미 다 있고, 두 카드가 표를 화면 아래로 밀어내 정작 봐야 할 숫자가 안 보였다.
**산출 조건은 엑셀 두 번째 시트에 그대로 남는다**(§6) — 그 기록이 필요한 시점은
파일이 외부로 나간 뒤이지 조회 중이 아니다.

**검색줄은 한 줄이다.** 키워드와 기간을 둘 다 정해야 결과가 성립하는데 두 줄로 끊으면
기간을 안 보고 검색부터 누른다. 900px 이하에서만 키워드가 한 줄을 차지하도록 접힌다.
데모용 키워드 칩(`인공지능 · 필사 · 클로드 · 파이썬`)은 검색줄에서 뺐다 — 실서비스에는
없는 요소이고, 검색 실패 시 안내 문구가 같은 역할을 한다(문구는 `KS_DATA.KEYWORDS`에서
생성하므로 목업 키워드를 늘려도 어긋나지 않는다).

**표 컬럼** — `순위/번호 · 상품번호 · 도서명·부제 · 해시태그 · 출간일 · 판매가 ·
판매량 · 매출` (+ 판별 후 `관련성`).

- 부제는 별도 열이 아니라 **도서명 아래**에 붙인다. 열을 하나 줄여야 표가 노트북
  폭(1280px)에서 가로 스크롤 없이 들어온다. 엑셀에는 별도 열로 나간다.
- **전년 동기·증감·행별 제외 버튼은 없다.** 앞의 둘은 엑셀로 옮겼고(§4), 제외 버튼은
  판별 시점이 다운로드로 옮겨가면서 근거를 잃었다 — 다운로드 직전에만 판정이 존재하므로
  그 사이에 사람이 개별 행을 뒤집을 구간이 없다.

**판정 확인**

- 무관 판정 행은 **숨기지 않고** 흐리게 남기고 판정 근거를 함께 보여준다. 판정이 맞는지
  검증할 수 있어야 하기 때문이다.
- 결과 바의 `무관 상품 숨기기` 토글은 **표시 옵션일 뿐**이다. 번호와 엑셀 범위에는 영향이
  없다 — 엑셀 범위는 `AI 판별` 체크박스가 정한다(§6).
- 판별되지 않은 상품(조건을 넓혀 새로 들어온 건)은 `관련성` 열에 `—`로 보이고, 다음
  다운로드에서 그 상품만 추가로 판별된다.

### 5.1 좌측 상세 조건 — 실서비스 규모의 전제

실제 `인공지능` 검색은 상품 6,919종(국내도서 4,638종)이다. 이 규모에서 AI 판정 결과를
한 건씩 눌러 검수하는 것은 불가능하다. 그래서 **상세 조건을 AI 판정보다 앞에 적용해
모수를 먼저 좁힌다.**

```
검색 전건 → ① 상세 조건(분야·태그·재검색) → ② AI 관련성 판별(다운로드 시) → ③ 눈으로 확인
```

항목은 둘뿐이다(+재검색). 검색 조건(도서명/저자/출판사)과 `AI 활용`은 언론 집계에 쓰이지
않아 넣지 않았다. 상단 검색줄의 `국내도서`·`인기도순` 셀렉트도 제거했다 — 상품군은 아래
분야 트리로 흡수했고, 정렬은 전건을 집계하므로 결과에 영향이 없다.

| 항목 | 동작 |
|---|---|
| 분야 | **2단 트리.** 상품군(`goodsGroup`) 아래 전시분류 대분류. 하위 항목의 키는 `상품군|대분류` 라서 국내도서의 `컴퓨터/모바일` 과 eBook 의 `컴퓨터/모바일` 은 별개로 동작한다. 상품군을 켜면 **그 상품군의** 하위가 모두 함께 켜지고, 이후 하위를 개별로 뺄 수 있다 |
| 상품태그 | `hashtags` 다중 선택. 하나라도 걸리면 포함(OR) |
| 결과 내 재검색 | 도서명·부제 부분 일치 |

```
분야
  국내도서            32
     컴퓨터/모바일     15
     과학              3
     경제경영          3
     …
  eBook                3
     컴퓨터/모바일      2
     자기계발           1
```

**분야가 가장 강력하다.** 오탐이 분야로 뭉치기 때문이다 — 인공관절은 의학, 인공위성은
공학, 인공 낙원은 소설. 목업 `인공지능` 35종에서 분야 `의학`만 고르면 2종이 남는데 그
2종이 모두 무관 판정 대상이다(대외 파일 0종). 오탐과 분야가 거의 일치한다는 뜻이다.
AI 호출보다 싸고 빠르며 외부에 설명하기도 쉽다. 판별 대상이 상세 조건 통과분이라
**조건을 먼저 좁히면 LLM 비용도 그만큼 줄어든다.**

**태그만으로 모수를 잡으면 안 된다.** `tag_monitoring` POC 실측에서 메인 업데이트 도서
33종 중 15종(45%)이 미태깅이었다. 태그 기준만 쓰면 절반을 놓친다. 분야로 모수를 잡고
태그는 보조 근거·AI 판정 입력으로 쓴다.

**패싯 카운트는 검색 결과 전건 기준으로 고정한다.** 선택할 때마다 카운트가 바뀌면 무엇을
고를지 판단할 수 없다 (YES24 검색 좌측과 같은 방식).

**선택한 조건은 엑셀의 산출 조건 시트에 반드시 기록한다.** 조건이 곧 "이 키워드 시장의
정의"이므로, 기록이 없으면 그 숫자를 재현할 수 없다. `대상` 항목은 선택한 상품군을 따른다
(미선택이면 `전체`).

### 5.2 아직 넣지 않은 것 — 실서비스 전 필요

| 항목 | 내용 |
|---|---|
| **판정 결과 영구화** | 지금은 판정 캐시가 브라우저 `localStorage`에만 남는다. `(키워드, 상품번호) → 판정`을 서버에 저장하면 판별이 일회성 비용이 아니라 누적 자산이 된다. 두 번째 조회부터는 신규 상품만 판별하면 된다. **실서비스 성패를 가르는 항목** |
| **담당자 수동 조정** | AI 오판을 사람이 덮어쓰는 경로. 판정을 서버에 영구화한 뒤에 붙여야 의미가 있다 — 지금 붙이면 새로고침마다 날아간다 |
| **조건 프리셋 저장** | 분야·태그 조합이 매번 달라지면 분기 비교가 깨진다. 조합을 저장해 다음 조회에 그대로 불러 쓴다 |
| **검수 큐** | `신뢰도 < 0.85 AND 누적 판매량 상위 95% 구간`만 검수 대상으로 제시. 나머지는 판정대로 확정하고 `미검수 N건 = 합계의 0.8%`로 오차 범위를 명시 |
| **영향도 표시** | 행마다 `제외 시 합계 −3.2%`. 목업 26종에서도 상위 5종이 51.6%, 하위 5종은 다 합쳐 1.98%다. 무엇부터 볼지가 자명해진다 |
| **일괄 처리** | 다중 선택 + 분야 단위 일괄 제외 |
| **판별 진행률** | 지금은 버튼이 `관련성 판별 중…`으로만 바뀐다. 수천 종을 배치로 돌리면 진행률과 취소가 필요하다 |

## 6. 엑셀 다운로드

`assets/js/xlsx.js` — 외부 라이브러리 없는 XLSX 생성기(`downloadXlsx`), `ebook_solo_pub`에서
가져와 다중 시트를 지원하도록 확장했다. **버튼 1개, 시트 2개**다.

**내보내는 파일은 대외 제공용 한 종류다.** 파일명은 `키워드판매_{키워드}_{시작}-{종료}.xlsx`.

`대외 제공용 / 내부 확인용` 셀렉트는 없앴다. 판정 근거를 확인하는 자리가 **화면 표의
`관련성` 열**로 옮겨오면서, 검수만을 위해 별도 파일을 받을 이유가 사라졌기 때문이다.
확인은 화면에서, 파일은 내보내기용 하나 — 그래야 "내부용 파일을 실수로 외부에 보냈다"가
구조적으로 불가능해진다.

**`검색어 관련성 AI 판별` 체크박스(기본 켬)** 가 다운로드 버튼 옆에 있다. §2·§3.2 참고.

| 체크 | 담기는 상품 | 산출 조건 시트의 `AI 관련성 판별` |
|---|---|---|
| 켬 | 무관 판정 제외 | `적용 (관련 n종 / 무관 m종)` |
| 끔 | 전건 | `미적용 — 검색 결과 전건` |

**화면에 판정이 떠 있어도 체크를 끄고 받은 파일에는 반영되지 않으므로**, 파일만 보고도
구분할 수 있어야 한다.

내보낼 상품이 0종이면 파일을 만들지 않고 안내만 띄운다 — 조건이 과하게 좁거나 전부
무관으로 판정된 경우다.

| 시트 | 내용 |
|---|---|
| `상품별 집계` | **목록만.** 1행이 헤더, 2행부터 데이터 |
| `산출 조건` | `항목 / 내용` 2열 표. **화면에는 없고 파일에만 있다** |

컬럼:

```
순위(또는 번호) | 상품번호 | 도서명 | 부제 | 해시태그 | 저자 | 출판사 | 출간일 |
정가 | 판매가 | 판매량 | 매출액 | ISBN13 |
{전년 동기|직전 동기간} 판매량 | 증감률(%) | {판매량|매출} 점유율(%)
```

- **무관 판정 상품은 뺀다.** 어떤 책을 왜 뺐는지는 내부 판단이라 외부로 나가면 안 된다.
  판정과 근거는 화면 `관련성` 열에서 확인한다.
- 첫 열의 라벨은 화면과 같이 정렬에 따라 `순위`/`번호`로 바뀐다(§4.1).
- 전시분류명·판매상태·AI 판정·신뢰도·판정근거·공급률·제조사·공급사·전시분류코드는
  **넣지 않는다** (사내 정보).
- 현재 페이지가 아니라 **전건**을 내보낸다.
- 화면에서 뺀 `전년 동기 판매량`·`증감률`은 **엑셀에는 남긴다**. 기사에 쓰이는 숫자라
  파일에는 있어야 한다.

**산출 조건은 별도 시트에 둔다.** 표 위에 주석이 섞여 있으면 정렬·필터·복사할 때마다
걸리기 때문이다. 화면 상단 요약과 같은 내용을 항목별로 편다:

```
키워드              필사
조회 기간            2026-01-01 ~ 2026-09-07
대상                전체
검색 결과            17종
상세 조건            없음
상세 조건 적용 후     17종
AI 관련성 판별       적용 (관련 11종 / 무관 6종, 검토 필요 1종)
파일에 담긴 상품      11종
상품 정렬            판매량순
매출 기준            판매량 × 판매가 (부가 할인·쿠폰 미반영)
비교 구간            2025-01-01 ~ 2025-09-07 (전년 동기)
내보내기 범위         대외 제공용 — 무관 판정 상품 제외, 사내 정보 미포함
추출 일시            2026-09-08 10:59
```

숫자 컬럼은 문자열이 아닌 number로 넣어 엑셀에서 바로 합계·정렬이 되게 한다.
헤더 볼드 + 틀 고정 + 자동필터는 `xlsx.js`가 이미 적용한다.

### 넣지 않기로 한 것 (검토 후 제외)

다시 검토하지 않도록 판단 근거를 남긴다.

**상품 × 기간 교차표** — 상품 수명이 조회 기간보다 짧다. 목업 56종의 출간일이 1년 구간에
몰려 있어 10년(120개월) 창에 넣으면 전체 6,720셀 중 출간 이후 셀이 245개(3.6%)뿐이고
나머지 96.4%가 구조적으로 0이 된다. 실데이터에서도 도서 수명은 보통 1~3년이라 같다.
스파크라인·멀티라인도 같은 이유로 제외했다.

**기간별 추이 차트** — 언론 제공에 쓰이지 않아 제거했다. 조회 기간에 따라 묻는 질문이
다른데, 어느 쪽도 차트를 필요로 하지 않았다:

| 기간 | 실제 질문 | 답하는 것 |
|---|---|---|
| 30~90일 | 지금 뭐가 잘 나가나 | 표(순위·판매량) |
| 1~10년 | 이 키워드 시장이 커졌나 줄었나 | 엑셀의 전년 동기 판매량·증감률 |

덧붙여 장기 조회에서 차트는 물리적으로 못 읽는다 — 10년을 일 단위로 그리면 셀 폭 0.3px에
막대 폭 2px라 막대가 서로 겹쳐 검은 띠가 된다(월 단위 121개만 정상). 필요해지면 월·연
단위 전용으로 되살리되, 일 단위에는 기간 상한을 걸어야 한다.

**순위 변동(▲▼)** — MD의 일상 모니터링용이고 외부 제공에는 쓰이지 않는다. 장기 조회에서는
대부분 `NEW`로 나와 노이즈만 된다. 대신 `증감률`(비교 구간 대비)을 엑셀에 넣었다.

**총 판매량·총 매출 KPI 카드** — 모수가 상세 조건·AI 판별에 따라 크게 흔들리는데 큰 글씨로
박아 두면 그 숫자만 인용된다. 합계가 필요하면 엑셀 열 합계로 만든다(§1).

| 항목 | 상태 |
|---|---|
| 검색 API | 목업 — `assets/js/data.js`에 키워드 4종(`인공지능` 35(eBook 3) / `필사` 17(eBook 2) / `클로드` 8 / `파이썬` 8). 전년 동기 비교가 성립하도록 2023~2024년 출간 백리스트를, 분야 트리가 성립하도록 eBook 판을 포함 |
| AI 관련성 판별 | 목업 — 판정·신뢰도·근거를 상품별로 하드코딩, `700ms + 45ms×건수`(최대 2.6s) 지연 + localStorage 캐시. 다운로드 시점에만 호출 |
| 판매 데이터 | 목업 — 상품번호를 시드로 하는 결정론적 PRNG (새로고침해도 같은 값) |
| 화면·집계·엑셀 | **실제 동작** |

목업 판매량 = `기저량 × 요일계수 × 신간감쇠 × 노이즈`, 기저량은 상품별 28~448(롱테일 분포),
생성 범위는 2026-09-07 기준 최근 1,300일(약 3.5년). 출간일 이전은 0.

목업에 없는 키워드를 입력하면 `SEARCH_001` 안내를 띄운다.

## 8. 파일

```
keyword_sales/
  index.html              앱 셸 + 마크업
  assets/css/style.css    ax-labs-platform style-base.css + 페이지 전용 .ks-* 클래스
  assets/fonts/paperlogy/ (미사용 — Pretendard 로 교체하며 @import 제거)
  assets/js/data.js       목업 카탈로그 + 결정론적 PRNG
  assets/js/app.js        목업 API · 집계 · 렌더 · 엑셀
  assets/js/xlsx.js       XLSX 생성기 (ebook_solo_pub에서 복사 후 다중 시트 지원 추가)
```

표 컬럼·엑셀 컬럼은 `XLSX_COLS.common` 한 곳에서 나온다 — 대외/내부 두 벌을 두던 구조를
없앴다.

`xlsx.js`는 원본이 시트 1개만 지원해서 **다중 시트를 지원하도록 확장**했다.
`downloadXlsx(파일명, [시트1, 시트2])` 형태로 배열을 넘기면 되고, 시트별로
`{ name, cols, header, rows, filter }`를 갖는다(`filter: false` 면 자동필터 생략).
단일 객체를 넘기던 기존 호출 방식도 그대로 동작한다.

UI는 `.claude/skills/apply-ax-labs-ui` 기준 — vercel 테마(primary 니어블랙), 색은 토큰
변수만 사용하고 하드코딩 hex를 쓰지 않는다.

**본문 폰트는 Pretendard**다(`ebook_solo_pub`과 동일, jsDelivr CDN). Paperlogy는 쓰지
않으므로 `@import`를 뺐다 — `assets/fonts/paperlogy/`는 남아 있지만 로드되지 않는다.

**본문 글자는 플랫폼 기준보다 한 단계(+1px) 크다.** `ebook_solo_pub`과 같은 방식으로,
스타일시트 맨 아래 `본문 가독성` 블록에서 `page-content` 안쪽 요소만 덮어쓴다.
사이드바·상단 헤더는 플랫폼 기준을 그대로 둔다 — 앱 셸까지 키우면 다른 화면과 어긋난다.
**표 글자를 키우면 열 폭도 같이 커진다.** 아래 폭 규칙의 분기점은 이 +1px 상태를
기준으로 다시 잡은 값이다.

**폭 규칙** — 표가 카드 안에 가로 스크롤 없이 들어와야 한다. 판매량·매출이 화면 밖으로
밀리면 확인 자체가 안 된다. 그래서:

| 뷰포트 | 처리 |
|---|---|
| >1495px | 좌측 상세 조건(232px) + 표. 여유 폭은 도서명이 흡수 |
| ≤1495px | 상세 조건을 **표 위로** 올리고 표에 폭을 전부 준다 |
| ≤1260px | `해시태그` 열을 접는다 (엑셀에는 그대로 나간다) |
| ≤1000px | 사이드바를 접는다 |
| ≤900px | 상세 조건 3단을 1단으로, 검색줄의 키워드를 한 줄로 |

`도서명`(min 160px)만 가변이고 나머지는 내용에 맞춘 고정 폭이다. `판매량`(72px)과
`매출`(96px)은 자릿수가 달라 폭을 따로 준다 — 한 클래스로 묶으면 매출에 맞춘 폭이
판매량에도 붙어 표가 그만큼 넓어진다.

**`해시태그`는 250px** — 목업 4개 키워드 전체에서 **태그 3개까지 한 줄에** 들어가는 폭을
실측해 잡았다(3개 최대 소요 231px + 셀 여백). 태그 4개짜리는 두 줄로 넘어간다. 4개까지
한 줄에 넣으려면 300px 가까이 필요한데 그만큼 위 분기점이 전부 올라간다. 3개까지가
손익분기점이다.

**표 위로 올라간 상세 조건은 3단 그리드**(재검색 / 분야 / 상품태그)이고, 각 섹션 안의
목록은 **세로 2단**으로 흐른다. 항목을 가로로 늘어놓으면 분야의 2단 트리
(상품군 > 대분류)가 평평해져 무엇이 무엇의 하위인지 사라진다.

**태그 폭·좌측 패널 폭·본문 글자 크기를 바꾸면 위 표의 분기점도 함께 옮겨야 한다.**
표에 남는 폭이 줄수록 좌측 패널을 붙일 수 있는 하한(1495)·태그 열을 유지할 수 있는
하한(1260)·사이드바를 유지할 수 있는 하한(1000)이 모두 같이 올라간다.

열 폭·패널 폭·글자 크기를 바꾼 뒤에는 **각 구간에서 표가 가장 좁아지는
1496 / 1261 / 1001px 세 지점**에서 `.ks-table-wrap`의 `scrollWidth === clientWidth`인지
확인한다.

실행: `node serve.js` 후 `http://localhost:8942/keyword_sales/`
