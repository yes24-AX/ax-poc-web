# 질문 1 — 자리 선점이 옳은 선택인가

## 결론: 방향은 옳지만, 고르신 근거가 사실이 아닙니다

"답이 열리는 순간의 상단 높이를 그 자리에서 잴 수 없었다 — 한 프레임 뒤 · `ResizeObserver` · `scrollHeight` · 절대배치 후 개별 측정까지 넷 다 0 이나 옛 값"이라 하셨는데, **잴 수 있습니다.** 그리고 그 방법은 이 파일이 이미 다른 곳에서 쓰고 있습니다 — `measureFly()`(`h1:1668-`)가 열 머리의 활자를 카드 이름에 **잠깐 입혀 재고 되돌리는** 바로 그 기법입니다.

`.asked` 를 잠깐 켜고 `getBoundingClientRect()` 로 **동기 레이아웃을 강제**한 뒤 되돌리면 됩니다. 실측(현재 판에서 그대로 실행):

| 해상도 | 접힘 | 열림(임시 측정) | 차이 | 복원 |
|---|---|---|---|---|
| 1440×900 | 262 | **465** | 203 | 정확 |
| 1366×768 | 258 | **461** | 203 | 정확 |
| 375×667 | 199 | **375** | 176 | 정확 |

두 번 반복해도 값이 같고 원상 복구도 정확합니다(`✓ 재현·복원 정확`). 실패하신 넷은 전부 **`display:none` 인 요소의 높이를 직접 물어본 것**이라 0 이 나온 것이고, 상태를 바꿔 놓고 부모를 재면 나옵니다.

## 그래서 무엇을 권하는가

**빈 자리 대 잘림의 맞바꿈은 사실 강요된 선택이 아닙니다.** 셋째 길이 있습니다.

```

② 격자의 "자리"는 접힌 높이에 둔다    → 빈 자리가 없다
```

`textH` 를 두 개 재서 `avail` 계산(`h1:1628`)에는 **열린 높이**를, `gyTop` 계산(`h1:1659` 부근)에는 **접힌 높이**를 쓰면 끝입니다. 지금 코드에서 줄 몇 개입니다.

이러면 ⓐ 홈의 240px 빈 자리가 사라지고, ⓑ 768 높이 잘림도 그대로 닫혀 있고, ⓒ 모바일 회귀도 같이 사라집니다(크기를 열린 높이로 고르므로).

## 현재 방식의 부작용 — `visibility:hidden` 은 다른 경로를 깨지 않습니다

확인한 범위에서는 깨끗합니다.

| 경로 | `#askreply` | `.asknote` | 버튼 | 판정 |
|---|---|---|---|---|
| 연출(홈) | `hidden` → 물으면 `visible` | 샘플과 다를 때만 | `묻기` | 정상 |
| 축소 모션 | `visible` | **항상 표시** | `샘플 답` | 정상 |
| JS 완전 차단 | `visible` | **항상 표시** | `샘플 답` | 정상 |
| `←`/`→` 왕복 후 홈 복귀 | `hidden`, `asked` 해제 | — | — | 정상 |

`body:not(.js) .asknote{display:block}` 도 두 폴백 경로에서 정확히 켜지고, `askecho` 기본값이 샘플 질문이라 답 카드가 예시로 읽힙니다. **묻지 않은 질문에 답한 것처럼 보이는 상태는 사라졌습니다.**

다만 셋을 짚어 둡니다.

1. **240px 빈 자리는 실제로 눈에 띕니다.** 1440×900 캡처에서 질문 바 아래(310)부터 카드(557)까지 비어 있어, 관객이 가장 오래 머무는 화면 한복판이 미완성으로 읽힙니다. 위의 셋째 길을 권하는 이유입니다.
2. **`aria-live` 가 조용해졌습니다.** `#askreply` 는 이제 항상 DOM 에 있고 `askecho` 기본값이 샘플 질문이라, **샘플 그대로 물으면 내용이 하나도 안 바뀌어** 스크린리더가 아무것도 읽지 않습니다. 예전 `display:none → flex` 는 영역 등장으로 읽혔습니다. `submit()` 에서 `ask.setAttribute('aria-busy', …)` 를 토글하거나, 답 라벨에 상태 한 마디를 넣어 변화를 만들어 주면 됩니다.
3. **`#foot` 위로 1~6px 물립니다.** 답을 연 뒤 1440×900(862 vs foot 861) · 1152×864(831 vs 825) · 1024×768(735 vs 732)에서 카드 아랫줄이 하단 안내줄에 살짝 겹칩니다. `compTop` 예산의 상수 `40`(`h1:1628, 1651`)이 `#foot` 의 실제 높이(약 39~45px)보다 조금 작아서 생기는 계통 오차입니다. `#foot` 을 실측해 빼면 정확해집니다.

# 질문창 폴백 — `readonly` 방식에 대한 의견

**`noGsap`(연출 파일 미로드) 과 JS 완전 차단에는 `readonly` 가 더 낫습니다.** 제출을 받아 줄 수단이 아예 없는 경로에서 입력을 열어 두는 건 의미가 없고, "조작 자체를 막는 쪽이 덜 배신한다"는 판단에 동의합니다.

**다만 축소 모션에는 반대합니다.** 그 경로는 **스크립트가 살아 있습니다** — 배너를 만들고 버튼에 리스너를 다는 코드가 바로 그 자리에서 돌고 있습니다. 즉 기술적 제약이 아니라 선택으로 입력을 막은 것인데, 그 대상이 **"동작 줄이기"라는 접근성 설정을 켠 사용자**입니다. 접근성 설정을 켰다는 이유로 다른 사람은 쓸 수 있는 기능을 못 쓰게 되는 형태라, 이 파일이 지금까지 지켜 온 원칙(축소 모션에도 전체 내용을 펼치고 `그래도 재생` 을 주는)과도 어긋납니다.

`h1:1264` 의 분기가 이미 `reduced` 와 `noGsap` 을 구분하고 있으니 이렇게 가르면 됩니다.

```js
if(reduced || noGsap){
  … 배너 …
  if(reduced){                       // 스크립트가 살아 있는 경로 — 질문창을 연다
    input.removeAttribute('readonly');
    send.textContent = '묻기';
    send.addEventListener('click', staticSubmit);
    input.addEventListener('keydown', e=>{ if(e.key==='Enter'){ e.preventDefault(); staticSubmit(); } });
  }
  return;
}
/* GSAP 도 layout() 도 필요 없는 세 줄 */
function staticSubmit(){
  const typed = (input.value||'').trim();
  echo.textContent = typed || SAMPLE_Q;
  ask.classList.toggle('offsample', !!typed && typed !== SAMPLE_Q);
  ask.classList.add('asked');
}
```

축소 모션에서는 `#askreply` 가 이미 `visible` 이므로 `.asked` 만 붙으면 됩니다. 3줄로 축소 모션 사용자도 같은 정직함과 같은 기능을 갖습니다.

작은 것 하나 더 — 지금 축소 모션·JS 차단에서 `샘플 답` **버튼을 눌러도 아무 일이 없습니다**(실측 `asked:false`). 문구가 명사라 라벨로 읽히긴 하나 포커스를 받고 활성화되는 `<button>` 이라 죽은 컨트롤입니다. 위처럼 축소 모션에서 살리면 남는 건 JS 차단뿐이고, 그때는 `<button>` 대신 `<span class="askbtn" aria-hidden="true">` 로 두고 JS 가 버튼으로 교체하는 방법이 깔끔합니다(우선순위 낮음).

# 정리

이번 라운드도 지적을 정확히 닫았습니다. 특히 `matchMedia` 통합은 제가 네 라운드에 걸쳐 세 번 지적한 **경계 불일치 계열을 구조적으로 없앤 수정**이고, `--slot-max` 순서 교정은 정지 캡처로는 원리상 안 잡히는 결함을 코드 근거만으로 정확히 고친 것입니다. 격자 선택 로직도 요동·되먹임이 없어 견고합니다.

남은 문제는 하나이고 원인이 분명합니다 — **자리 선점이라는 결정이 `if(!mobile)` 이라는 기존 예외와 만나 폰에서만 비용이 보상 없이 남았습니다.** 그리고 그 결정의 근거였던 "잴 수 없다"는 이 파일이 이미 쓰고 있는 기법으로 반증됩니다(1440×900 에서 접힘 262 · 열림 465, 두 번 재도 같고 복원도 정확).

크기는 열린 높이로 고르고 자리는 접힌 높이에 두면, **빈 자리 · 폰 잘림 · 1600 재배치가 한 번에 사라집니다.** 그게 이 화면이 도달할 수 있는 가장 깨끗한 상태로 보입니다.
