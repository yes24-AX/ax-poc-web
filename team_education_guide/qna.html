🎨 프론트엔드(Frontend) 아키텍처 및 동작 원리

Q1 인터넷 vs 웹많은 사람들이 인터넷과 웹을 같은 뜻으로 혼용합니다. 영상에서 비유한 '도로망' 개념을 사용하여 인터넷과 웹의 명확한 차이점을 설명해 주세요. 정답 보기
인터넷은 전 세계의 컴퓨터들을 서로 연결해 주는 네트워크 인프라, 즉 물리적인 '도로망'에 해당합니다. 반면 웹(Web)은 이 도로망 위를 달리는 서비스이자 데이터(문서) 콘텐츠입니다. 즉, 인터넷이라는 거대한 인프라 시스템 속에 존재하는 하나의 서비스가 웹입니다.
네트워크 인프라도로망 비유인프라 위의 서비스
Q2 자바 vs 자바스크립트초보자들이 가장 많이 헷갈려하는 '자바(Java)'와 '자바스크립트(JavaScript)'의 관계를 설명하고, 자바스크립트가 탄생한 목적을 간략히 서술해 주세요. 정답 보기
자바와 자바스크립트는 이름만 비슷할 뿐, 설계 철학과 목적이 완전히 다른 독립적인 언어입니다. 자바스크립트는 1995년 네스케이프 브라우저 개발 팀에서 웹페이지에 동적인 기능(움직임, 상호작용)을 넣기 위해 단 10일 만에 개발한 웹 전용 언어입니다.
완전히 다른 언어1995년 네스케이프10일 만에 개발동적 기능 구현
Q3 HTML/CSS/JS 역할웹페이지가 화면에 그려질 때 HTML, CSS, 자바스크립트가 각각 어떤 역할을 담당하는지 영상 속 '가구 배치와 인테리어' 비유를 들어 설명해 주세요. 정답 보기
HTML은 웹페이지의 구조와 뼈대를 잡는 '배치도' 역할을 합니다. CSS는 그 배치도 위에 색상을 입히고 테두리를 그리며 예쁘게 꾸미는 '실제 가구 배치 및 인테리어' 단계를 담당합니다. 자바스크립트는 이렇게 완성된 공간에 생동감과 움직임(동적 제어)을 불어넣는 역할을 합니다.
HTML(뼈대/배치도)CSS(색상/가구 인테리어)JavaScript(움직임/동적 제어)
Q4 리플로우브라우저가 화면을 그리는 과정에서 발생하는 '리플로우(Reflow)'란 무엇이며, 개발할 때 왜 이를 최소화하도록 고려해야 하나요? 정답 보기
리플로우는 웹페이지 내 요소의 크기, 위치 등 구조적 배치가 변경되었을 때, 브라우저가 화면 위의 기하학적 구조를 다시 계산하여 새로 정렬하는 과정을 뜻합니다. 가구를 매번 새로 배치할 때 힘이 드는 것처럼 리플로우는 컴퓨터 자원을 많이 소모하므로, 부드러운 유저 경험과 성능 최적화를 위해 발생을 최소화해야 합니다.
레이아웃 재계산크기/위치 변경브라우저 자원 소모성능 최적화
Q5 트리쉐이킹프론트엔드 빌드 과정에서 언급된 '트리쉐이킹(Tree Shaking)'의 개념을 나무를 흔드는 비유와 연결하여 설명해 주세요. 정답 보기
트리쉐이킹은 코드를 하나로 묶는 번들링 단계에서 '한 번도 사용하지 않은 코드'를 자동으로 솎아내서 지워버리는 최적화 기술입니다. 마치 나무를 흔들어서 쓸모없이 떨어지는 열매나 낙엽을 털어내듯, 불필요한 코드를 털어내 최종 파일 용량을 줄이고 로딩 속도를 향상시킵니다.
번들링 과정사용하지 않는 코드 제거나무 흔들기 비유용량 다이어트

⚙️ 백엔드(Backend) 탄생과 구조적 진화

Q6 서버 사이드 렌더링초기의 정적 웹 방식에서 백엔드 기술이 왜 필요해졌는지, 영상에서 언급된 '방명록'이나 '검색창'의 예시를 들어 서버의 역할 변화 관점에서 설명해 주세요. 정답 보기
초기의 웹은 이미 만들어진 HTML 파일을 그대로 꺼내주는 방식이었습니다. 하지만 '방명록'처럼 누가 언제 어떤 글을 남길지 모르거나, '검색창'처럼 사용자가 무엇을 검색할지 모르는 상황에서는 파일을 미리 만들어 둘 수 없습니다. 따라서 사용자 요청에 따라 그 자리에서 데이터를 계산하고 화면을 제조해야 할 필요성이 생겼고, 이 문제를 해결하기 위해 서버가 직접 HTML을 조립해 주는 백엔드(서버 사이드 렌더링) 기술이 탄생했습니다.
정적 파일매 요청마다 계산파일 보관 → 파일 제조서버 사이드 렌더링
Q7 MVC 패턴서비스가 커지면서 도입된 MVC 패턴에서 M, V, C의 각각의 역할은 무엇이며, 이렇게 파일을 역할별로 나누었을 때의 이점은 무엇인가요? 정답 보기
M (Model): 데이터를 다루는 부분 (DB에서 데이터를 꺼내고 저장)
V (View): 화면을 그리는 부분 (사용자에게 보여줄 HTML 생성)
C (Controller): 교통정리 (요청이 오면 어떤 데이터를 꺼내 어떤 화면을 보여줄지 결정)

이점: 코드와 DB 처리, 화면을 그리는 코드가 한 파일에 뒤섞여 있으면 기능 하나를 고칠 때 관련 없는 코드까지 전부 읽어야 합니다. 역할별로 파일을 나누면 특정 기능을 고칠 때 해당 코드만 수정하면 되므로 유지보수와 관리가 용이해집니다.
Model(데이터)View(화면)Controller(교통정리)역할 분리유지보수 용이
Q8 비즈니스 로직영상에서 정의한 '비즈니스 로직(Business Logic)'이란 무엇인가요? 쇼핑몰에서 '주문 버튼'을 누르는 상황을 예로 들어 설명해 주세요. 정답 보기
비즈니스 로직은 화면을 그리거나 단순히 DB에 저장하는 것을 넘어, 해당 서비스가 작동하는 핵심 규칙이자 일련의 처리 과정을 뜻합니다. 쇼핑몰 주문의 경우 재고 확인 → 결제 처리 → 재고 감소 → 배송 정보 등록 → 주문 완료 이메일 발송으로 이어지는 일련의 핵심 서비스 규칙들이 비즈니스 로직에 해당합니다.
서비스의 핵심 규칙주문/결제/재고 처리 흐름

Q9 프론트/백 분리2007년 아이폰 등장 이후 서버의 역할이 어떻게 바뀌었는지, 이로 인해 프론트엔드와 백엔드의 역할이 어떻게 분리되었는지 설명해 주세요. 정답 보기
모바일 앱은 웹브라우저와 달리 HTML 화면을 직접 쓸 수 없고 '순수한 데이터'가 필요합니다. 이 때문에 서버의 역할이 HTML 제조기에서 '데이터 공급자'로 변화했습니다. 이때 데이터 요청 창구 역할을 하는 API와 데이터 포맷인 JSON(Key-Value 쌍)이 쓰이기 시작했습니다. 결과적으로 백엔드는 데이터 공급자, 프론트엔드는 화면 제작자로 역할이 명확히 분리되었습니다.
모바일 앱의 등장HTML → 데이터 공급APIJSON(텍스트 데이터)역할 분리
Q10 상태 관리HTTP 통신의 특징인 'Stateless(상태 없음)'의 의미와, 이를 해결하기 위한 '세션-쿠키' 방식과 'JWT' 방식의 구조적 차이를 설명해 주세요. 정답 보기
Stateless란 서버가 기억력이 없어서 방금 로그인한 사용자라도 다음 요청이 오면 누구인지 알아보지 못하는 특징을 말합니다.

세션-쿠키 방식: 로그인 정보를 서버 메모리에 저장하고 사용자에게 번호표(세션 ID)를 발급하면, 브라우저가 쿠키에 이를 저장해 두고 매번 서버에 제출하는 방식입니다. (서버 여러 대 운영 시 관리가 어려움)
JWT(JSON Web Token) 방식: 서버 메모리에 정보를 저장하는 대신, 로그인 정보를 서버가 도장(서명)을 찍어 암호화(인코딩)한 토큰 형태로 사용자에게 건네주는 방식입니다. 서버는 메모리 조회 없이 토큰의 서명만 검증하면 됩니다.
Stateless세션(서버 메모리 저장)쿠키(브라우저 저장)JWT(서명 검증)
Q11 인증과 인가'인증(Authentication)'과 '인가(Authorization)'의 개념적 차이를 예를 들어 설명해 주세요. 정답 보기
인증: 이 사람이 누구인지 '신원'을 확인하는 과정입니다. (예: 아이디/비밀번호로 로그인하기)
인가: 인증된 사용자가 특정 자원에 접근하거나 권한을 행할 수 있는지 '자격'을 확인하는 과정입니다. (예: 일반 사용자가 관리자 페이지에 접근하려고 할 때 권한이 없음을 확인하고 막는 것)
인증 = 누구인가인가 = 권한이 있는가

⚡ 대규모 트래픽과 가용성 확보

Q12 캐싱 시스템DB 조회를 줄이기 위한 '캐시(Redis)'와 'TTL'의 역할을 영상 속 '마트 바구니' 예시를 활용해 설명해 주세요. 정답 보기
DB는 디스크에서 데이터를 읽어오기 때문에 속도가 느립니다. 캐시(Redis)는 자주 찾는 데이터를 속도가 빠른 메모리에 미리 올려두고 DB까지 가기 전에 바로 꺼내주는 기술입니다. 마트 창고(DB)까지 매번 가지 않고, 계산대 옆 바구니(Redis)에 잘 팔리는 물건을 두고 바로 주는 것과 같습니다. TTL(Time To Live)은 캐시 데이터의 유효 시간으로, 데이터가 바뀔 수 있으므로 일정 시간이 지나면 캐시를 지우고 새로 갱신하기 위해 설정합니다.
메모리 기반 저장디스크 조회 최소화계산대 옆 바구니TTL(유효 시간)
Q13 스케일 아웃'수직 확장'과 '수평 확장'의 차이를 설명하고, 대형 서비스에서 수평 확장을 선호하는 이유와 '로드 밸런서'의 역할을 서술해 주세요. 정답 보기
수직 확장(Scale-up): 서버 컴퓨터 한 대의 성능을 더 좋은 것으로 업그레이드하는 것 (물리적 한계와 고비용 문제)
수평 확장(Scale-out): 같은 사양의 서버를 여러 대 늘려서 일을 나누는 것 (현대 대형 서비스 표준)
로드 밸런서: 서버가 여러 대(분산 시스템)가 되면 사용자의 요청을 어디로 보낼지 결정해야 하는데, 들어오는 트래픽을 여러 대의 서버에 골고루 분배해 주는 역할을 합니다.
성능 업그레이드서버 대수 늘리기로드 밸런서(트래픽 분배)분산 시스템
Q14 메시지 큐'치킨 주문 폭주' 상황을 예로 들어 '메시지 큐(Message Queue)'의 필요성을 설명해 주세요. 정답 보기
대형 경기 날 치킨 주문이 폭증하여 사장님 앱에 알림을 보내는 시스템이 순간적으로 20초간 마비(서버 다운)되었다고 가정할 때, 메시지 큐가 없다면 주문 데이터가 전달되지 못하고 유실되어 '환불 대란'이 일어납니다. 반면 메시지 큐가 있으면 주문 서비스가 알림 서비스에 직접 요청하는 대신 큐(메모장)에 주문 내용을 적어두고 자기 할 일을 끝냅니다. 알림 서비스는 복구된 후 큐에 쌓인 메모를 순서대로 꺼내 처리하므로 주문 데이터가 단 하나도 사라지지 않고 안정적으로 처리됩니다.
비동기 처리버퍼/메모장 역할데이터 유실 방지시스템 간 결합도 완화

🛡️ 데이터 무결성과 운영 안정성

Q15 트랜잭션계좌 이체 상황을 예로 들어 '트랜잭션'의 개념과 '커밋', '롤백'의 작동 방식을 설명하고, ACID 원칙을 요약해 주세요. 정답 보기
트랜잭션은 여러 작업이 '전부 성공하거나 전부 실패'해야 한다는 규칙입니다. 계좌 이체 시 A 계좌 출금은 성공했으나 오류로 B 계좌 입금이 실패하면 돈이 사라집니다. 이를 막기 위해 임시 메모장에서 작업을 수행합니다.

커밋(Commit): 모든 작업이 성공했을 때 실제 DB에 최종 확정하는 선언
롤백(Rollback): 도중에 오류가 나면 임시 메모장을 찢어버리고 트랜잭션 시작 전 상태로 되돌리는 것

ACID 원칙:
  • 원자성(Atomicity): 전부 실행되거나 전혀 실행되지 않음 (중간 상태 없음)
  • 일관성(Consistency): 데이터는 항상 정해진 규칙과 제약 조건을 만족함
  • 격리성(Isolation): 동시에 실행되는 여러 작업이 서로 간섭하지 못함
  • 지속성(Durability): 성공 완료된 작업은 서버가 꺼져도 DB에 영구히 남음

Q16 CI/CD 및 도커환경 문제를 해결하는 '도커(Docker)'와 배포를 자동화하는 'CI/CD'의 필요성을 설명해 주세요. 정답 보기
도커(Docker): "내 컴퓨터에선 되는데 서버에선 안 된다"는 환경 차이 문제를 해결하기 위해 코드와 실행 환경을 통째로 묶어 포장하는 기술입니다. 어떤 환경에서든 똑같이 동작하도록 보장합니다.
CI/CD: 개발자가 수작업으로 코드를 올리고 서버를 재시작하던 과거 방식과 달리, 코드를 올리면 자동으로 테스트를 거쳐 실제 서버에 업데이트(배포)까지 완료해 주는 자동화 시스템입니다. 서비스가 수십 개로 나뉜 현대 아키텍처에서 관리를 위해 필수적입니다.
환경 포장 기술어디서나 동일 작동배포 자동화테스트 및 업데이트 자동화
