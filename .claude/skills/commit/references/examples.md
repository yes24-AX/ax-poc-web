# 예시

## 좋은 예

### 제목만으로 충분한 변경

```
fix(crawler): 페이지네이션 마지막 장에서 무한 루프 제거
```

```
refactor(mail): 템플릿 렌더링을 별도 서비스로 분리
```

```
feat(db): 회원 등급 이력 테이블 추가

Refs: AX-1508
```

### 변경 단위 1개 — 번호 없이 목록

```
feat(auth): 로그인 세션 만료 시 자동 재발급 추가

- 기존: 세션 만료 시 재로그인 필요
- 변경: 리프레시 토큰 유효 시 자동 재발급

Refs: AX-1421
```

```
build: spring-boot 3.2.4로 올림

- 사유: 3.2.1 커넥션 풀 누수 이슈
```

### 변경 단위 여러 개 — 번호 계층

제목에 나열한 순서와 번호 항목 순서가 같다.

```
style(deploy): ACTIVE 슬롯 강조·마이그레이션 0개 숨김

1. ACTIVE 슬롯 강조
   - 배지: 기본색 채움 + 깜빡이는 점
   - 카드: 틴트 강화 + 테두리 색
   - 사유: 옅은 틴트로는 Standby 와 구분 어려움
2. 마이그레이션 0개 숨김
   - 변경 열: 있을 때만 표시
   - 사유: 마이그레이션이 있는 배포가 눈에 띄도록
```

제목이 한 주제일 때는 그 주제의 측면으로 번호를 나눈다.

```
feat(deploy): 커밋 목록을 GitHub API 로 직접 조회

1. 조회 경로 전환
   - 기존: 에이전트가 갱신한 refs.json 에서만 읽음
   - 사유: 에이전트 주기 탓에 갱신 약 2분 간격
   - 변경: 웹이 GitHub REST API 로 main first-parent 커밋 직접 조회
   - 대체: 토큰 없음·API 실패 시 refs.json
2. 조회 규칙
   - 머지 포함·요약 규칙: 에이전트와 동일
   - 커밋 시각: KST 변환
   - 목록 캐시: 30초
   - 동기화 버튼: 캐시 무시 후 즉시 조회
   - 토큰: 환경변수 Github__commitApi
3. 화면
   - 목록 원천 배지: GitHub API·에이전트 구분
   - 대체 사유: 툴팁 표시
4. 문서
   - 배포 구조 그림: 커밋 목록 API 경로 추가
   - 배포 매뉴얼: API 토큰 절 추가
```

여러 항목에 공통인 사실은 번호 목록 뒤에 번호 없이 둔다.

```
fix(deploy): GitHub API 토큰 줄바꿈 제거·배포 대상 값 누락 수정

1. GitHub API 토큰 줄바꿈 제거
   - 증상: 토큰 등록 후에도 커밋 목록이 에이전트 목록으로 대체
   - 원인: 환경변수 토큰 끝에 CRLF 포함
   - 변경: 설정 읽기와 헤더 생성 직전에 앞뒤 공백·줄바꿈 제거
2. 배포 대상 값 누락 수정
   - 증상: 모든 배포 요청이 등록 오류로 실패
   - 원인: 이력 저장 SQL 의 @Target 값 미전달
   - 변경: 이력 저장 매개변수에 Target 추가

- 확인: 배포 관리 SQL 5종 매개변수 대조 결과 누락 없음
```

## 나쁜 예와 이유

| 나쁜 메시지 | 문제 |
|---|---|
| `수정` | type 없음, 무엇을 고쳤는지 알 수 없음 |
| `fix: 버그 수정함` | 내용이 비어 있고 "~함" 종결 사용 |
| `feat(auth): Add auto refresh for expired session.` | 영어 번역투에 마침표까지 |
| `chore: 로그인 기능 추가` | 기능 추가인데 type이 chore |
| `feat: 로그인 추가, 크롤러 버그 수정, README 갱신` | 관심사 3개가 한 커밋에 섞임 |
| `fix(auth): 세션 관련 코드 정리 및 리팩터링과 함께 만료 처리 로직 보완 작업 진행` | 제목이 너무 길고 type이 실제 변경과 불일치 |

## 본문 구조 — 나쁜 예와 고친 예

| 나쁜 본문 | 문제 | 고친 본문 |
|---|---|---|
| 변경 2개를 `기존:` `변경:` `사유:` 평평한 줄로 나열 | 사유가 어느 변경의 것인지 불명 | `1. <변경 A>` / `2. <변경 B>` 아래에 각각 들여쓴 `- 사유:` |
| `1. 배지 기본색 채움, 카드 테두리 색 적용` | 번호 줄에 사실 두 개 | `1. ACTIVE 슬롯 강조`<br>`   - 배지: 기본색 채움`<br>`   - 카드: 테두리 색` |
| `1. 변경: 자동 재발급 추가` | 번호 줄에 라벨 | `1. 자동 재발급 추가` |
| 변경 단위가 1개인데 `1.` 하나만 있음 | 번호가 불필요 | 번호 없이 `- 기존:` `- 변경:` 목록 |
| 제목은 `A·B` 인데 본문 번호가 B, A 순 | 제목과 본문 순서 불일치 | 번호 항목을 제목 순서대로 |
| 하위 줄 아래 한 번 더 들여쓴 줄 | 깊이 3단계 | 번호 항목을 나누거나 하위 줄을 합침 |
| 72자 넘는 하위 줄을 다음 줄에 이어 씀 | 들여쓰기 계층이 흐려짐 | 줄이거나 두 사실로 나눔 |

## 본문 문체 — 나쁜 예와 고친 예

| 나쁜 줄 | 문제 | 고친 줄 |
|---|---|---|
| `- 기존 팝업은 한 사람만 보여서 비교가 안 됐다` | 설명문·종결어미 | `- 기존: 사람끼리 비교 불가` |
| `- 그래서 헤더를 두 곳에서 공유하도록 바꿨다` | 접속사로 이음 | `- 변경: 헤더 델리게이트 공유` |
| `- 서버는 바꾸지 않았고 화면에서 집계한다` | 한 줄에 두 사실 | `- 서버 변경: 없음`<br>`- 집계: 화면에서 수행` |
| `- 진행률을 합치면 없는 숫자를 지어내게 되기 때문이다` | 종결어미로 맺음 | `- 통합 진행률: 미도입 (원천에 값 없음)` |
