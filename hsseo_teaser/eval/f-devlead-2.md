## 1. 홈 질문창이 마우스로 전혀 조작되지 않는다 — 배포 차단

**`h1/index.html:359-363`** (`body.js .stage{ … pointer-events:none}`) · **`h1/index.html:392-395, 403`** (`body.js #nodes{position:absolute; inset:0; z-index:7}` / `#nodes.live{pointer-events:auto}`)

실측 (1440×900, `#step=6`):
```

#ask     pointer-events: none
#askin / #asksend  pointer-events: none
elementFromPoint(묻기 버튼 중앙)  →  #nodes     ← 전면 레이어가 가로챔
elementFromPoint(입력창 중앙)     →  #nodes

원인이 둘 겹쳐 있어 한쪽만 고치면 안 됩니다.
- `body.js .stage` 가 `pointer-events:none` 인데 `#ask` 에 되돌리는 규칙이 없습니다.
- `body.js #nodes` 가 `inset:0 · z-index:7` 전면 레이어이고 `.live` 에서 `pointer-events:auto` 가 되므로 **카드 바깥 빈 영역까지 전부 삼킵니다.** 질문창은 그 아래에 깔립니다.

```css
/* #nodes 는 전면 레이어다 — 카드 밖의 클릭까지 먹으면 그 아래 질문창이 죽는다 */
body.js #nodes.live{pointer-events:none}
body.js #nodes.live .node{pointer-events:auto}
/* 질문창은 최종 화면의 실제 입력 UI다 — 무대가 꺼도 여기만 되돌린다 */
body.js #ask{pointer-events:auto}
```

부수 효과: 커서 IIFE 의 `$('#ask').addEventListener('mouseenter', …)`(`h1:2240-2241`)도 지금은 영영 발화하지 않습니다 — 질문창 위에서 커스텀 커서가 시스템 캐럿에 자리를 내주는 처리가 죽어 있고, 이 수정으로 함께 살아납니다.

**기능 자체는 다 만들어져 있습니다.** 키보드로 제출하면(Tab→입력→Enter) echo·"이 시연은 위 샘플 질문 하나만 답합니다"·판단 줄까지 의도대로 전부 열립니다. 포인터만 막혀 있습니다.

## ② 폰트 CDN — **무응답에서 first paint 184 ms. 이전 판은 45초 넘게 백지**

측정하지 못하셨다는 부분입니다. 요청을 **가로채고 영영 응답하지 않는(블랙홀)** 조건을 만들고, 대조군으로 `media="print"` 만 걷어낸(= 이전 판의 차단 stylesheet) 사본을 같이 돌렸습니다.

| 조건 | 현재 판 (`media="print"`) | 대조군 (차단 stylesheet) |
|---|---|---|
| **무응답 (블랙홀)** | **first paint 184 ms** · FCP 184 ms · 스크립트 기동 · `#step=0` 재생 중 | **45초 내 first paint 없음.** `document.documentElement` 조회조차 불가 — 파싱 자체가 진행되지 않음 |
| 연결 거부 (즉시 실패) | first paint 228 ms | first paint 176 ms |

두 가지가 드러납니다.

1. **효과는 확실합니다.** 무응답 CDN에서 무한 백지 → **184 ms**. 21초라는 기존 수치는 오히려 낙관적이었습니다 — 진짜 블랙홀에서는 45초에도 아무것도 그려지지 않고, 상한은 크롬 네트워크 타임아웃(수 분)입니다. 가림막 타이머를 포함한 인라인 스크립트까지 전부 파서에 묶여 자구책이 돌지 못하기 때문입니다.
2. **연결 거부 조건에서는 둘이 구분되지 않습니다**(176 vs 228 ms). 기존 검증이 `MAP … 0.0.0.0`(즉시 실패)을 썼기 때문에 이 결함을 못 잡았던 것입니다. 앞으로 CDN 장애 검증은 **연결 거부가 아니라 무응답**으로 해야 합니다.

잔여 리스크 하나: `onload="this.media='all'"` 는 인라인 이벤트 핸들러라 CSP 에 `unsafe-inline`(또는 해당 해시)이 없으면 실행되지 않습니다. 그 경우 폰트가 영영 적용되지 않고 `-apple-system / Malgun Gothic` 로 남습니다 — **렌더는 멈추지 않으므로 저하일 뿐 고장은 아닙니다.** 사내 포털이 CSP 를 거는 곳이면 알고 넣으시면 됩니다.

다만 **높이가 짧아지면 두 가지가 남습니다.**

**(가) 641~900 폭 × 667 높이에서 첫 카드가 도구 줄을 덮습니다.**
`bandTop = H*.26` 은 H=667 에서 173px 인데, 헤드라인 덩어리는 `padding-top:7vh`(47) + eyebrow + `.slot`(9vw = 81px 활자, 높이 94) + `.slot2` 로 **219px** 까지 내려옵니다. 900×667 실측: 첫 카드 top 167, 「배포 이력 · Elasticsearch · DB 로그에서」중 앞부분이 카드 뒤로 들어가 `· DB 로그에서` 만 읽힙니다. 900·820·768·700 × 667 에서 동일. `bandTop` 을 헤드라인 덩어리의 실측 bottom 으로 잡으면 닫힙니다.

**(나) `--gh` 하한 80px 에서 카드 내용이 잘립니다.**
375×667 · 641~900×667 에서 `--gh:80px` 하한에 걸리는데, 이 높이에서는 프로그램 줄이 다 앉지 못합니다. 실측(900×667): 「운영 시스템」이 영업관리·WMS 만 보이고 **MIS 가 잘림**, 「시스템 모니터링」이 배포 이력·Elasticsearch 만 보이고 **DB 로그가 잘림**. 화면이 "10개 프로그램"을 말하는데 세어 보면 8개입니다. 하한에서는 `.gcard__sys` 를 두 줄로 접거나 `--gh` 하한을 92px 근처로 올리는 편이 안전합니다.

참고: 자동 판정에서 나온 `카드간세로여백 = -10 ~ -13px` 는 **회전 사각형의 축정렬 bounding box 때문에 생긴 허위 양성**입니다. 스크린샷으로 확인한 실제 카드 사각형은 서로 겹치지 않습니다.

# 그 밖에 확인한 것

**입구 6개** — 6개 모두 `href` 경로와 카드에 표기된 `/경로` 문자열이 일치하고, `권한 필요` 표기가 카드 본문과 `aria-label` 양쪽에 일관됩니다(`/MdBriefing`·`/ArRisk` 만 표기). 마크업 정합성은 통과입니다. 운영 HTTP 응답은 사내망 밖이라 확인할 수 없어 팀장님 확인을 그대로 인용합니다.

**입구 링크 클릭** — 연출 경로에서 실제 마우스 클릭이 `https://ax-datahub.yes24.com/MdBriefing` 로 정상 도달합니다(위 1번을 고쳐도 유지되도록 `.node` 에 `pointer-events:auto` 를 주는 것).

**마그네틱 커서** — 살아 있습니다. 마우스 4점 이동에 `#cursor` 의 x/y 가 정확히 추종, `opacity:1`, `cursor-on` 부착, 카드 호버 시 14→58px 확대 + "열기" 라벨 표시. 27점 판의 최대 결함은 닫혔습니다.

**WCAG 2.1.1** — `#skip` 포커스 + Space → `#step=6` 이동, `#asksend` 포커스 + Space → 제출. 배너 버튼은 Enter·Space 둘 다 재생 복귀. 닫혔습니다.

**`visibilitychange`** — hidden 6초 동안 `#step=0` 정지, 복귀 후 `#step=1` 진행. 정상.

**타임라인** — 마지막 착지 `3.62+4×0.17+0.92 = 5.22`, 행 채움 `5.48` → 0.26초 여유. `settle 6.85` 는 캡션 완료(6.78) 직후·퇴장(7.10) 직전. 장 끝 7.9에서 잘리는 요소 없음. 전부 실측 일치.

**`th[style*="--g-mkt"]{--c:#8A6A1E !important}`** — computed `--c: #8A6A1E`, 글자색·밑줄색 `rgb(138,106,30)`. GSAP 은 `--keyed` 만 트윈하므로 충돌 없습니다.

**JS 완전 차단** — 1440·500 두 폭에서 입구 6개가 실제 폭(236/150px)으로 서고, 표 6행, 밑줄 5/5, 답 카드 노출. 단 스파크라인은 JS 생성이라 6칸 모두 빈 띠로 남습니다(`spark:0`).

# 배포 전 권장 (차단 아님)

**4. 폴백 경로에서 질문창이 먹통** — `h1:1279`(이른 `return`)이 질문창 IIFE(`h1:2173-2191`)보다 위에 있어, 축소모션·GSAP 부재 경로에서 `묻기`·Enter 가 아무 동작도 하지 않습니다. 이 경로에서는 `#askreply` 가 처음부터 펼쳐져 있으므로, 관객이 다른 질문을 치고 눌러도 「기획전 종료 −7% · 베스트 3종 품절 −4%」가 그대로 앉아 **묻지 않은 질문에 답한 것처럼 보입니다.** `h1:955-958` 주석이 "관객이 직접 만지는 그 지점에서 시치미를 떼면 안 된다"고 적어 둔 상황이 폴백 경로에서만 발생합니다. IIFE 를 `return` 위로 올리고 `layout(true)`·`gsap.*` 호출부만 가드하면 두 경로가 같은 정직함을 갖습니다.

**5. 답이 열리면 입구 아랫줄이 하단 문구를 덮음** — `h1:1514` 의 하한 `Math.max(12, …)` 때문에 1440×900 에서 아랫줄 카드 하단 876px vs `#foot` 상단 861px. 기능 문제는 아니고(`#foot` 은 `pointer-events:none`) 시각 충돌입니다.

**6. JS 차단 시 스파크라인 빈칸** — 정적 우선을 표방하는 문서이므로 여섯 개 `<polyline>` 을 마크업에 박아 두는 편이 일관됩니다.
