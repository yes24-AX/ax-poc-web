# 실제 결함 — `.70` 하한이 두 축의 맞춤을 모두 덮어씁니다

**`h1/index.html:1677`** (`const s = Math.max(.70, best.s);`) · **`h1:1663`**(`avail`) · **`h1:1686-1689`**(clamp)

`best.s = Math.min(1, sW, sH)` 는 **가로(`sW`)와 세로(`sH`) 양쪽에 들어가는 배율**입니다. 여기에 `Math.max(.70, …)` 를 걸면 그 맞춤이 **두 축 모두에서 무효**가 되고, 그 뒤에 되돌려 잡아 주는 clamp 가 없습니다. `compTop` 은 `Math.max(12, …)` 로 위쪽만 막을 뿐 아래쪽·좌우는 아무도 안 봅니다.

**5차에서 하한을 `.58 → .70` 으로 올리자고 한 건 제 권고였고, 이름 잘림만 보고 넘침 쪽을 못 본 판단이었습니다.** 정정합니다.

## 처방 — 하한이 "화면 안"에 양보해야 합니다

원칙은 하나로 정리됩니다. **읽히지 않는 것보다 닿지 않는 것이 나쁩니다.** 이름이 말줄임되어도 카드는 여전히 눌리고 `/MdBriefing` 경로도 보입니다. 화면 밖 카드는 아무것도 아닙니다.

```js
/* 배치 후보 중 .70 이상으로 들어가는 게 있으면 그걸 쓴다(이름을 지킨다).
   하나도 없으면 하한을 포기하고 실제로 들어가는 배율을 쓴다 —
   이름이 잘리는 건 회복 가능하지만 화면 밖으로 나간 카드는 회복이 안 된다 */
const fits = cand.map(...).filter(x => x.s >= .70);
const best = (fits.length ? fits : all).sort((a,b)=> b.s - a.s)[0];
const s    = best.s;                       // Math.max(.70, …) 제거
```
그리고 마지막 안전망 두 줄을 둡니다 — `gw` 가 `W` 를 넘거나 `gyTop + gh` 가 `H − footH` 를 넘으면 그만큼 `s` 를 다시 줄이는 것입니다. 지금은 이 보정이 아예 없습니다.

## 결론 — 겹침은 코드 결함이 아니라 **측정 시점 문제**입니다

`layout()` 의 `L.grid[0].y` 와 노드의 실제 `gsap.getProperty(node,'y')` 를 시간축으로 같이 찍었습니다.

**커밋 `3a1244f` · 1366×797 (실효 H=797 — 보고하신 조건과 동일)**
```
묻기 전                 grid.top = 490   (y = 151)
[layout]  submit() 에서 1회      grid[0].y = 253   asked=true
[moveNodes] target=253  cur=151  dur=0.6
  +2251ms  y=191  top=530   tw=1     ← 트윈 진행 중
  +2437ms  y=244  top=583   tw=1
  +2895ms  y=253  top=592   tw=0     ← 도착
  +3604ms  y=253  top=592   tw=0
최종  grid.top = 592   reply.bottom = 548   겹침 = -44 (여백)
```

**노드는 목표값에 정확히 도착합니다.** `y` 가 151 → 253 으로 이동하고 트윈 수가 1 → 0 으로 끝납니다. 1366×900 · 1600×797 · 완주 진입까지 전부 같습니다.

보고하신 값과 맞춰 보면 원인이 드러납니다.

| 보고하신 값 | 제 측정 |
|---|---|
| 계산 `gyTop = 594` | 계산 253(중심 기준) = **화면 좌표 592** — 일치 |
| 「실제 grid.top = 492」 | **묻기 전** grid.top = **490** — 일치 |
| `reply.bottom = 558` | 548 — 일치(±10) |

즉 「실제」로 잡으신 492 는 **묻기 전 자리**입니다. `moveNodes` 는 0.6초짜리 트윈이라 클릭 직후에 읽으면 출발점이 그대로 나옵니다. 보고서의 "560 은 18px 움직입니다"가 결정적인 단서였습니다 — 트윈이 조금 진행된 시점에 읽힌 값입니다. 세 해상도의 겹침 45 / 66 / 53 은 전부 `reply.bottom(제출 후) − grid.top(제출 전)` 으로 정확히 떨어집니다.

**계측 시 `gsap.getTweensOf(node).length === 0` 을 기다리거나 최소 700ms 뒤에 읽으시면 됩니다.** 제 하네스는 그 조건을 걸고 읽습니다.

- `moveNodes` 시점의 `L.grid[i].y` 와 트윈 종료 후 `gsap.getProperty(n,'y')` — **정확히 일치**(253/253)

## 워킹트리에 남는 것 두 가지

**(가) 안전망이 넘침을 작은 겹침으로 바꿉니다.** 새로 넣으신 `gyTop = Math.min(compTop + basis + vgap, H - footH - gh)` 는 자리가 모자라면 격자를 **위로 끌어올려** 화면 안에 넣는데, 그만큼 답 카드를 파고듭니다 — 1280×617 타이핑 4px · 560×564 타이핑 5px · 360×540 22px. 우선순위는 옳습니다(닿지 않는 것보다 겹치는 게 낫습니다). 완전히 없애려면 **끌어올리는 대신 그만큼 더 줄이면** 됩니다.
```js
const over = (compTop + basis + vgap + gh) - (H - footH);
if(over > 0){ const k = Math.max(.4, (gh - over) / gh); nwU = Math.round(nwU*k); nhU = Math.round(nhU*k); /* gh 재계산 */ }
```

**(나) 아주 작은 화면에서 이름이 전부 잘립니다.** 하한을 없앤 대가로 360×540·375×564·560×564 에서 카드 폭이 75px 까지 내려가 **여섯 장 모두 이름이 말줄임**됩니다. 제가 권한 맞바꿈의 결과이고 방향은 맞지만(닿는 게 우선), 그 폭에서는 입구로서 값이 거의 없습니다. **`#foot` 은 안내 문구일 뿐 길이 아니므로, 세로가 아주 짧을 때(예 `H < 600`) `footH` 를 0 으로 두고 그 56px 을 카드에 돌려주는 것**이 가장 싼 개선입니다.
