# 세로 흐름 — 짧은 높이에서 두 가지

먼저 정정합니다. 2차에서 보고한 "카드끼리 세로 여백 −10 ~ −13px"는 **회전 사각형의 축정렬 bounding box 때문에 생긴 허위 양성이었습니다.** 이번에 `getBoxQuads` 로 실제 회전 사각형 교차를 재려 했으나 Chrome 이 quad 를 반환하지 않아 같은 bbox 로 되돌아갔고, 스크린샷으로 직접 확인한 결과 **카드끼리는 어느 조합에서도 겹치지 않습니다.** 62개 조합 전부 정상입니다.

실제로 남은 건 둘입니다.

**(가) 641~1024 폭 × 667·740 높이에서 첫 카드가 도구 줄을 덮습니다.**
`bandTop = H*.26`(`h1:1508`)은 H=667 에서 173px 인데, 세로 흐름의 헤드라인 덩어리는 `padding-top:7vh` + `.slot`(활자 `9vw`, `--slot-max` 가 걸리지 않아 **최대 92px**)로 **219px** 까지 내려옵니다. 900×667 스크린샷에서 「배포 이력 · Elasticsearch」가 카드 뒤로 들어가 `· DB 로그에서` 만 읽힙니다. 900 높이에서도 폭 960~1024 는 활자가 86~92px 이라 같은 증상이 납니다.
→ `bandTop` 을 상수 비율이 아니라 **헤드라인 덩어리의 실측 bottom** 으로 잡으면 폭·높이와 무관하게 닫힙니다.

**(나) `--gh` 하한 80px 에서 카드 내용이 잘려 프로그램이 사라집니다.**
`ch = Math.max(80, …)`(`h1:1514`). 실측(900×667 · 768×667 · 1024×667):
```

시스템 모니터링   29px 자리에 39px 필요  →  DB 로그가 카드 밖으로 밀려남
전사 데이터 분석 / 마케팅  29px 자리에 32px 필요  →  하위 갈래 줄 잘림
```
5장 중 4장이 넘칩니다. 화면은 프로그램을 다 보여준다고 말하는데 세면 8개입니다.
흥미로운 건 **375×667 에서는 잘리지 않는다**는 점입니다 — `@media (max-width:640px)` 블록(`h1:748-`)이 `.gcard__sys` 활자를 9px 로 내려 주기 때문입니다. 1032 블록(`h1:722-`)은 안쪽 여백만 줄이고 활자는 그대로 둬서, **641~1024 짧은 높이만 사각지대**가 됐습니다. 1032 블록에 640 블록과 같은 활자 축소를 넣거나, 하한을 92px 근처로 올리면 됩니다.

# 정리

이번 라운드는 **지적한 것을 정확히, 최소 변경으로 고쳤습니다.** 특히 질문창은 두 원인을 다 막고 부작용(빈 곳 클릭이 링크를 먹는 것)까지 없앴고, `--keyed` 는 한 줄로 전 구간이 닫혔습니다. 수치 정합은 열 곳 넘는 중복에도 불구하고 **한 군데도 어긋나지 않았습니다** — 논지를 갈아엎는 변경에서 이 정도면 잘 관리된 것입니다.

남은 것은 전부 **"특정 크기에서만 나오는 잘림"** 한 종류이고, 그중 1366×768 답 열림 건만 배포를 막습니다. 그것을 닫으면 O 입니다.

한 가지 구조적 제안은 반복해 둡니다 — 지금 이 문서는 **경계값이 다섯(`L.mobile` 640 · `flowDown` 1024 · CSS 1032 · 640 · 430)** 이고, 이번 라운드의 결함 둘(1025~1032 밴드, 641~1024 짧은 높이 사각지대)이 정확히 그 경계 사이에서 나왔습니다. JS 가 `matchMedia` 로 CSS 와 같은 판정을 읽게 하고, 경계를 둘(모바일 · 세로흐름)로 줄이면 이 계열의 결함이 구조적으로 사라집니다.
