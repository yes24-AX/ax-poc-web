## 1. 배경

eBook 단독 선출간은 종이책이 시장에서 반응을 보이기 시작한 시점에 **먼저 발견하고 먼저 섭외**하는 것이 성패를 가릅니다. 그러나 현재는 후보를 찾는 일 자체가 MD의 수작업입니다.

**As-Is**

- MD가 종이책 신간 목록, 발주현황조회, 판매량 순위, 작가 이력을 **각각 다른 화면에서** 확인하며 후보를 추립니다.
- 탐색에 시간이 들고, 판매가 급상승한 상품을 놓치는 누락이 발생합니다.
- 후보 선정 기준이 MD 개인의 경험에 의존해 **표준화되어 있지 않습니다.**
- 어떤 기준으로 고른 상품이 실제 성과로 이어졌는지 **되짚어볼 데이터가 없습니다.**

**핵심 문제**

> 섭외 가치가 높은 상품을 찾는 데 시간을 쓰느라, 정작 상품성 판단과 출판사 협상에 쓸 시간이 부족하다.

---

## 2. 목표

### 2.1 제품 목표

사내 종이책 데이터로 **선출간 섭외 가능성이 높은 상품을 매일 자동 선별**하고, MD는 판단과 섭외에 집중하게 합니다.

AI·자동화가 MD의 의사결정을 대신하지 않습니다. **후보를 좁혀주는 것까지**가 시스템의 역할이고, 상품성 판단과 협상은 MD의 몫입니다.

### 2.2 성공 지표

| 구분 | 지표 | 목표 | 측정 방법 |
|---|---|---|---|
| 효율 | 후보 탐색 소요 시간 | 도입 전 대비 **70% 감소** | 도입 전후 MD 인터뷰 |
| 처리 | MD 검토 완료율 | **90% 이상** | 검토 완료 / 추천 |
| 처리 | 추천 → 검토 소요일 | 평균 **3영업일 이내** | 검토일 − 추천일 |
| 성과 | 섭외 전환율 | **30% 이상** | 섭외 / 검토 완료 |
| 성과 | 선출간 성사율 | **45% 이상** | 성사 / 섭외 |
| 품질 | 조건별 적중률 편차 파악 | 운영 3개월 내 **기준 1회 이상 조정** | 조건별 성과 리포트 |

> 도입 초기에는 절대값보다 **조건별 적중률의 상대 비교**가 중요합니다. 어떤 조건이 실제로 유효했는지 알아야 기준을 고도화할 수 있습니다.

### 2.3 비목표 (Non-goals)

- 시스템이 섭외 여부를 자동 결정하지 않습니다.
- 출판사 컨택·계약 관리는 범위 밖입니다(별도 프로세스).
- 종이책 자체의 매입·판매 의사결정은 다루지 않습니다.

## 3. 대상 사용자

| 사용자 | 역할 | 이 제품에서 하는 일 |
|---|---|---|
| **eBook MD** (주 사용자) | 분야별 선출간 담당 | 매일 추천 목록 확인 → 섭외/보류/제외 판단 → 출판사 섭외 |
| eBook 팀장 | 팀 운영 | 검토 현황 점검, 추천 조건·담당 매핑 조정, 성과 리포트 확인 |
| 운영자 | 시스템 관리 | 관리분류-담당 MD 매핑 관리, 배치 모니터링 |

**주 사용자 시나리오 (일일 루틴)**

```
09:00  출근
10:00  [eBook 선출간] 후보 메일 수신 — 우선순위 순으로 정렬된 오늘의 후보
10:05  메일의 링크로 검토 화면 진입
10:05~10:20  위에서부터 순서대로
         · 표지·도서명·추천 사유를 보고 즉시 판단되는 건 → 섭외/보류/제외 클릭
         · 애매한 건 → [상품 상세]로 세부 지표 확인 후 판단
         · 보류·제외는 사유 선택 (필수)
10:20~ 섭외 결정 건에 대해 출판사 컨택 시작
```

**설계 원칙** — 이 화면의 목적은 *빠른 판단*입니다. 판단에 필요한 최소 정보만 노출하고, 세부 지표는 상품 상세로 넘깁니다.

## 4. 범위

### 4.1 In Scope

| # | 산출물 | 설명 |
|---|---|---|
| 1 | 일일 추천 배치 | 영업일 매일 후보 추출·중복 제거·우선순위 산정·지표 스냅샷 적재 |
| 2 | 일일 추천 메일 | 영업일 오전 10시, eBook팀 발송 |
| 3 | MD 검토 화면 | 섭외/보류/제외 입력, 사유 관리 |
| 4 | 추천·검토 이력 | 추천 시점 지표 + MD 판단 누적, 엑셀 다운로드 |
| 5 | 추천 성과 리포트 | 퍼널·판단 분포·**조건별 적중률** |
| 6 | 담당 MD 매핑 관리 | 관리분류별 담당자 운영자 편집 |

### 4.2 Out of Scope (차기)

- eBook 실제 매출 연동을 통한 ROI 분석 (1차는 성사 여부까지)
- 출판사 컨택 이력·계약 진행 관리
- 판권 정보 연동을 통한 사전 필터링
- 외국도서 등 국내도서(001) 외 상위분류 확장

## 5. 기능 요구사항

우선순위: **M**(Must, 1차 필수) / **S**(Should, 1차 포함 권장) / **C**(Could, 차기)

### 5.1 후보 추출

| ID | 요구사항 | 우선 | 수용 기준 |
|---|---|---|---|
| FR-01 | eBook 미등록 종이책만 대상으로 한다 | M | eBook 상품이 존재하는 종이책은 후보에서 제외된다 |
| FR-02 | 6개 조건 중 하나라도 충족하면 후보로 추출한다 | M | 조건별 추출 건수가 배치 로그에 기록된다 |
| FR-03 | 조건 임계값은 배포 없이 조정 가능해야 한다 | M | 조건 마스터 값 변경 시 다음 배치부터 반영된다 |
| FR-04 | 여러 조건을 충족하면 사유를 **모두** 기록·표시한다 | M | 카드·메일·이력에 사유가 중복 표시된다 |
| FR-05 | 추천 시점의 발주량·판매량·순위를 함께 저장한다 | M | 이력 화면에서 추천 당시 지표를 조회할 수 있다 |

**추출 조건 6종**

| 코드 | 조건 | 기준(초기값) | 데이터 출처 |
|---|---|---|---|
| ① | 초도 발주량 상위 | 800부 이상 (취소 수량 차감 안 함) | 영업프로그램 > 발주/반출 > 발주현황조회 |
| ② | 당일 발주량 급증 | 100부 이상 | 동일 |
| ③ | 최근 7일 판매량 상위 | 국내도서 TOP 50 | 판매 집계 |
| ④ | 예약판매 | 전체 (재고부족 전환분 포함) | 상품 마스터 판매상태 |
| ⑤ | 주목할 신상품 상위 | 판매량순 TOP 120 | 닷컴 주목할 신상품 |
| ⑥ | 베스트셀러·셀럽 작가 | 저자 전작 최고 3만부 이상 또는 셀럽 목록 등재 | 저자 판매 이력 + 셀럽 관리 목록 |

### 5.2 중복 방지

| ID | 요구사항 | 우선 | 수용 기준 |
|---|---|---|---|
| FR-06 | 동일 상품번호는 **평생 1회만** 추천한다 | M | 다른 조건을 새로 충족해도 재추천·재발송되지 않는다 |
| FR-07 | 제외 판단 건은 영구 제외한다 | M | 제외 건이 다시 목록에 나타나지 않는다 |
| FR-08 | 보류 건은 N일(기본 30일) 후 검토 화면에만 재노출한다 | S | 메일은 재발송되지 않는다 |

> FR-06은 이 제품의 **가장 중요한 제약**입니다. 매일 같은 상품이 반복 추천되면 MD가 목록 자체를 신뢰하지 않게 됩니다.

### 5.3 우선순위

| ID | 요구사항 | 우선 | 수용 기준 |
|---|---|---|---|
| FR-09 | 여러 조건 충족·반응 강도가 큰 상품을 상단에 노출한다 | M | 목록·메일이 우선순위 점수 내림차순으로 정렬된다 |
| FR-10 | 조건 가중치는 지정된 순서를 따른다 | M | ① > ② > ③ > ⑤ > ⑥ > ④ 순으로 기본 가중치가 부여된다 |

### 5.4 발송량 제어

| ID | 요구사항 | 우선 | 수용 기준 |
|---|---|---|---|
| FR-12 | MD 1인당 하루 최대 **10종**까지 추천한다 | M | 11번째부터 이월 처리되어 메일에 담기지 않는다 |
| FR-13 | 상한 초과분은 폐기하지 않고 다음 영업일로 이월한다 | M | 이월 건이 다음 날 신규 건과 함께 재정렬된다 |
| FR-14 | MD별 상한 소진 현황을 화면에 표시한다 | S | `김효인 10/10 이월 3` 형태로 노출된다 |

> 배경: 추천이 한꺼번에 쏟아지면 MD가 소화하지 못해 미검토 재고가 쌓입니다. 상한은 **품질 유지 장치**입니다.

| **오늘의 추천 후보** | 빠른 판단 | KPI 3종 · MD별 배분 바 · 필터 · 후보 카드 목록 · (하단) 추천 조건 가이드 |
| 일일 추천 메일 | 발송본 확인 | 실제 발송 HTML 미리보기 |
| 추천·검토 이력 | 누적 데이터 조회 | 검색·필터 · 이력 테이블 · 엑셀 |
| 추천 성과 리포트 | 기준 고도화 | 퍼널 · 판단 분포 · 조건별 적중률 · 개선 제안 |
| 담당 MD 매핑 | 운영자 관리 | 요약 4종 · 인라인 편집 표 · 저장/되돌리기 |

### 6.1 후보 카드에 노출하는 정보 (확정)

판단에 필요한 최소 세트만 남깁니다.

```
[표지+순위칩]  상품번호 · 관리분류 · 판매상태
               도서명 (→ 상품 상세 새 탭)
               저자 · 출판사
               추천 사유 배지 (조건별 실측값 포함)
                                        [섭외][보류][제외]
                                        판단 결과 · 담당 MD
                                        [상품 상세에서 세부 지표 보기]
```

- 표지·도서명 클릭 시 상품 상세가 **새 탭**으로 열립니다.
- 세부 지표(초도 발주·당일 발주·7일 판매·순위·작가 이력)는 카드에 나열하지 않고 상품 상세에서 확인합니다.
- 추천 조건 가이드는 고정값 안내이므로 화면 **최하단**에 접힌 상태로 둡니다.

## 8. 릴리즈 계획

| 단계 | 범위 | 기간(안) | 완료 기준 |
|---|---|---|---|
| **Phase 1** | DB 스키마 + 추출 배치(조건 ③ 단독) | 2주 | 매일 후보가 적재되고 중복이 차단됨 |
| **Phase 2** | 조건 ①②④⑤⑥ 확장 + 우선순위·1일 상한 | 2주 | 6개 조건 전체 동작, MD별 TOP 10 발송 |
| **Phase 3** | 검토 화면 + 판단 API + 담당 MD 매핑 | 3주 | MD가 실제로 판단을 입력할 수 있음 |
| **Phase 4** | 메일 발송 + 리마인드 | 1주 | 영업일 10시 자동 발송 |
| **Phase 5** | 이력 화면 + 엑셀 | 1주 | 누적 데이터 조회·다운로드 |
| **Phase 6** | 성과 리포트 | 1주 | 조건별 적중률 확인 가능 |

**파일럿 운영** — Phase 4 완료 후 2주간 실제 발송하며 임계값(①② 기준)과 1일 상한을 조정합니다. 리포트(Phase 6)는 데이터가 한 달 이상 쌓인 뒤에야 의미가 생기므로 마지막에 배치했습니다.
