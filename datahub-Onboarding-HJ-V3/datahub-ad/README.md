# DataHub Onboarding V14 — DATA IN MOTION

V14는 V13 `DATA LAYER`와 별도로 만든 운동감 중심의 온보딩 후보다. 참고 사이트의 공간감과 대형 타이포그래피 문법을 차용하되, 온라인서점 직원이 보는 DataHub 온보딩이라는 목적에 맞게 재해석한다.

## 프로젝트 목적

온라인서점의 서비스와 업무에는 한 화면으로 설명하기 어려운 다양한 데이터가 동시에 존재한다. V14는 기능 목록을 나열하지 않고, 작은 사건에서 시작한 시야가 서비스 전체와 업무 환경으로 확장되는 체험을 통해 데이터의 규모를 전달한다.

## 핵심 컨셉 — DATA IN MOTION

> 하나의 작은 움직임을 따라가다 보면, 온라인서점 전체에서 서로 다른 데이터가 움직이고 있었음을 발견한다.

여기서 `MOTION`은 데이터 파이프라인이나 실시간 전송을 뜻하지 않는다. 온라인서점의 화면, 콘텐츠, 상품, 주문과 업무가 계속 변화하고 있으며 각 맥락에서 데이터가 사용된다는 시각적 은유다.

- 데이터는 하나의 목적지로 이동하거나 합쳐지지 않는다.
- 특정 사용자나 단일 상품의 여정을 추적하지 않는다.
- 장면의 이동과 스케일 변화로 데이터 세계의 범위를 체감시킨다.
- DataHub는 이 세계를 필요한 관점으로 탐색하는 도착점이다.

## V14의 시각 문법

- 화면을 가로지르는 강한 수평 이동
- 전경·중경·원경이 분리된 깊이감
- 장면의 내용을 압축해 전달하는 대형 한글 타이포그래피
- 카드 나열이 아닌 하나의 연속된 공간
- 작은 데이터 포인트와 부분적인 업무 표면
- 카메라가 이동하면서 화면 밖에 이미 존재하던 정보를 발견하는 연출
- 어두운 도입부에서 밝고 넓은 업무 세계로 확장되는 명도 변화

화려한 선이나 입자 자체가 주인공이 되어서는 안 된다. 움직임은 책, 콘텐츠, 서비스 사건과 업무 데이터로 시선을 옮기는 장치다.

## 전체 흐름

1. 작은 데이터 포인트와 함께 어두운 공간에서 시작한다.
2. 한 권의 책과 온라인 서비스에서 발생한 사건을 발견한다.
3. 검색, 콘텐츠, 반응, 주문 등 서로 다른 서비스 맥락이 하나의 넓은 공간에 나타난다.
4. 시야가 업무 영역으로 확장되며 상품, 콘텐츠, 주문에서 서로 다른 데이터가 사용됨을 본다.
5. 개별 장면이라고 생각했던 것들이 더 큰 온라인서점 데이터 환경의 일부였음을 발견한다.
6. 공간이 정면화되고 정돈되며 DataHub로 진입한다.

## V13·V15와의 차이

- V13은 현실 화면에 숨어 있던 흔적을 조용히 발견하는 관찰형 경험이다.
- V14는 움직임과 공간 확장으로 데이터 환경의 규모를 체감하는 운동형 경험이다.
- V15는 업무 질문을 데이터 관점의 층위로 분해하는 사고형 경험이다.

V14를 수정할 때 V13의 작은 annotation이나 V15의 정적인 카드 레이어를 중심 문법으로 가져오지 않는다. V14의 핵심은 이동하면서 더 큰 세계를 발견하는 감각이다.

## 디자인 원칙

- 대형 타이포그래피는 메시지를 압축해야 하며 오브젝트를 가리면 안 된다.
- 화면이 빠르게 지나가는 것보다 무엇이 새롭게 발견되는지가 먼저 느껴져야 한다.
- 여러 업무는 서로 다른 시각 문법을 가져야 하며 동일한 카드 배열로 보이면 안 된다.
- 스크롤을 내릴 때마다 시선이 이동할 명확한 다음 대상이 있어야 한다.
- 규모감은 빈 공간을 늘리는 것이 아니라 화면 밖으로 이어지는 정보의 범위로 만든다.
- DataHub 도착 전까지 제품 기능을 구체적으로 단정하지 않는다.

## 금지 사항

- 특정 개인의 행동 추적과 퍼널
- 하나의 상품을 끝까지 따라가는 공정도
- 데이터가 중앙으로 빨려 들어가거나 자동 통합되는 표현
- 노드 그래프와 다수의 연결선
- 의미 없이 반복되는 Light Trail과 입자 효과
- 근거 없는 KPI 또는 실시간 처리 표현
- 동일한 모니터·패널을 여러 장 공중에 배치하는 구성
- 실제 지원 여부가 확인되지 않은 DataHub 기능

## 최종 DataHub 적용

마지막 화면에는 `datahub_main.png` 실제 DataHub 캡처가 적용되어 있다. 임시 목업 UI는 노출하지 않으며, 실제 캡처가 Scene 자체의 opacity·원근·scale 변화와 함께 자연스럽게 형성된다. 이후 화면이 변경되면 같은 파일을 교체하는 것만으로 최종 UI를 갱신하며, 전환 구조와 카피·CTA 레이아웃은 유지한다. 최종 진입 주소는 `https://ax-datahub.yes24.com`을 사용한다.

## 현재 기준

V14는 V13과 독립된 실험안이다. 이후 수정은 운동감, 장면 간 깊이, 대형 타이포그래피의 가독성, 스크롤 리듬과 최종 DataHub 도착감을 중심으로 진행한다.
