# 새로 찾은 것 — `--slot-max` 제거 순서

**`h1/index.html:1522`** (`headBot` 측정) · **`h1/index.html:1563`** (`removeProperty('--slot-max')`)

`headBot` 을 1522 에서 재는데, 데스크톱 분기가 심어 둔 `--slot-max` 는 **41줄 뒤인 1563 에서야 지웁니다.** `getBoundingClientRect()` 는 그 자리에서 레이아웃을 강제 계산하므로, **직전 폭의 `--slot-max` 가 아직 붙은 상태로 글 높이를 재게 됩니다.**

`.slot` 은 `clamp(34px, 9vw, var(--slot-max,116px))` 라 `--slot-max` 가 `9vw` 보다 작을 때만 물립니다. `--slot-max` 는 1025~1100 구간에서 하한 52px 이므로, **그 폭에서 세로 흐름으로 좁히면** 52px 로 잰 글 높이가 그대로 띠 계산에 들어갑니다.

실측 (1회차 = 리사이즈 직후, 2회차 = layout() 한 번 더):

| 리사이즈 | 진입 전 `--slot-max` | 1회차 첫 카드 top | 도구줄 겹침 | 2회차 | 겹침 |
|---|---|---|---|---|---|
| 1100 → 900×667 | 52.0px | **177** | **1** | 210 | 0 |
| 1100 → 768×667 | 52.0px | **175** | **1** | 195 | 0 |
| 1050 → 900×667 | 52.0px | **177** | **1** | 210 | 0 |
| 1100 → 900×900 | 52.0px | 225 (11px 어긋남) | 0 | 236 | 0 |
| 1440 → 900×667 | 95.3px | 210 | 0 | 210 | 0 |

즉 **창을 1100 언저리에서 1024 이하로 끌어내리면 방금 고친 그 결함(첫 카드가 도구 줄을 덮음)이 다시 나고, 다음 `layout()` 이 돌 때까지 남습니다.** 1440 에서 내려올 때는 `--slot-max` 95.3px 이 `9vw` 보다 커서 물리지 않아 증상이 없습니다 — 그래서 캡처 검증에서 안 잡히셨을 겁니다.

고치는 법은 한 가지입니다. **`--slot-max`/`--card-clear` 를 정하는 블록(`h1:1557-1565`)을 `if(flowDown)` 블록보다 위로 올리면** 됩니다. 세로 흐름 분기가 항상 지워진 상태에서 글을 재게 되고, 데스크톱 분기는 순서가 바뀌어도 결과가 같습니다.

## 3. 폴백 경로 질문창 — 방법을 좁혀 달라 하신 건

**전제를 하나 정정합니다. 이 경로는 JS 가 죽은 게 아닙니다.**

`h1:1322` 의 `return;` 은 **IIFE 안의 조기 반환**이라, 축소모션·GSAP 부재 두 경우 모두 **스크립트는 살아서 돌고 있습니다.** 배너를 만들어 붙이고 버튼에 리스너를 다는 코드가 바로 그 위에서 실행되는 게 증거입니다. 단지 질문창 IIFE(`h1:2244-`)가 `return` 아래에 있어 **등록되지 못할 뿐**입니다.

따라서 마크업만으로 풀 필요가 없고, 두 층으로 나누면 됩니다.

**(가) 축소모션 · GSAP 부재 — JS 로 해결 (실제로 문제되는 경우 전부)**
질문창 IIFE 를 `h1:1322` 의 `return` **위로 옮기고**, 연출에 기대는 세 줄만 가드합니다.
```js
function submit(){
  const typed = (input.value || '').trim();
  echo.textContent = typed || SAMPLE_Q;
  ask.classList.toggle('offsample', !!typed && typed !== SAMPLE_Q);
  ask.classList.add('asked');
  if(!document.body.classList.contains('js')) return;   // 여기까지가 정직함의 몫
  if(current !== HOME){ paused = false; go(HOME); }
  layout(true);
  gsap.fromTo('#askreply', …);
  nodes.forEach(…);
}
```
`echo` · `offsample` · `asked` 는 GSAP 도 `layout()` 도 필요 없습니다. 이 세 줄이 "되받아 적고, 다르면 밝힌다"의 전부입니다.

**(나) JS 완전 차단 — 마크업/CSS 로 해결**
이 경우엔 무엇을 입력했는지 알 길이 자체가 없으므로, **처음부터 고정 샘플임을 밝혀 두는 것**이 유일하게 정직한 처리입니다. `.asknote` 는 지금 `#ask.offsample` 일 때만 켜지는데(`h1:189, 191`), 정적 문서에서는 항상 켭니다.
```css
body:not(.js) .asknote{display:block}
```
이러면 JS 가 어떤 이유로 죽든 답 카드에 "이 시연은 위 샘플 질문 하나만 답합니다"가 늘 붙어 있어, 관객이 무엇을 치든 시치미 떼는 상태가 되지 않습니다. **한 줄입니다.**

# 정리

이번 라운드는 지적 3건을 **전부, 그리고 근본적으로** 닫았습니다. 특히 띠 위 끝을 `H*.26` 상수에서 실측으로 바꾼 것과, "폭 기준 미디어쿼리로는 높이가 정하는 문제를 못 잡는다"를 `gcard-tiny` 로 갈라낸 것은 증상이 아니라 원인을 고친 수정입니다. 세로 흐름 28개 조합이 전부 무결하고 프로그램 줄이 하나도 잘리지 않는 상태는 이 문서가 지금까지 도달한 것 중 가장 깨끗합니다.

수치 정합도 열 곳 넘는 중복에도 불구하고 **한 군데도 어긋나지 않았습니다.** 논지를 통째로 갈아엎은 변경에서 이 정도면 잘 관리된 것입니다.

남은 것은 **1366×768 하나**입니다. 세 라운드째 열려 있고, 사내 노트북·프로젝터의 표준 해상도이며, 관객이 질문을 던지는 바로 그 순간에 메뉴 절반이 사라집니다. 이것만 닫으면 배포 O 입니다.

구조 제안은 한 번 더 남깁니다 — 경계값이 여전히 다섯(`L.mobile` 640 · `flowDown` 1024 · CSS 1032 · 640 · 430)이고, 이번 라운드의 잔여 결함 둘(1025~1032 밴드, `--slot-max` 순서)이 정확히 그 경계와 그 경계가 심는 변수에서 나왔습니다. JS 가 `matchMedia` 로 CSS 와 같은 판정을 읽게 하면 이 계열이 구조적으로 사라집니다.
