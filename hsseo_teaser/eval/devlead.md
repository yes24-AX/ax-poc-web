## 안별 기술 실사

### t1 (Lusion 계열) — 32점
1,003줄 / 43.9KB 단일 파일 / JS 의존성 0 (CDN은 Pretendard 폰트뿐).

손으로 쓴 GLSL 레이마처(구 7개 + 캡슐 6개, 픽셀당 80스텝)입니다. 방어는 제대로 되어 있습니다 — DPR 2 캡, 총 픽셀 1.15M 하드캡, 느린 프레임 8회 감지 시 해상도 1.0→0.6 자동 강하, 바운딩 스피어 게이트, IntersectionObserver + visibilitychange. 셰이더 컴파일 실패도 `nogl` 경로로 빠져 CSS 폴백이 뜹니다(`--disable-3d-apis` 캡처로 확인 — 6개 입구 pill이 전부 살아 있음). 다만 916행 `elapsed < T_END + 40` 조건 때문에 일시정지·재생 종료 후에도 rAF가 영원히 돕니다. 사내 내장 그래픽 PC에서 이 페이지를 열어두면 GPU를 계속 물고 있습니다.

### t2 (Bruno Simon 계열) — 26점
1,117줄 / 53.0KB / three.js r160을 importmap으로 CDN 로드.

저폴리 Lambert 씬(메시 약 40개 + InstancedMesh 150)이라 3D치고는 가볍습니다. CDN 차단 캡처에서 9초 타이머가 정상 작동해 정적 폴백으로 넘어갔습니다 — 다만 그 9초 동안 부팅 스피너만 보입니다. 치명적인 건 834행입니다: `if(k==='enter'){ e.preventDefault(); ... }` 가 전역이라, 키보드로 6개 게이트 링크에 Tab 이동 후 Enter를 눌러도 이동하지 않고 페이지가 리로드됩니다. 온보딩의 유일한 CTA가 키보드로 작동하지 않습니다.

### t3 (Cuberto 계열) — 37점
958줄 / 42.7KB / GSAP 3.12.5 CDN.

499행 `if(reduced || typeof gsap === 'undefined') return;` — 이 한 줄이 전부입니다. 문서의 기본 상태가 이미 "완성된 최종 화면"이고, GSAP이 정상일 때만 `body.js`가 붙어 시네마틱으로 바뀝니다. CDN을 0.0.0.0으로 막고 캡처하니 6개 입구가 그대로 있는 완성 화면이 나왔습니다. 입구 6개가 정적 마크업(`grep -c "../sites/"` = 6). 캔버스 없음, 상시 루프 없음.

### t4 (Obys 계열) — 38점
969줄 / 49.4KB / 외부 JS 의존성 전무.

5안 중 유일하게 GSAP·three.js 어느 것도 쓰지 않습니다. 빌더 6개를 `try/catch`로 개별 격리해 하나가 던져도 나머지가 삽니다(765–767행). 그레인 노이즈를 dataURL로 1회 베이크해 재사용합니다. 입구 6개 정적 마크업, `#summary` 스크린리더 요약, Skip/ESC 시 첫 입구로 포커스 이동까지 있습니다. 흠은 897–911행 `loop()`이 타임코드 갱신을 위해 끝난 뒤에도 영원히 rAF를 돌리고 visibilitychange 가드가 없다는 것 정도입니다(비용은 텍스트 2줄이라 미미).

### t5 (ERA 계열) — 20점
586줄 / 파일 9개 / 1,219KB (WebP 8장이 1,189KB, 최대 stock.webp 324KB).

코드 자체는 가장 짧고 읽기 좋습니다. 문제는 구조입니다. 입구 6개와 정적 폴백이 모두 GSAP에 묶여 있습니다 — `staticFallback()`(546행)이 스스로 `gsap.set`을 호출합니다. CDN을 막고 캡처한 결과는 완전한 검은 화면(10KB PNG, 로고와 눈금만)이었습니다. 6개 입구가 통째로 사라집니다. 게다가 첫 화면이 이미지 8장 프리로드(6초 타임아웃)에 묶여 있어, 모션 축소 사용자도 1.2MB를 기다려야 합니다. 전체화면 이미지에 `grayscale+contrast+brightness` 필터 + `mix-blend-mode` 베일을 clip-path로 계속 애니메이션하는 것도 저사양에서 부담입니다.

## 내 순위와 이유

**1위 t4, 2위 t3.** 유지보수와 장애 대응이 제 몫이라는 전제에서 답은 이 둘로 좁혀집니다. 외부 런타임 의존이 없거나(t4) 있어도 죽으면 최종 화면이 그대로 남는(t3) 구조라, 새벽에 jsdelivr가 흔들려도 저를 부를 일이 없습니다. 둘 다 입구 6개가 정적 마크업이라 JS가 통째로 실패해도 온보딩의 목적지는 살아남습니다. t4를 반 칸 앞에 두는 건 GSAP조차 없어서 자산 관리가 진짜로 0이기 때문입니다.

**3위 t1.** 코드 완성도와 폴백 설계는 t3·t4급인데 순전히 GPU 비용 때문에 내려갑니다. 이식은 가장 쉽지만(파일 하나, 의존성 0) 저사양 사무용 PC가 주 사용 환경이면 상시 레이마칭은 제가 감당할 리스크가 아닙니다.

**4위 t2.** 3D 씬 자체는 가볍고 폴백도 갖췄지만, three.js 벤더링 부담과 Enter 키 문제가 겹칩니다. 접근성 결함이 하필 CTA에 있습니다.

**5위 t5.** 시각적 완성도와 무관하게, 서비스에 올릴 수 없는 실패 모드를 가지고 있습니다. 외부 CDN 하나가 6개 입구를 전부 지웁니다.

## 채택한다면 반드시 고쳐야 할 것 (안별 1가지)

- **t1** — `t1/index.html:916`의 루프 조건을 고쳐 일시정지·종료 시 rAF를 실제로 멈출 것. 현재 `elapsed < T_END + 40`은 정지 중 `elapsed`가 고정되므로 항상 참이라 풀스크린 레이마치가 무한히 돕니다. 포인터 패럴랙스가 수렴한 뒤에는 정지하도록 `playing || pointerSettling` 형태로 바꾸면 됩니다.
- **t2** — `t2/index.html:834`의 전역 Enter 가로채기를 제거하거나 `document.activeElement`가 `a`/`button`이면 통과시킬 것. 지금은 키보드 사용자가 6개 입구 중 어디에도 들어갈 수 없습니다.
- **t3** — GSAP를 jsdelivr에서 받지 말고 사내에 벤더링할 것. 이미 안전하게 열화되지만, 그 열화가 곧 "연출 전체 상실"이라 script 태그 한 줄 바꾸는 비용으로 가용성을 크게 올릴 수 있습니다.
- **t4** — `t4/index.html:897-911`의 `loop()`가 마지막 장 도달 후에도, 탭이 가려져도 계속 돕니다. `cur===LAST`에서 `cancelAnimationFrame` 하고 `visibilitychange` 가드를 붙일 것.
- **t5** — 입구 6개와 정적 폴백을 GSAP에서 분리할 것. `#final`을 CSS 기본값으로 보이게 두고 연출이 그것을 감추는 방향으로 뒤집은 뒤, `typeof gsap === 'undefined'` 가드에서 인라인 스타일로만 폴백을 구성해야 합니다. 부수적으로 WebP 1.2MB는 리사이즈·재압축이 필요하고, 첫 페인트를 이미지 프리로드에서 떼어내야 합니다.
