# AX DataHub — 데이터를 찾아 떠나는 여행

카메라가 **데이터센터 복도를 실제로 통과하며** 흩어진 데이터를 스캔해 찾아내고,
마지막에 대시보드 홀에 도착하는 3D 애니메이션입니다.

페이지를 열면 알아서 재생됩니다. 스크롤은 사용하지 않습니다.
기본 배속은 **1.5× (약 25초)** 이고, 하단 컨트롤에서 바꿀 수 있습니다.

| 조작 | 동작 |
|---|---|
| 하단 재생 버튼 / `Space` | 일시정지 · 재생 (끝나면 다시 보기) |
| 하단 `1.5×` 버튼 / `[` `]` | 재생 시간 조절 — 0.5×(1분 16초) ~ 2×(19초) |
| 우측 챕터 점 클릭 | 해당 구역으로 이동 |
| `←` `→` | 이전 · 다음 구역 |
| 상단 진행바 클릭 | 원하는 지점으로 탐색 |

## 여정

카메라는 z = +700에서 출발해 −11,000까지, 하나의 긴 복도를 **끊김 없이** 이동합니다.

| # | 구역 | 월드 z | 보이는 것 |
|---|---|---|---|
| 0 | **진입** | 700 → −900 | 서버 랙이 늘어선 복도, 천장 조명이 규칙적으로 지나감 |
| 1 | **MSTR** | −2,150 ~ −3,410 | 매출 · 재고 · 발주 · 상품권 랙에 불이 들어오고 데이터 큐브가 떠오름 |
| 2 | **CLICKSTREAM** | −4,780 ~ −3,990 | 세션 행동 경로(홈 → 검색 → 상품 → 장바구니 → 주문)가 공중에 지그재그로 떠오름 |
| 3 | **UNIFY** | −6,500 | 복도 한가운데의 조인 코어. GA4 · CLICKSTREAM · SALES 세 갈래가 모임 |
| 4 | **PERFORMANCE** | −8,600 ~ −9,800 | 유입 → 클릭 → 주문 → 매출, 점점 좁아지는 네 개의 퍼널 게이트를 **관통** |
| 5 | **DASHBOARD** | −11,350 ~ −11,680 | 밝은 홀에 떠 있는 지표 패널과 이상 징후 알림 |

구역 사이마다 `01 MSTR` `02 CLICKSTREAM` 같은 대형 표지가 공간에 서 있고,
카메라가 그것을 통과하며 다음 구역으로 넘어갑니다.

## "데이터를 찾는" 장치 — 스캐너 HUD

우상단 패널이 지금 무엇을 찾고 있는지 계속 알려줍니다.

```
BOOTING → SCANNING → TRACING → JOINING → MEASURING → COMPLETE
```

찾아낸 레코드 수는 구역을 지날 때마다 **누적**됩니다.
MSTR 6,143,780건(랙 4종 합계) → 클릭스트림 9,572,680 → GA4 조인 12,486,120 → 12,898,920.
화면 중앙의 조준 리티클은 구역마다 스캔 대상 위로 이동해 잠기고, 대상 이름을 띄웁니다.

## 왜 WebGL이 아닌가

이 PC의 크롬은 GPU 가속이 꺼져 있어 WebGL 컨텍스트 생성 자체가 실패합니다.
그래서 3D를 **CSS 3D Transform**으로 구현했습니다.

| 역할 | 기술 |
|---|---|
| 복도 · 원근 | CSS `perspective` + `preserve-3d` |
| 서버 랙 · 데이터 큐브 | 6면 CSS 박스 (면별 명도차로 조명 표현) |
| 공기 원근 · 컬링 | 자체 뎁스 포그 (카메라 거리 기반) |
| 카메라 · 재생 | GSAP 타임라인 |
| LED · 회전 · 부유 | CSS keyframes (브라우저 네이티브) |

### 카메라

CSS에는 카메라가 없으므로 월드 전체에 **역변환**을 겁니다.

```js
world.style.transform =
  `rotateX(${-rx}deg) rotateY(${-ry}deg) translate3d(${-x}px, ${-y}px, ${-z}px)`;
```

`camera.js`의 웨이포인트 19개를 smoothstep으로 보간해 복도를 매끄럽게 지나갑니다.
MSTR 구역에서는 좌우로 번갈아 붙어 랙을 스치고, 통합 코어는 옆을 크게 돌아 지나갑니다.

### 뎁스 포그가 3D를 만든다

CSS 3D는 아무리 멀어도 또렷하게 보이고, 카메라 뒤로 넘어간 요소는 뒤집혀 보입니다.
`fog.js`가 매 프레임 각 오브젝트의 카메라 기준 깊이로 투명도를 조절합니다.

```
depth = cameraZ - objectZ
 · < 30      → 사라짐 (지나쳤다 / 뒤집힘 방지)
 · 30~260    → 서서히 사라짐
 · 260~1500  → 완전 불투명
 · 1500~2700 → 어둠 속에서 서서히 나타남
```

투명도 0인 요소는 `visibility: hidden`이 되어 렌더링에서 빠집니다.
덕분에 월드 610개 요소 중 화면에 그려지는 것은 **항상 10~48개**입니다. 포그가 곧 컬링입니다.

### 완급

진행도를 시간에 대해 일정하게 흘리면 밋밋해집니다. `story.js`의 `BEATS`가
구역으로 **이동**할 때는 빠르게, 구역에 **머무를** 때는 느리게 흐르도록 나눕니다.
장면 상태(문구·색·HUD·랙 점등)는 콜백이 아니라 현재 진행도에서 매번 다시 계산하므로,
챕터를 클릭해 건너뛰어도 어긋나지 않습니다.

## 실행 방법

ES Module을 쓰므로 로컬 서버가 필요합니다 (`file://` 불가).

```bash
npx serve .
```

접속: `http://localhost:포트/ax_datahub/` (레포 루트에서 실행 시).

> GSAP과 Pretendard 폰트만 CDN에서 받습니다. 폰트가 늦어도 1.2초 뒤에는 화면이 시작됩니다.

## 코드 구조

```
ax_datahub/
├── index.html
├── styles/
│   └── main.css     # 3D 스테이지, 6면 박스, 랙·게이트·패널, HUD, 재생 컨트롤
├── src/
│   ├── main.js      # 엔트리 — 월드 조립, GSAP ticker 렌더 루프
│   ├── data.js      # 구역 좌표 · 문구 · 랙 목록 · 게이트 수치 (여기만 고치면 된다)
│   ├── world.js     # 데이터센터 건설 (복도 · 랙 · 경로 · 코어 · 게이트 · 홀)
│   ├── camera.js    # 웨이포인트 보간 → #world 역변환
│   ├── fog.js       # 뎁스 포그 + 컬링
│   ├── hud.js       # 스캐너 패널 · 조준 리티클
│   └── story.js     # 자동 재생 완급 + 재생 컨트롤
└── README.md
```

## 커스터마이징

| 하고 싶은 것 | 위치 |
|---|---|
| 문구 · 스캔 내용 · 구역 색 | `data.js` → `ACTS` |
| 구역 위치 · 복도 치수 | `data.js` → `ZONE`, `HALL` (카메라 웨이포인트도 함께 조정) |
| 데이터 랙 · 퍼널 수치 | `data.js` → `DATA_RACKS`, `GATES`, `BOARDS` |
| 카메라 동선 | `camera.js` → `KEYFRAMES` |
| 구역별 완급 | `story.js` → `BEATS` (inDur = 이동, outDur = 머무름) |
| 기본 배속 | `story.js` → `DEFAULT_RATE` (바꿀 때 `RATE_KEY` 버전도 함께 올릴 것) |
| 공기 색 | `story.js` → `AIR` |
| 포그 거리감 | `fog.js` → `DEFAULTS` |

원근 때문에 **월드 좌표 크기 ≠ 화면 크기**입니다.
`화면크기 ≈ 월드크기 × perspective / (perspective + depth)` 이므로,
멀리 둘 오브젝트일수록 크게 잡아야 합니다. (구역 표지 178px인 이유)

## 검증 내역

- 카메라가 +700 → −11,000까지 단조 이동, 6개 구역의 문구 · 색 · HUD 모드 · 랙 점등이 전부 의도대로 전환
- **원근 확인** — 복도 랙 전면 높이가 깊이에 따라 426 → 186px로 수렴, 퍼널 게이트가 590 → 137px로 중첩되어 멀어짐
- 구역 표지가 접근하며 346 → 673px로 커지고 카메라가 관통
- 포그 컬링 — 610개 중 화면에 10~48개만 렌더링
- 챕터 6곳 클릭 시 해당 구역으로 정확히 이동, 인디케이터·HUD 일치
- 진행바 탐색 오차 없음, 배속 5단계 총 길이 표기 일치
- 데스크톱 1440×860 — 도착 시 대시보드 4장이 화면 좌우를 감싸고 중앙 714px이 비어 문구와 겹치지 않음
- 모바일 375×812 — 전용 좌표로 4장 모두 화면 안, 문구와 겹침 0
- 콘솔 오류 0건
