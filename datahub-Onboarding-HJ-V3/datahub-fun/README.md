# DataHub Onboarding V15 — QUESTION LAYERS

V15는 V13과 V14를 유지한 채 별도로 실험하는 질문 중심의 DataHub 온보딩 후보다. 온라인서점 직원이 실제 업무에서 떠올리는 질문을 출발점으로 삼아, 질문과 데이터 관점의 관계를 하나의 연속된 시네마틱 지면으로 보여준다.

## 프로젝트 목적

DataHub의 기능 메뉴를 먼저 설명하지 않는다. 직원이 업무에서 자연스럽게 갖는 질문에는 맥락이 있고, 그 질문을 살펴보기 위해 필요한 데이터와 관점이 서로 다르다는 사실을 경험하게 한다. 마지막에는 펼쳐졌던 층위가 정돈되며 DataHub 탐색 경험으로 진입한다.

## 핵심 컨셉 — QUESTION LAYERS

> 우리가 말로 묻는 것을, 데이터의 관점으로 바라본다.

하나의 질문은 단순한 검색어가 아니다. 질문을 둘러싼 업무 맥락, 살펴볼 데이터, 바라보는 관점이 함께 존재한다. V15는 이를 다음 네 개의 층위로 시각화한다.

- `QUESTION`: 업무에서 출발한 실제 질문
- `CONTEXT`: 질문이 발생한 콘텐츠와 운영 맥락
- `DATA`: 질문과 관련해 살펴볼 수 있는 값의 표면
- `VIEWS`: 상품, 콘텐츠, 판매, 반응 등 서로 다른 업무 관점

이 층위는 실제 DataHub의 화면 구조나 데이터 모델을 재현한 것이 아니다. 제품 기능이 확인되기 전에도 사용할 수 있는 중립적인 서사 장치다.

## 전체 서사

1. 온라인서점의 일은 매일 새로운 질문에서 시작된다는 사실을 제시한다.
2. “요즘 어떤 책에 관심이 모이고 있을까?”라는 하나의 질문이 단어 단위로 형성된다.
3. 질문 주변에서 QUESTION, CONTEXT, DATA, VIEWS 네 층위가 순서대로 펼쳐진다.
4. 같은 질문도 상품, 콘텐츠, 판매, 반응 관점에서 다르게 바라볼 수 있음을 보여준다.
5. 시야가 넓어지며 온라인서점에는 서로 다른 업무 질문이 동시에 존재함을 발견한다.
6. 질문이 달라지면 먼저 살펴볼 데이터 관점도 달라진다는 결론에 도착한다.
7. 펼쳐진 구조가 하나의 정돈된 인터페이스로 조립되며 DataHub로 진입한다.

## 장면별 역할

### 도입 — 질문의 시작

첫 문장은 V15 전체의 관점을 고정한다. 대형 서체와 충분한 여백을 사용하되, 후반 장면이나 카드가 첫 화면에 겹치지 않아야 한다.

### 오늘의 질문

질문의 주요 단어가 순차적으로 나타나면서 완성된다. 타이핑 효과처럼 기계적으로 보이기보다 생각이 구체화되는 인상을 만든다.

### 데이터의 층위

네 장의 카드는 동시에 튀어나오지 않고 QUESTION → CONTEXT → DATA → VIEWS 순서로 형성된다. 카드를 단순 기능 메뉴처럼 보이게 하지 않고 하나의 질문을 해석하는 지면으로 다룬다.

### 서로 다른 관점

같은 데이터 표면에서 강조점이 바뀌며 상품, 콘텐츠, 판매, 반응이라는 관점의 차이를 보여준다. 실제 데이터 관계나 자동 연결을 암시하지 않는다.

### 업무의 질문

온라인서점의 서로 다른 업무 질문을 통해 세계를 확장한다. 질문 카드의 개수 자체보다 질문마다 필요한 관점이 달라진다는 사실이 중요하다.

### 질문에서 탐색으로

질문과 데이터 관점을 짝지어 보여주되 정답이나 자동 추천처럼 표현하지 않는다. 사용자가 무엇을 먼저 살펴볼지 판단하는 탐색의 출발점이다.

### DATAHUB

마지막 질문 카드가 잠시 정착한 뒤, 크기와 구조가 변하며 중립적인 DataHub UI Shell로 확장된다. 이전 장면이 흰 배경에 잔상처럼 비치거나 새 화면이 단순 fade-in되는 방식은 피한다.

## 고유 시각 문법

- Noto Serif KR 기반의 큰 질문 문장
- IBM Plex Mono 기반의 작은 장·데이터 표기
- 따뜻한 종이 질감과 편집 지면의 여백
- 질문을 나타내는 burnt orange와 데이터 관점을 나타내는 teal
- 단어 단위로 정착하는 질문 타이포그래피
- 순차적으로 상승하는 레이어
- 관점 변화에 따라 이동하는 작은 강조점
- 마지막 질문 카드가 UI Shell로 확장되는 morph

애니메이션은 장식을 추가하기 위한 것이 아니라 질문 → 층위 → 관점 → 탐색이라는 사고의 흐름을 보여주기 위해 사용한다.

## V13·V14와의 차이

- V13 `DATA LAYER`: 현실과 서비스에서 원래 존재하던 데이터 흔적을 발견한다.
- V14 `DATA IN MOTION`: 움직임을 따라 데이터 환경의 규모를 발견한다.
- V15 `QUESTION LAYERS`: 업무 질문을 데이터 관점의 층위로 펼쳐 사고의 구조를 발견한다.

V15는 세 버전 중 가장 개념적이고 편집 디자인에 가깝다. V13의 실사 장면을 추가하거나 V14의 강한 공간 이동을 중심 연출로 가져오지 않는다.

## 디자인과 모션 원칙

- 한 화면에는 하나의 질문 또는 하나의 인식 변화만 명확하게 남긴다.
- 중요한 문구는 읽기 전에 교체되지 않도록 충분한 스크롤 구간을 확보한다.
- 레이어는 동시에 등장하지 않고 인지 가능한 순서로 형성된다.
- 카드가 많아져도 대시보드나 서비스 메뉴처럼 보이지 않게 한다.
- 모션은 질문의 구조와 관점 변화를 설명해야 한다.
- 마지막은 질문 카드 정착 → UI 골격 등장 → 최종 카피·CTA의 순서를 유지한다.
- 전환 시 이전 장면의 문구나 카드가 다음 장면에 잔상처럼 남지 않는다.

## 의미상 주의사항

- DataHub가 자연어 질문을 이해하거나 자동으로 답한다고 표현하지 않는다.
- 질문과 데이터 관점의 매핑을 제품 추천 기능처럼 표현하지 않는다.
- 모든 데이터를 자동 통합·연결·수집한다고 단정하지 않는다.
- 실시간 변화, 인과관계, KPI를 근거 없이 만들지 않는다.
- 질문은 탐색의 출발점이며 답변 기능이 아니다.
- 각 층위는 실제 제품 정보구조가 아니라 중립적인 은유다.

## 실제 DataHub 화면 적용

마지막 UI Shell에는 `datahub_main.png` 실제 DataHub 캡처가 적용되어 있다.

- 이후 실제 화면이 변경되면 같은 파일을 교체해 Shell 내부 전체 화면 이미지를 갱신한다.
- 캡처 바깥에 실제 제품에 없는 메뉴나 기능을 임의로 추가하지 않는다.
- 최종 카피와 CTA는 실제 제품 UI를 가리지 않는다.
- 캡처 적용 후에는 scale, position, object-position과 주변 여백만 조정한다.
- 최종 진입 주소는 `https://ax-datahub.yes24.com`이다.

## 현재 기준

V15는 질문에서 출발해 DataHub 탐색으로 도착하는 독립된 후보안이다. 이후 수정은 새로운 장면을 추가하기보다 문구 유지 시간, 레이어 전환의 가독성, 스크롤 리듬, 마지막 morph와 실제 UI 적용을 중심으로 진행한다.

향후 수정의 판단 기준은 다음과 같다.

> 이 변화가 질문과 데이터 관점의 관계를 더 명확하게 만드는가?

그렇지 않다면 단순한 장식이나 기능 설명은 추가하지 않는다.
