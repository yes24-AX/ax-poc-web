호출 가이드

YES24 Open API를 처음 사용하는 개발자를 위한 호출 가이드입니다. 실제 코드 예제와 함께 인증, 요청, 응답, 에러 처리까지 한 번에 정리했습니다.

5분 안에 시작하기

  1. API Key 신청 페이지에서 키를 발급받습니다.
  2. 아래 cURL을 복사해 터미널에서 실행합니다. YOUR_API_KEY 만 교체하세요.
  3. 응답 JSON을 확인하면 끝! 이제 자유롭게 호출하실 수 있습니다.
curl -X GET "https://api.yes24.com/v1/products/9788960778795" \
  -H "Authorization: Bearer YOUR_API_KEY"

SDK 설치 (선택)

공식 SDK를 사용하면 인증·재시도·페이지네이션을 직접 구현하지 않아도 됩니다.

npm install @yes24/openapi
# 또는
yarn add @yes24/openapi
pip install yes24-openapi
// build.gradle
implementation 'com.yes24:openapi-client:1.0.0'

최초 호출 예제

import { Yes24Client } from '@yes24/openapi';

const client = new Yes24Client({ apiKey: process.env.YES24_API_KEY });
const book = await client.products.get('9788960778795');
console.log(book.title);
from yes24 import Yes24Client

client = Yes24Client(api_key=os.environ['YES24_API_KEY'])
book = client.products.get('9788960778795')
print(book.title)

API Key 보관 원칙

  • 절대 클라이언트에 노출하지 마세요. 브라우저·모바일 앱 코드에 직접 박지 말고, 자사 서버에서 프록시 형태로 호출하세요.
  • 환경변수 또는 Secret Manager(AWS Secrets Manager, GCP Secret Manager 등)에 저장하는 것을 권장합니다.
  • 유출이 의심되면 즉시 이메일(openapi@yes24.com)로 키 재발급을 요청해 주세요.

필수 헤더

헤더필수설명
Authorization필수Bearer {API_KEY}
Accept권장application/json
User-Agent권장서비스명/버전 형태 (예: my-app/1.2.0) — 운영 추적에 사용됩니다.
X-Request-Id선택클라이언트 측 trace ID. 응답 헤더로 그대로 반환됩니다.

요청 형식

  • 모든 요청은 HTTPS로 전송해야 합니다.
  • GET 요청의 파라미터는 쿼리스트링으로, POST/PUT 요청의 페이로드는 JSON Body로 전송합니다.
  • 한글 파라미터는 encodeURIComponent로 URL 인코딩 후 전송하세요.
const q = encodeURIComponent('파이썬');
const url = `https://api.yes24.com/v1/search?query=${q}&size=10`;

페이지네이션

목록 형태의 응답은 page·size 파라미터로 페이징합니다. 응답에는 total 필드가 함께 반환됩니다.

{
  "total": 1284,
  "page": 3,
  "size": 20,
  "items": [ /* ... */ ]
}

대용량 데이터는 page 방식보다 cursor 방식(향후 v2 지원)을 권장합니다.

응답 필드 선택

응답 본문 크기를 줄이고 싶다면 fields 파라미터로 필요한 필드만 받을 수 있습니다.

GET /v1/products/9788960778795?fields=title,author,price

Rate Limit 처리

응답 헤더에 다음 정보가 함께 반환됩니다.

헤더설명
X-RateLimit-Limit현재 윈도우의 호출 한도
X-RateLimit-Remaining남은 호출 수
X-RateLimit-Reset한도 리셋되는 Unix 타임스탬프

한도 초과 시 HTTP 429 Too Many Requests가 반환되며, Retry-After 헤더에 다시 시도할 시간이 초 단위로 안내됩니다.

재시도 전략 (권장)

  • 5xx 응답과 429 응답에 한해 재시도합니다. 4xx는 재시도하지 마세요.
  • 지수 백오프(Exponential Backoff) + Jitter 를 적용합니다. 예: 1s → 2s → 4s → 8s, 각 단계에 ±20% jitter
  • 최대 재시도 횟수는 3회를 넘기지 않습니다.
async function callWithRetry(url, options, retries = 3) {
  for (let i = 0; i <= retries; i++) {
    const res = await fetch(url, options);
    if (res.ok) return res.json();
    if (res.status !== 429 && res.status < 500) {
      throw new Error(`API error ${res.status}`);
    }
    const wait = Math.pow(2, i) * 1000 * (0.8 + Math.random() * 0.4);
    await new Promise(r => setTimeout(r, wait));
  }
  throw new Error('Retries exhausted');
}

에러 처리

모든 에러 응답은 동일한 포맷을 가집니다. requestId 는 지원팀 문의 시 함께 전달해 주세요.

{
  "error": {
    "code": "RATE_LIMIT_EXCEEDED",
    "message": "분당 호출 한도를 초과했습니다.",
    "requestId": "req_01HZE7K9X2Y..."
  }
}

캐싱 권장

  • 상품 상세·카테고리 트리 같은 변경 빈도가 낮은 응답은 최소 10분 이상 캐시하세요.
  • 베스트셀러는 1시간 이상, 신간은 30분 이상이 적절합니다.
  • 응답 헤더의 Cache-Control 값을 그대로 따르는 것이 가장 안전합니다.

모니터링

  • 호출량·에러율·평균 지연 시간은 별도 모니터링 도구(Datadog, Grafana 등)로 추적하거나, 응답 헤더의 X-RateLimit-* 값을 로깅해 관리하세요.
  • 일일 호출량의 80% 도달 시 등록된 이메일로 자동 알림이 발송됩니다.
  • 장애 발생 시 상태 페이지(status.yes24.com)에서 공지됩니다.

보안 체크리스트

  • ✅ API Key를 클라이언트에 노출하지 않았는가
  • ✅ HTTPS로만 호출하는가
  • ✅ 응답 데이터에 출처(YES24) 를 명시했는가
  • ✅ 이상 호출이 감지되었을 때 키를 즉시 재발급할 수 있는 절차가 있는가
  • ✅ 운영(Live)과 개발(Sandbox) 키를 분리해 관리하는가
