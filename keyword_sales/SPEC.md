# 키워드 판매 분석 — 구현 사양

POC 화면: `keyword_sales/index.html` (정적 파일, 목업 데이터로 동작)
작성일 2026-09-07

---

## 1. 이 화면이 푸는 문제

**특정 키워드 관련 상품이 얼마나 팔렸는지를 집계해 언론에 매출·판매량 데이터를 제공하는 것**이
목적이다. 지금은 검색 결과와 판매 데이터를 따로 뽑아 수작업으로 합치고 있다.

목적이 언론 제공이라 일반 분석 화면과 우선순위가 다르다:

- **틀린 숫자를 되돌릴 수 없다** → AI 관련성 판정과 담당자 검수가 가장 중요하다.
  `필사` 검색은 필터 ON/OFF에 따라 총 판매량이 두 배 넘게 갈린다.
- **"전년 대비 몇 %"가 기사의 절반이다** → 비교 구간 수치가 화면 전면에 있어야 한다.
- **나중에 "그 숫자 어떻게 나왔냐"에 답해야 한다** → 산출 조건을 화면과 파일에 함께 남긴다.
- **사내 정보가 기자에게 나가면 안 된다** → 대외 제공용 내보내기를 분리한다.

그래서 화면의 주인공은 상품 순위표가 아니라 **키워드 집계 숫자**다.

**핵심 제약:** 검색 API 응답에는 판매량·매출이 없다. 상품번호(`itemId`)를 조인 키로
판매 데이터를 별도 조회해야 한다.

## 2. 파이프라인 — 순서가 중요하다

```
① 검색 API        키워드 → 상품 목록 (상품번호 포함)
② 상세 조건        분야·태그·재검색으로 모수를 먼저 좁힌다 (§5.1)
③ AI 관련성 판정   '필사' 검색에 걸린 '필사적인 밤'을 근거와 함께 제외
④ 판매 집계        상품번호 × 기간 → 판매량 / 매출
⑤ 순위·점유율      ②③을 통과한 '집계 대상'을 모수로 계산
```

**②③이 ④⑤보다 먼저여야 한다.** 순위·점유율·KPI 총합이 전부 관련 상품 집합을 모수로
계산되기 때문이다. 엑셀 다운로드 시점에만 필터링하면 화면의 1위와 엑셀의 1위가 달라지고
점유율이 어긋난다.

'필사' 키워드가 이 문제를 그대로 보여준다 — 검색 결과에 『필사의 추격』·『필사적인 밤』
같은 오탐이 섞이고, 그중 일부는 판매량 상위권이다. 2026-01-01~09-07 기준으로 필터를 끄면
총 판매량 **14,110부·15종**, 켜면 **7,511부·9종**으로 거의 두 배가 갈린다.

## 3. 서버 계약

### 3.1 검색

```
GET /api/keyword-sales/search
    ?query = 인공지능            (필수)
    &page = 1 &pageSize = 200    (전건 조회 — §4 페이징 참고)
```

상품군·정렬은 파라미터로 넘기지 않는다. **상품군은 좌측 상세 조건에서 거르고**(§5.1),
정렬은 어차피 전건을 집계하므로 결과에 영향이 없다.

`GET /v1/goods/itemList` 프록시. 응답 봉투를 그대로 전달한다.

```jsonc
{ "success": true, "message": "OK", "errorCode": null,
  "data": {
    "meta": { "apiTitle": "...", "query": "인공지능", "total": 214, "page": 1, "pageSize": 20 },
    "data": { "items": [ { "sortOrder": 1, "itemId": "194483933", "title": "...",
      "subTitle": "...", "author": "...", "publisher": "...", "isbn13": "...", "ean": "...",
      "shopPrice": 32000, "salePrice": 28800, "supplyRate": 68, "publishDate": "2026-08-05",
      "itemStatus": "판매중", "dispCategory": "001001003032", "dispCategoryName": "...",
      "starScore": 4909, "reviewCount": 11, "goodsStatGbSort": 2,
      "goodsGroup": "국내도서",
      "hashtags": ["청년패스", "인공지능", "노동"],
      "cover": "...", "link": "..." } ] }
  } }
```

- `goodsGroup`: 상품군(`국내도서` / `eBook` / `외국도서` …). 좌측 분야 트리의 최상위다.
- 표지: `https://image.yes24.com/goods/{itemId}/L`
- 상세: `https://www.yes24.com/product/goods/{itemId}`
- 실패: `errorCode` = `SEARCH_001`(결과 없음) / `INVALID_PARAM`
- `hashtags`: 사내 검색 응답의 `해시태그` 필드(공백 구분 문자열)를 배열로 파싱해 전달한다.
  화면에서 **검색 키워드와 일치하는 태그를 강조**해 "왜 이 상품이 걸렸는지"를 보여주고,
  AI 관련성 판정의 입력으로도 넘긴다 — 제목·부제만으로 애매한 상품의 판단 근거가 된다.
  (태그 운영 현황은 `tag_monitoring` POC 참고. `청년패스`만 달린 상품은 미태깅 취급)

### 3.2 AI 관련성 판정 (내부 AI API 경유)

```
POST /api/keyword-sales/relevance
{ "query": "필사",
  "items": [ { "itemId", "title", "subTitle", "author", "publisher", "dispCategoryName" } ] }

→ { "rows": [ { "itemId": "195330019", "verdict": "excluded",
                "confidence": 0.95,
                "reason": "제목의 필사는 필사적(必死的)의 일부로 쓰였을 뿐, 필사 행위와 무관한 장편소설이다." } ] }
```

구현 시 반드시 지킬 것:

- **배치 1회 호출.** 상품 1건당 1회 호출 금지 — 200종이면 지연·비용이 선형으로 터진다.
- **응답은 `itemId`로 매칭.** 순서·개수가 요청과 다를 수 있으므로 인덱스를 신뢰하지 않는다.
- **누락은 보수적으로 처리.** 응답에 없는 `itemId`는 `relevant` + `confidence: null`.
  (놓치는 쪽보다 남기는 쪽이 안전 — 담당자가 화면에서 직접 제외할 수 있다)
- **`(query, itemId)` 키로 캐싱.** 같은 키워드 재검색 시 재판정하지 않는다.
- `confidence < 0.7`은 화면에서 `검토 필요` 배지로 표시한다.

### 3.3 판매 집계

```
POST /api/keyword-sales/stats
{ "itemIds": ["194483933", ...], "from": "2026-08-09", "to": "2026-09-07",
  "unit": "day|month|year" }

→ { "rows":  [ { "itemId", "qty", "amount", "buckets": [ { "key", "qty", "amount" } ] } ],
    "base":  [ { "itemId", "qty", "amount" } ],     // 비교 구간 (전년 동기 또는 직전 동기간)
    "total": { "qty", "amount" } }
```

- 조인 키는 **상품번호(`itemId` = `GOODS_NO`)** — `ebook_solo_pub/SPEC.md`와 동일한 키다.
- 매출액 = `판매량 × 판매가`(정가 아님).
- `base` 구간은 §4의 비교 구간 규칙을 따른다 (1년 이하 → 전년 동기, 초과 → 직전 동기간).
- **`itemIds`는 검색 결과 전체를 보낸다.** 화면 `pageSize`(20)와 무관하게 순위가 정확하려면
  전체 집합의 판매량이 필요하다. 상한이 필요하면 `statsLimit`(예: 200)을 별도로 둔다.
- `unit` 은 화면에서 **조회 기간을 경계에 맞추는 용도**로만 쓴다 (월 → 1일~말일, 연 →
  1/1~12/31, 끝은 오늘로 클램프). 맞추지 않으면 부분 구간이 온전한 달·연도처럼 읽힌다.
  주 단위는 언론 데이터에 쓰이지 않아 제외했다.
- 버킷 배열(`buckets`)은 화면 차트를 제거하면서 현재 쓰이지 않는다. 계약에는 남겨두되
  구현 우선순위는 낮다.

## 4. 클라이언트 계산

순위·점유율·증감률은 **서버가 아니라 화면에서** 계산한다 — 상세 조건, AI 필터 ON/OFF,
담당자 수동 조정에 따라 모수가 바뀌기 때문이다.

| 항목 | 계산 |
|---|---|
| 키워드 내 순위 | 관련 상품 집합 내 정렬축(판매량 or 매출) 내림차순 |
| 증감률 | `(현재 − 비교구간) ÷ 비교구간`. 비교구간 판매량이 0이면 `신규` |
| 점유율 | 해당 상품 ÷ 관련 상품 합계, **분자·분모 모두 현재 정렬축** |

**비교 구간**은 조회 기간 길이에 따라 자동으로 정해진다 — 1년(366일) 이하면 **전년 동기**
(같은 구간을 1년 전으로 이동), 그보다 길면 **직전 동일 길이 기간**. 화면·엑셀의 라벨도
그에 맞춰 바뀐다. 순위 변동(▲▼)은 언론 제공에 쓰이지 않아 제거했다.

**점유율은 시장 점유율이 아니라 "이 키워드 검색 결과 안에서의 비중"이다.** 모수는 AI 필터
상태를 따라간다(ON이면 관련 상품, OFF면 검색 전건). 정렬축과 반드시 함께 움직여야 한다 —
판매량으로 순위를 매기면서 매출 점유율을 보여주면 1위의 점유율이 2위보다 낮게 나온다.
헤더도 `판매량 점유율` / `매출 점유율`로 바뀐다.

전체/분야 내 순위가 필요해지면 `stats` 응답에 `catRank`를 추가해 확장한다.

### 페이징

**페이징은 표시 단위일 뿐, 집계 모수가 아니다.** 검색 API의 `page`/`pageSize`로 20건만
받아 오면 그 20건 안에서의 순위가 되어 전부 틀린다. 그래서:

- `search`는 검색 결과 **전건**(상한 `statsLimit`, 예: 200)을 받고, `relevance`·`stats`도
  전건에 대해 수행한다.
- 순위·점유율·KPI를 전건 기준으로 계산한 **뒤에** 화면에서 잘라 보여준다.
- 엑셀 다운로드는 **현재 페이지가 아니라 전건**을 내보낸다.
- 페이지는 검색·기간·단위·정렬·탭·필터가 바뀌면 1페이지로 되돌린다.
- 페이지당 10/20/50/100건(기본 20).

## 5. 화면 동작

1. 검색 응답 도착 → **표를 즉시 렌더** (전체 기준 잠정 순위 + `판정 중…` 표시)
2. `relevance` 배치 1회 호출
3. 판정 도착 → 제외 행 분리 + **순위·점유율·KPI 전부 재계산**

**담당자 통제** (AI 오판을 사람이 덮어쓸 수 있어야 한다)

- `AI 관련성 필터` ON/OFF 토글 — OFF면 전체 집합 기준으로 재계산
- 행별 `제외` / `집계에 포함` 버튼 — 수동 변경은 `사용자 수정` 배지로 구분
- 제외 항목은 숨기지 않고 **`제외 (n)` 탭**에 판정 근거와 함께 남긴다. 판정이 맞는지
  검증할 수 있어야 하기 때문이다.

### 5.1 좌측 상세 조건 — 실서비스 규모의 전제

실제 `인공지능` 검색은 상품 6,919종(국내도서 4,638종)이다. 이 규모에서 AI 판정 결과를
한 건씩 눌러 검수하는 것은 불가능하다. 그래서 **상세 조건을 AI 판정보다 앞에 적용해
모수를 먼저 좁힌다.**

```
검색 전건 → ① 상세 조건(분야·태그·재검색) → ② AI 관련성 판정 → ③ 담당자 검수
```

항목은 둘뿐이다(+재검색). 검색 조건(도서명/저자/출판사)과 `AI 활용`은 언론 집계에 쓰이지
않아 넣지 않았다. 상단 검색줄의 `국내도서`·`인기도순` 셀렉트도 제거했다 — 상품군은 아래
분야 트리로 흡수했고, 정렬은 전건을 집계하므로 결과에 영향이 없다.

| 항목 | 동작 |
|---|---|
| 분야 | **2단 트리.** 상품군(`goodsGroup`) 아래 전시분류 대분류(`dispCategoryName`의 ` > ` 앞부분). 두 단계를 각각 독립적으로 다중 선택한다 — 상품군만 고르면 그 안 전체, 대분류만 고르면 상품군을 가로질러 선택 |
| 상품태그 | `hashtags` 다중 선택. 하나라도 걸리면 포함(OR) |
| 결과 내 재검색 | 도서명·부제 부분 일치 |

```
분야
  국내도서            32
     컴퓨터/모바일     15
     과학              3
     경제경영          3
     …
  eBook                3
     컴퓨터/모바일      2
     자기계발           1
```

**분야가 가장 강력하다.** 오탐이 분야로 뭉치기 때문이다 — 인공관절은 의학, 인공위성은
공학, 인공 낙원은 소설. 목업 `인공지능` 35종에서 분야 `의학`만 고르면 2종이 남는데 그
2종이 모두 AI 판정 제외 대상이다(집계 대상 0종). 오탐과 분야가 거의 일치한다는 뜻이다.
AI 호출보다 싸고 빠르며 기자에게 설명하기도 쉽다.

**태그만으로 모수를 잡으면 안 된다.** `tag_monitoring` POC 실측에서 메인 업데이트 도서
33종 중 15종(45%)이 미태깅이었다. 태그 기준만 쓰면 절반을 놓친다. 분야로 모수를 잡고
태그는 보조 근거·AI 판정 입력으로 쓴다.

**패싯 카운트는 검색 결과 전건 기준으로 고정한다.** 선택할 때마다 카운트가 바뀌면 무엇을
고를지 판단할 수 없다 (YES24 검색 좌측과 같은 방식).

**선택한 조건은 산출 조건에 반드시 기록한다.** 조건이 곧 "이 키워드 시장의 정의"이므로,
기록이 없으면 그 숫자를 재현할 수 없다. 산출 조건의 `대상` 항목은 선택한 상품군을 따른다
(미선택이면 `전체`).

### 5.2 아직 넣지 않은 것 — 실서비스 전 필요

| 항목 | 내용 |
|---|---|
| **검수 결과 영구화** | 지금은 검색할 때마다 `overrides`가 초기화된다. `(키워드, 상품번호) → 판정`을 서버에 저장하면 검수가 일회성 비용이 아니라 누적 자산이 된다. 두 번째 조회부터는 신규 상품만 보면 된다. **실서비스 성패를 가르는 항목** |
| **조건 프리셋 저장** | 분야·태그 조합이 매번 달라지면 분기 비교가 깨진다. 조합을 저장해 다음 조회에 그대로 불러 쓴다 |
| **검수 큐** | `신뢰도 < 0.85 AND 누적 판매량 상위 95% 구간`만 검수 대상으로 제시. 나머지는 판정대로 확정하고 `미검수 N건 = 합계의 0.8%`로 오차 범위를 명시 |
| **영향도 표시** | 행마다 `제외 시 합계 −3.2%`. 목업 26종에서도 상위 5종이 51.6%, 하위 5종은 다 합쳐 1.98%다. 무엇부터 볼지가 자명해진다 |
| **일괄 처리** | 다중 선택 + 분야 단위 일괄 제외 |

## 6. 엑셀 다운로드

`assets/js/xlsx.js` — 외부 라이브러리 없는 XLSX 생성기(`downloadXlsx`), `ebook_solo_pub`에서
가져와 다중 시트를 지원하도록 확장했다. **버튼 1개, 시트 2개**다.

**대외 제공용 / 내부 확인용** 두 모드가 있다.
파일명은 `키워드판매_{모드}_{키워드}_{시작}-{종료}.xlsx`.

| 시트 | 내용 |
|---|---|
| `상품별 집계` | **목록만.** 1행이 헤더, 2행부터 데이터 |
| `산출 조건` | `항목 / 내용` 2열 표 |

공통 컬럼:

```
순위 | 상품번호 | 도서명 | 부제 | 해시태그 | 저자 | 출판사 | 출간일 | 정가 | 판매가 |
판매량 | 매출액 | ISBN13 | {전년 동기|직전 동기간} 판매량 | 증감률(%) | 점유율(%)
```

내부 확인용만 추가로 갖는 컬럼:

```
전시분류명 | 판매상태 | AI판정 | 신뢰도 | 판정근거
```

- **대외 제공용은 집계에 포함된 상품만** 내보낸다. 어떤 책을 왜 뺐는지는 내부 판단이라
  기자에게 나가면 안 된다. 내부 확인용은 제외 항목까지 포함해 판정을 검증할 수 있게 한다.
- 공급률·제조사·공급사·전시분류코드는 **어느 모드에도 넣지 않는다** (사내 정보).
- 현재 페이지가 아니라 **전건**을 내보낸다.

**산출 조건은 별도 시트에 둔다.** 표 위에 주석이 섞여 있으면 정렬·필터·복사할 때마다
걸리기 때문이다. 화면 상단 요약과 같은 내용을 항목별로 편다:

```
키워드              필사
조회 기간            2026-01-01 ~ 2026-09-07
집계 단위            월 단위
대상                국내도서
검색 결과            15종
상세 조건            태그 #필사
상세 조건 적용 후     8종
AI 관련성 필터       적용
AI 판정 제외         6종
담당자 수동 조정      0건
집계 대상            9종
비교 구간            2025-01-01 ~ 2025-09-07 (전년 동기)
매출 기준            판매량 × 판매가
정렬 기준            판매량
내보내기 범위         대외 제공용 — 집계에 포함된 상품만
추출 일시            2026-09-07 16:31
```

숫자 컬럼은 문자열이 아닌 number로 넣어 엑셀에서 바로 합계·정렬이 되게 한다.
헤더 볼드 + 틀 고정 + 자동필터는 `xlsx.js`가 이미 적용한다.

### 넣지 않기로 한 것 (검토 후 제외)

다시 검토하지 않도록 판단 근거를 남긴다.

**상품 × 기간 교차표** — 상품 수명이 조회 기간보다 짧다. 목업 56종의 출간일이 1년 구간에
몰려 있어 10년(120개월) 창에 넣으면 전체 6,720셀 중 출간 이후 셀이 245개(3.6%)뿐이고
나머지 96.4%가 구조적으로 0이 된다. 실데이터에서도 도서 수명은 보통 1~3년이라 같다.
스파크라인·멀티라인도 같은 이유로 제외했다.

**기간별 추이 차트** — 언론 제공에 쓰이지 않아 제거했다. 조회 기간에 따라 묻는 질문이
다른데, 어느 쪽도 차트를 필요로 하지 않았다:

| 기간 | 실제 질문 | 답하는 것 |
|---|---|---|
| 30~90일 | 지금 뭐가 잘 나가나 | 표(순위·판매량) |
| 1~10년 | 이 키워드 시장이 커졌나 줄었나 | KPI(전년 대비 증감률) |

덧붙여 장기 조회에서 차트는 물리적으로 못 읽는다 — 10년을 일 단위로 그리면 셀 폭 0.3px에
막대 폭 2px라 막대가 서로 겹쳐 검은 띠가 된다(월 단위 121개만 정상). 필요해지면 월·연
단위 전용으로 되살리되, 일 단위에는 기간 상한을 걸어야 한다.

**순위 변동(▲▼)** — MD의 일상 모니터링용이고 언론 제공에는 쓰이지 않는다. 장기 조회에서는
대부분 `NEW`로 나와 노이즈만 된다. 대신 `증감률`(비교 구간 대비)을 넣었다.

## 7. POC 목업의 범위

| 항목 | 상태 |
|---|---|
| 검색 API | 목업 — `assets/js/data.js`에 키워드 4종(`인공지능` 35(eBook 3) / `필사` 17(eBook 2) / `클로드` 8 / `파이썬` 8). 전년 동기 비교가 성립하도록 2023~2024년 출간 백리스트를, 분야 트리가 성립하도록 eBook 판을 포함 |
| AI 관련성 판정 | 목업 — 판정·신뢰도·근거를 상품별로 하드코딩, 800ms 지연 + localStorage 캐시 |
| 판매 데이터 | 목업 — 상품번호를 시드로 하는 결정론적 PRNG (새로고침해도 같은 값) |
| 화면·집계·엑셀 | **실제 동작** |

목업 판매량 = `기저량 × 요일계수 × 신간감쇠 × 노이즈`, 기저량은 상품별 28~448(롱테일 분포),
생성 범위는 2026-09-07 기준 최근 1,300일(약 3.5년). 출간일 이전은 0.

목업에 없는 키워드를 입력하면 `SEARCH_001` 안내를 띄운다.

```
keyword_sales/
  index.html              앱 셸 + 마크업
  assets/css/style.css    ax-labs-platform style-base.css + 페이지 전용 .ks-* 클래스
  assets/fonts/paperlogy/ Paperlogy woff2 9종 (로컬 서빙)

  assets/js/app.js        목업 API · 집계 · 렌더 · 엑셀
  assets/js/xlsx.js       XLSX 생성기 (ebook_solo_pub에서 복사 후 다중 시트 지원 추가)
```

`xlsx.js`는 원본이 시트 1개만 지원해서 **다중 시트를 지원하도록 확장**했다.
`downloadXlsx(파일명, [시트1, 시트2])` 형태로 배열을 넘기면 되고, 시트별로
`{ name, cols, header, rows, filter }`를 갖는다(`filter: false` 면 자동필터 생략).
단일 객체를 넘기던 기존 호출 방식도 그대로 동작한다.

UI는 `.claude/skills/apply-ax-labs-ui` 기준 — vercel 테마(primary 니어블랙), 색은 토큰
변수만 사용하고 하드코딩 hex를 쓰지 않는다.

실행: `node serve.js` 후 `http://localhost:8942/keyword_sales/`
