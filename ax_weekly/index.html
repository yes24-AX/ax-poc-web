Metric Catalog

전사 지표 정의 사전 — 모든 대시보드 숫자는 여기 정의된 기준으로만 집계됩니다. "이 숫자가 왜 우리 엑셀과 다르죠?"를 없애는 장치

—
Metric Catalog는 무엇인가
  • 전사 지표 정의의 단일 원천 — "매출"이라는 같은 단어를 팀마다 다른 기준(결제일/주문일, 취소 포함/제외)으로 쓰는 문제를 없앱니다. 모든 대시보드·AI 요약은 여기 정의된 기준으로만 집계합니다.
  • 숫자 분쟁 차단 장치 — "이 숫자가 왜 우리 엑셀과 다르죠?"가 나오면, 화면의 MetricId를 눌러 집계 기준·제외 조건·기준일을 바로 확인합니다. 기준이 다르면 어느 쪽이 공식인지가 명확해집니다.
  • AI 신뢰의 기반 — AI 요약과 대화형 검색은 DB에 임의 SQL을 날리지 않고 Metric Catalog → Semantic Query 경로로만 숫자를 가져옵니다. AI가 숫자를 "계산"하지 않고 "인용"하게 만드는 장치입니다.
어떻게 동작하나
1
지표 정의 등록
지표명, 원천 시스템, 집계 기준(예: 결제일), 제외 조건(예: 취소/환불), 갱신 주기, Owner를 등록합니다.
2
Owner 승인 · 버전 관리
정의 변경은 Owner 승인을 거치며 버전 이력이 남습니다. 과거 주간보고는 당시 버전 기준으로 보존됩니다.
3
수집 배치가 정의대로 집계
Weekly Snapshot 배치가 카탈로그 정의를 읽어 자동 집계합니다. 정의에 없는 수기 숫자는 대시보드에 들어갈 수 없습니다.
4
모든 화면·AI가 MetricId 참조
주간보고·매출 조회·경영진 대시보드·AI 요약이 같은 MetricId를 인용합니다. 화면 하단에 출처와 기준일이 표기됩니다.
이럴 때 이렇게 쓰세요
  • 숫자가 내 엑셀과 다를 때 — 지표 사전에서 해당 지표를 검색해 집계 기준·제외 조건을 확인하세요. 대부분 취소/환불 포함 여부나 기준일(결제일 vs 주문일) 차이입니다.
  • 새 지표가 필요할 때 — 팀 자체 엑셀로 관리하지 말고 지표 등록을 요청하세요. 등록되면 자동 수집 대상이 되고 전사가 같은 숫자를 봅니다.
  • 과거 숫자가 바뀐 것 같을 때 — 주간보고는 Snapshot으로 고정되므로 "그때 보고된 값"은 변하지 않습니다. 현재 값과 다르면 환불·정산 보정이 이후에 반영된 것입니다.
운영 규칙
  • 지표 정의 변경은 Owner 승인 + 버전 이력 필수 — 소급 적용하지 않습니다
  • 모든 화면 숫자에 MetricId·데이터 기준일·원천 시스템이 표기됩니다
  • 수집 실패·지연 시 "수집 지연"으로 표기하며 빈칸이나 추정치로 대체하지 않습니다
  • 코드 마스터(조직·담당자·상태·분류)와 미매칭인 데이터는 적재 시 반려됩니다

지표 정의 변경은 Owner 승인 + 버전 이력 관리 · 대시보드의 모든 숫자에는 MetricId와 기준일이 표기됩니다
