# DataHub Interactive Onboarding — Find the Answer

사내 직원이 캠페인, 독자 반응, 상품, 주문, 매출 등 흩어진 데이터를 연결해 매출 변화의 원인을 스스로 발견하는 클릭·드래그 기반 인터랙티브 온보딩입니다.

## Story

사용자는 `이번 달 매출은 왜 달라졌을까?`라는 질문으로 시작합니다. 질문을 둘러싼 5가지 근거 데이터를 모으고, 그 데이터를 "관심 → 반응 → 상품 → 구매 → 결과"라는 업무 흐름 순서로 연결하고, 개인 추출 파일과 회사 공식 지표 중 신뢰할 기준을 선택합니다. 연결된 데이터가 패턴(어떤 지표가 오르고 내렸는지)을 보여주고, 이 패턴이 회사 전체의 다양한 데이터 도메인과 어떻게 이어지는지 확인한 뒤, 마지막에는 전체 과정이 DataHub Interface로 변형되며 답이 완성됩니다.

## Journey (7 scenes)

`js/SceneManager.js`의 `titles` 배열과 1:1로 대응합니다.

1. **QUESTION** — 중앙의 `WHY?` 신호를 클릭해 "이번 달 매출은 왜 달라졌을까?"라는 질문을 활성화합니다.
2. **SOURCES** — 캠페인 반응 · 독자 반응 · 상품·콘텐츠 · 주문·배송 · 매출 성과, 5개의 근거 데이터 토큰을 질문에 모읍니다.
3. **CONNECT** — 빛나는 데이터 카드를 `캠페인 → 독자 → 상품 → 주문 → 매출`(업무 언어로는 `관심 → 반응 → 상품 → 구매 → 결과`) 순서로 선택해 연결합니다. 기술적인 연결(Column Key 등)은 DataHub가 자동으로 처리한다는 전제입니다.
4. **STANDARD** — 개인 추출 파일(`매출_최종__v2.xlsx`)과 회사 공식 매출 지표를 담당자·업데이트 시각·산정 기준 기준으로 비교해, 보고와 의사결정에 사용할 기준을 선택합니다.
5. **PATTERN** — 연결된 데이터에서 관심·독자 반응은 늘었지만 구매 전환·출고 가능성은 줄고 품절 상품 조회는 늘었다는 패턴을 발견합니다.
6. **LANDSCAPE** — 마케팅 · 크레마클럽 · 사락 · B2X · 클릭스트림 · PD · 동네책방, 회사 전체의 7개 데이터 도메인을 하나의 질문 아래로 드래그해 근거를 완성합니다.
7. **DATAHUB** — 완성된 근거가 하나의 KEY FINDING("유입은 증가했지만, 상품 가용성 하락으로 구매 전환율이 감소했습니다")으로 정리되고, DataHub Interface로 이어집니다.

## Business-friendly connection

일반 사업부 사용자가 테이블명이나 Column Key를 몰라도 이해할 수 있도록 데이터의 역할을 업무 언어로 표현합니다. (2단계 SOURCES 토큰 및 3단계 CONNECT 카드 순서 기준)

- 캠페인 — 무엇이 관심을 만들었을까 (관심의 시작)
- 독자 — 누가, 어떻게 반응했을까
- 상품·콘텐츠 — 무엇을 보고 있었을까
- 주문·배송 — 무엇이 구매로 이어졌을까
- 매출 — 성과는 어떻게 달라졌을까

모든 단계는 오른쪽 상단 가이드의 `SKIP THIS STEP`으로 건너뛸 수 있습니다. Skip을 눌러도 해당 단계의 수집, 연결, 선택, 분석 애니메이션을 실제로 재생한 후 다음 단계가 열립니다 (`SceneManager.skip()` 참고).
