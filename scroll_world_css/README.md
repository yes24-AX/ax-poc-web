# AX LABS — Cinematic World (CSS 3D / WebGL 미사용)

카메라가 **하나의 긴 3D 공간**을 자동으로 여행하며 AX LABS를 소개하는 페이지입니다.
페이지를 열면 약 **31초짜리 시네마틱**이 스스로 재생됩니다. 스크롤은 사용하지 않습니다.

| 조작 | 동작 |
|---|---|
| 하단 재생 버튼 / `Space` | 일시정지 · 재생 (끝나면 다시 보기) |
| 하단 `1×` 버튼 / `[` `]` | **재생 시간 조절** — 0.5×(1분 2초) ~ 2×(16초) |
| 우측 챕터 점 클릭 | 해당 씬으로 이동 |
| `←` `→` | 이전 · 다음 씬 |
| 상단 진행바 클릭 | 원하는 지점으로 탐색 |

재생 시간 메뉴는 배속과 함께 **실제 총 길이**를 같이 보여주고, 고른 값은 브라우저에 저장되어
다음에 열 때도 유지됩니다. 선택지는 `journey.js`의 `RATES` 배열에서 바꿀 수 있습니다.

## 왜 WebGL을 안 쓰나

WebGL은 브라우저에서 GPU 가속이 꺼져 있으면(원격 데스크톱, 하드웨어 가속 비활성, 드라이버 차단)
아예 컨텍스트 생성에 실패합니다. 이 페이지는 다음 조합만 사용하므로 그런 환경에서도 항상 렌더링됩니다.

| 역할 | 기술 |
|---|---|
| 3D 공간·카메라 | **CSS 3D Transform** (`perspective` + `preserve-3d`) |
| 볼륨 있는 오브젝트 | **6면 CSS 박스** (면별 명도차로 광원 표현) |
| 공기 원근·컬링 | **자체 뎁스 포그** (카메라 거리 기반, JS) |
| 별·성운·워프 | **Canvas 2D** |
| 시간 → 카메라/색 | **GSAP 타임라인** (자동 재생) |
| 오브젝트 상시 동작 | **CSS keyframes** (브라우저 네이티브) |

## 핵심 원리

### 0. 완급 있는 자동 재생

진행도를 시간에 대해 일정하게 흘리면 관광버스처럼 밋밋해집니다. `journey.js`는 타임라인을
두 겹으로 나눠, 씬으로 **이동**할 때는 빠르게, 씬에 **머무를** 때는 아주 느리게 흐르게 합니다.

```
master : 길이 1짜리 "진행도 공간" 타임라인 (position === 진행도)
         캡션·환경색이 여기에 매달려 있다
auto   : 실제 재생 헤드. 시간에 따라 head.p를 움직이고
         매 프레임 master.progress(head.p)로 반영한다
```

`SCENES` 배열이 씬마다 `[진입 이동 시간] + [머무는 시간]`을 정의하며,
머무는 구간은 캡션이 떠 있는 진행도 범위와 맞춰져 있습니다.
그 결과 이동 구간은 초당 진행도 0.05~0.07, 머무는 구간은 0.023~0.035로 약 **2.8배**의 리듬 차이가 납니다.
배경 별도 이 속도차를 읽어 이동 중에만 속도선으로 늘어납니다.

### 1. CSS로 만드는 카메라

CSS에는 카메라가 없으므로, 뷰포트에 `perspective`를 걸고 **월드 전체에 카메라의 역변환**을 겁니다.

```js
// 카메라가 (x, y, z)에서 ry/rx로 회전해 있다면
world.style.transform =
  `rotateX(${-rx}deg) rotateY(${-ry}deg) translate3d(${-x}px, ${-y}px, ${-z}px)`;
```

`camera.js`의 웨이포인트 21개를 진행도에 따라 smoothstep 보간하므로 **섹션 점프 없이** 연속 이동합니다.

### 2. 뎁스 포그 = 공기 원근 + 컬링 (품질을 가장 크게 좌우)

CSS 3D는 아무리 멀어도 또렷하게 보이고, 카메라 뒤로 넘어간 요소가 뒤집혀 보여 "가짜 3D" 티가 납니다.
`fog.js`가 매 프레임 각 오브젝트의 카메라 기준 깊이를 계산해 투명도를 조절합니다.

```
depth = cameraZ - objectZ        // 양수 = 카메라 앞
 · depth < 40          → 사라짐 (통과 완료, 뒤집힘 방지)
 · 40 ~ 340            → 서서히 사라짐 (스쳐 지나가는 느낌)
 · 340 ~ 2100          → 완전 불투명
 · 2100 ~ 3400         → 서서히 나타남 (멀리서 다가오는 느낌)
```

투명도 0인 요소는 `visibility: hidden`이 되어 **렌더링에서 제외**됩니다.
덕분에 월드 전체 521개 요소 중 화면에 실제로 그려지는 것은 **항상 7~46개**뿐입니다.
포그가 곧 컬링이라 GPU 가속 없는 환경에서도 가볍습니다.

### 3. 진짜 입체 박스

평면을 세워 두면 카메라가 움직일 때 종이처럼 보입니다. 서버 타워·화물·팔레트는 6면 박스로 만들고,
면마다 배경 오버레이로 명도를 달리해 위쪽 광원을 표현합니다.

```css
.box > .top   { background: linear-gradient(rgba(255,255,255,.2), …), var(--face); } /* 밝게 */
.box > .left  { background: linear-gradient(rgba(0,0,0,.3), …), var(--face); }       /* 어둡게 */
```

> `filter: brightness()`가 아니라 배경 오버레이를 쓰는 이유: `filter`는 `preserve-3d` 레이어를
> 평탄화시켜 3D 정렬이 깨집니다.

### 4. 공전 라벨의 빌보드 처리

피벗(rotateY 무한 회전) → 팔(반지름 이동) → **역회전 컨테이너**(같은 duration의 `reverse`) → 라벨.
역회전이 피벗 회전을 정확히 상쇄해 라벨이 항상 정면을 봅니다.

## 실행 방법

ES Module을 쓰므로 로컬 서버가 필요합니다 (`file://` 불가).

```bash
npx serve .
```

```bash
python -m http.server 8080
```

접속: `http://localhost:포트/scroll_world_css/` (레포 루트에서 실행 시).
VSCode **Live Server**로 `index.html`을 열어도 됩니다.

> GSAP과 Pretendard 폰트만 CDN에서 받습니다. Three.js는 사용하지 않습니다.

## 코드 구조

```
scroll_world_css/
├── index.html          # 마크업 — 내비 / 챕터 인디케이터 / 캡션 / 피날레 / 재생 컨트롤
├── styles/
│   └── main.css        # 3D 스테이지, 6면 박스, 씬 오브젝트, 상시 애니메이션, UI
├── src/
│   ├── main.js         # 엔트리 — 월드 구축, GSAP ticker 렌더 루프
│   ├── scenes.js       # 월드 빌더 (place/box 헬퍼로 좌표 배치 + 포그 등록)
│   ├── camera.js       # 웨이포인트 보간 → #world 역변환
│   ├── fog.js          # 카메라 거리 기반 뎁스 포그 + 컬링
│   ├── particles.js    # Canvas 2D 별/성운/워프
│   └── journey.js      # 자동 재생 타임라인, 환경 키프레임, 캡션, 재생 컨트롤
└── README.md
```

렌더 루프는 GSAP ticker에 얹혀 있습니다. 재생 타임라인이 이미 돌리는 프레임 루프를 재사용하므로
rAF 루프가 하나로 줄고, 진행도와 카메라가 같은 프레임에 갱신되어 어긋나지 않습니다.
루프가 하는 일은 **카메라 역변환 · 포그 갱신 · 별 그리기** 셋뿐이고,
공전·컨베이어·기어 같은 상시 동작은 전부 CSS 키프레임이 처리합니다.
탭이 가려지면 재생을 멈춰, 돌아왔을 때 여정이 훌쩍 지나가 있지 않게 했습니다.

## 커스터마이징

| 하고 싶은 것 | 위치 |
|---|---|
| 재생 길이·씬별 완급 | `journey.js` → `SCENES` (in / inDur / out / outDur) |
| 카메라 동선 | `camera.js` → `KEYFRAMES` (p / x / y / z / ry / rx) |
| 씬 색·분위기 | `journey.js` → `ENV` (bg / tint / accent / fg) |
| 캡션 타이밍 | `journey.js`의 master 타임라인 position(0~1) |
| 포그 거리감 | `fog.js` → `DEFAULTS` (nearOut / nearIn / farIn / farOut) |
| 존 위치 | `scenes.js` → `ZONE`, `MARKS` (카메라 웨이포인트도 함께 조정) |
| 오브젝트 밀도 | `scenes.js` 각 빌더의 count |
| 화각 | `main.css` → `#viewport { perspective }` (작을수록 광각) |

원근 때문에 **월드 좌표 크기 ≠ 화면 크기**입니다. 화면에 보이는 크기는 대략
`화면크기 = 월드크기 × perspective / (perspective + depth)` 이므로,
멀리 둘 오브젝트일수록 크게 잡아야 합니다. (히어로 워드마크 420px, 챕터 타이포 260px인 이유)

## 최적화

- **포그 컬링**: 521개 중 매 프레임 7~46개만 렌더링
- **JS 프레임 비용 0.31ms** (60fps 예산 16.67ms의 2%)
- **blur 필터 0개**: 소프트웨어 렌더링에서 비싼 blur 대신 그라데이션·box-shadow로 광원 표현
- **스타일 쓰기 최소화**: 포그는 변화량 0.015 미만이면 건너뛰고, 카메라 transform은 값이 바뀔 때만 적용
- **Canvas DPR 1 고정**, 별 110~220개
- **모바일 등급 분기**: 오브젝트 수 축소, 스크롤 길이 640vh, 화각 조정
- **`prefers-reduced-motion`** 지원

## 같은 폴더의 다른 버전

`../scroll_world/`는 동일한 여정의 **Three.js(WebGL)** 버전입니다.
GPU 가속이 되는 환경에서는 실제 라이팅과 UnrealBloom을 써서 더 화려하지만,
가속이 꺼져 있으면 동작하지 않습니다. 이 CSS 버전이 호환성 측면의 기본값입니다.
