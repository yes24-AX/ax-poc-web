# DataHub Onboarding V16 — DATA DARKROOM

## 프로젝트 목적

V16은 YES24 임직원이 DataHub에 진입하기 전에 경험하는 직접 조작형 온보딩 프로토타입이다.

DataHub의 메뉴나 기능을 순서대로 설명하는 튜토리얼이 아니다. 어두운 현상실에서 필름에 빛을 비추고, 초점을 바꾸고, 인화하는 과정을 통해 다음 메시지를 체험하게 한다.

> 같은 데이터도 업무의 질문과 관점에 따라 다르게 보인다.  
> DataHub는 필요한 데이터를 필요한 관점에서 탐색하는 출발점이다.

실제 DataHub가 모든 데이터를 자동으로 통합하거나 연결하고, 정답을 만들어준다고 표현하지 않는다. V16의 핵심은 **데이터의 수집이나 통합이 아니라 관점의 선택과 탐색**이다.

## 핵심 컨셉 — DATA DARKROOM

업무 데이터는 처음부터 완성된 화면으로 주어지지 않는다. 현상되지 않은 필름처럼 어둠 속에 여러 형태로 존재하고, 질문에 맞는 빛과 초점이 주어질 때 필요한 모습이 드러난다.

현상실의 물성을 데이터 탐색 과정에 대응시킨다.

- **어둠**: 아직 질문과 관점이 정해지지 않은 데이터 환경
- **빛**: 지금 답하려는 업무 질문과 주목 범위
- **필름**: 서로 다른 업무에서 바라보는 데이터 표면
- **초점**: 상품·콘텐츠·판매·주문 중 어떤 관점으로 볼 것인지 선택하는 행위
- **인화지**: 선택한 관점을 한 화면에서 비교하고 확인하는 단계
- **현상**: 데이터가 정답으로 변하는 것이 아니라, 탐색할 관점이 선명해지는 과정
- **DataHub 화면**: 필요한 데이터를 필요한 관점에서 살펴보는 실제 경험으로의 진입

## 전체 시나리오

사용자는 어두운 공간에서 하나의 질문과 마주한다.

**“최근 주목받는 책은 무엇일까?”**

빛을 직접 움직이면 상품 필름이 드러난다. 필름을 노출 위치에 놓으면 상품의 판매 상태와 재고, 최근 판매 정보가 보이기 시작한다. 하지만 하나의 필름만으로는 질문을 충분히 바라볼 수 없다.

사용자는 초점 다이얼을 돌려 콘텐츠의 노출, 판매의 흐름, 주문의 상태라는 서로 다른 업무 관점을 차례로 살펴본다. 같은 온라인서점 안에서도 업무가 달라지면 주목하는 데이터가 달라진다는 사실을 발견한다.

이후 선택된 관점은 인화지 위에 함께 놓인다. 사용자가 인화지를 끌어 올리고 현상하면 흩어져 있던 관점이 하나의 탐색 가능한 장면으로 정돈된다. 마지막에는 실제 DataHub 화면이 나타나며 온보딩이 종료된다.

## 장면별 소개

### 00 / QUESTION — Illuminate

어두운 현상실과 하나의 업무 질문으로 시작한다.

- 사용자는 빛을 직접 움직여야 한다.
- 처음부터 데이터를 설명하지 않고, 어둠 속에 무언가 존재한다는 감각을 먼저 만든다.
- 빛은 정답을 비추는 장치가 아니라 질문의 범위를 정하는 장치다.

핵심 경험:

> 질문이 생기면 바라볼 데이터의 범위가 생긴다.

### 01 / EXPOSURE — Expose

빛 아래 상품 필름을 놓아 첫 번째 데이터 표면을 노출한다.

- 필름에는 **상품의 상태**가 나타난다.
- 판매 상태, 재고, 최근 판매처럼 상품 운영에서 확인하는 정보가 보인다.
- 사용자는 필름을 드래그하거나 직접 조작해 노출 위치를 맞춘다.

핵심 경험:

> 데이터는 질문의 빛이 닿을 때 비로소 읽을 수 있는 모습이 된다.

### 02 / FOCUS — Refocus

초점 다이얼을 움직이며 서로 다른 업무 필름을 차례로 확인한다.

관점은 다음과 같이 구성된다.

- **상품의 상태**: 판매 상태·재고·판매 현황
- **콘텐츠의 노출**: 노출 위치·노출 상태·대상 도서
- **판매의 흐름**: 기간·판매량·변화
- **주문의 상태**: 주문 수량·처리 상태·출고 흐름

각 필름은 같은 정보를 반복하지 않는다. 업무에 따라 질문과 읽는 데이터가 달라진다는 차이를 보여준다. `주문의 상태`에는 처리 흐름을 암시하는 그래프를 사용하되 실제 프로세스나 실시간 상태를 단정하지 않는다.

핵심 경험:

> 초점이 달라지면 보이는 데이터도 달라진다.

### 03 / CONTACT — Compare

앞에서 확인한 관점이 인화지 위에 함께 놓인다.

- 상품·콘텐츠·판매 데이터가 하나의 Contact Sheet로 나타난다.
- 사용자는 인화지를 위로 끌어 올려 장면을 전개한다.
- 이 단계는 데이터가 자동으로 합쳐지는 표현이 아니라, 서로 다른 관점을 나란히 비교하는 표현이다.
- 인화지가 올라오면 앞 단계의 빛과 그림자는 사라지고 인화지의 정보에 시선이 집중된다.

핵심 경험:

> 한 가지 질문도 여러 업무 관점에서 살펴볼 수 있다.

### 04 / DEVELOP — Develop

인화지를 누르거나 일정 시간 길게 눌러 관점을 현상한다.

- 선택된 정보가 점진적으로 선명해진다.
- 현상 과정은 새로운 데이터를 만들거나 정답을 생성하는 표현이 아니다.
- 질문에 필요한 관점이 정돈되고 탐색할 준비가 되는 과정이다.
- 충분한 전환 시간을 둔 뒤 실제 DataHub 화면으로 이어진다.

핵심 경험:

> 질문에 필요한 관점이 서서히 선명해진다.

### FINAL / DATAHUB — Developed View

현상된 화면이 실제 DataHub 화면으로 전환된다.

최종 메시지:

> 필요한 데이터가,  
> 필요한 관점에서 선명해집니다.

- 실제 화면 이미지는 `concept/datahub_main.png`를 사용한다.
- `DataHub 시작하기`는 `https://ax-datahub.yes24.com`으로 연결한다.
- 사용자는 전체 여정을 다시 실행할 수 있다.

## 직접 조작 원칙

V16은 스크롤형 페이지가 아니라 사용자가 장면을 직접 움직이는 경험이다.

- 빛을 이동한다.
- 상품 필름을 노출 위치로 옮긴다.
- 초점 다이얼을 조작한다.
- 인화지를 위로 끌어 올린다.
- 인화지를 눌러 현상한다.
- 클릭과 드래그가 어려운 사용자를 위해 대체 조작을 제공한다.
- `PLAY THE JOURNEY`는 직접 조작 없이 전체 흐름을 확인하는 자동 재생 수단이다.

조작은 게임 자체가 목적이 아니다. 사용자의 행위와 데이터 관점의 변화가 직접 대응되어야 한다. 조작 난도가 메시지 이해를 방해해서는 안 된다.

## 시각 디자인 원칙

- 어두운 현상실, 빛, 유리, 필름, 인화지의 물성을 유지한다.
- 메인 장면은 절제된 산세리프를 사용한다.
- 필름과 인화지의 주요 한글 제목·수치는 `Noto Serif KR`을 사용해 인쇄물의 우아함을 더한다.
- 영문 코드와 작은 메타데이터는 `DM Mono`를 유지해 데이터 구조를 구분한다.
- 청록색은 선택·초점·데이터 관점을, 금색은 현상과 결정적인 강조를 나타낸다.
- 발광 효과는 빛의 물성을 설명할 때만 사용하며 HUD나 SF 인터페이스처럼 만들지 않는다.
- 작은 글씨가 분위기를 위해 읽히지 않는 상태가 되지 않도록 한다.
- 장면마다 조작과 대표 시각 문법을 하나씩 둔다.

## 금지 사항

- 사용자 ID, 세션 또는 특정 개인의 행동 추적
- 하나의 상품이 모든 업무를 관통하는 단일 여정
- 데이터가 중앙으로 빨려 들어가는 표현
- 다수의 연결선, 노드 그래프, Light Trail
- 근거 없는 KPI, 추천, 예측 또는 실시간 처리 표현
- DataHub가 모든 데이터를 자동으로 통합·연결한다고 단정하는 표현
- DataHub가 질문의 정답을 자동으로 생성한다고 오해할 수 있는 표현
- 실제 지원 여부가 확인되지 않은 제품 기능을 UI에 구체화하는 것
