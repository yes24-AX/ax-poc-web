## 확인된 결함과 조치

### 1. 마지막 6개 입구 중 5개가 존재하지 않는 메뉴였다 — 최대 결함

실무자가 주소를 직접 눌러 404를 확인했고, 검증 결과 사실이었다.

| 화면의 입구 | 응답 |
|---|---|
| `/MarketingMetrics` · `/CremaClubSalesReport` · `/B2X/B2BOrderList` · `/BookShop/Dashboard` · `/Clickstream/Keywords` | **404** |
| `/BookclubStats` | 200 |

운영의 메뉴 관리 화면(`/Menu`)을 직접 받아 등록된 메뉴 전체를 확인했다.
없는 다섯은 저장소 `demo_sitemap` 의 **계획/로드맵**을 실존 메뉴로 착각해
옮겨 온 것이었다. 실제 등록 메뉴는 다음이 전부다.

```
공유        공지사항            /Notice          200
sarak      독서모임 통계        /BookclubStats   200
           리뷰·한줄평 급상승   /ReviewSurge     200
정산 관리   미수금 모니터링      /ArRisk          권한 필요
MD 업무     상품 브리핑         /MdBriefing      권한 필요
어드민 도구  사용 가이드 외 8    /Guide           200
```

**조치** — 여섯 칸을 실존 메뉴로 전부 교체. 실무자 제안대로 `상품 브리핑`을
첫 칸에 두었고(MD 직무 이름이 붙은 유일한 메뉴), 권한이 필요한 둘은
카드에 `권한 필요`를 적었다. 온보딩이면 `사용 가이드`가 자연스러워 마지막 칸에 넣었다.

> **미해결 확인 사항** — `MIS`는 이 티저에서만 주장하는 이름이다.
> 나머지 9개 프로그램은 근거가 있는데 이것만 없다. 담당자 확인이 필요하다.

### 2. 실캡처 5장이 원본 그대로 배포되고 있었다 — 보안

임원이 파일을 직접 열어 잡아냈다. 어둡게 만든 건 CSS뿐이라
**주소만 알면 누구나 원본을 본다.** 노출되던 것:

- `mon.jpg` — 내부 서버명, 내부 API 경로, 필드 구성 (가장 위험)
- `ops.jpg` — 가용재고·판매가능재고·발주대상 실수치
- `ana.jpg` — 물류센터별 실재고 수량

개인정보는 5장 어디에도 없었고 `beh.jpg`에는 마스킹이 이미 적용돼 있었다.
노출되던 건 **내부 운영 수치와 시스템 구조**다.

**조치** — 파일 자체에 블러를 구워 넣었다(축소→확대). 글자·숫자는 판독 불가가 되고
UI 구조와 색만 남는다. 더 이상 가릴 것이 없으므로 화면 표현은 오히려 밝혔다
(`opacity .62→.72`, `brightness .3→.42`) — 임원이 지적한 "안 보이게 가려놓고
원본은 다 내주는 가장 나쁜 조합"이 뒤집혔다.

> **대외 시연 시 주의** — 6개 입구가 운영 주소로 직결된다. 사내에서는 최대 강점이지만
> 외부인 앞에서 카드를 누르면 사내 시스템이 열린다. 발표자에게 명시하거나
> 대외용 빌드에서는 링크를 비활성화할 것.

### 3. 1280~1440에서 카드가 헤드라인을 양쪽에서 덮었다

임원·실무자·기획자 셋이 각각 독립적으로 잡았다. `시스템 모니터링`이
`니스템 모니터리`로 보이는 상태였다. **노트북 미러링이 정확히 이 폭이다.**

원인은 카드를 화면 폭의 비율(`fx*W`)로 흩뿌리는데 카드 폭(316px)과
중앙 활자(116px)는 고정이라, 폭이 줄면 가운데 여유만 줄어든 것이었다.

**조치** — 카드를 화면 끝(여백 24px)까지 밀어내고, 카드 사이에 실제로 남은
폭(`--card-clear`)에서 활자 상한(`--slot-max`)을 계산해 CSS로 넘긴다.
1920은 지금 모습 그대로고 그 아래에서만 활자가 따라 내려간다.
마찰 장의 헤드라인과 본문에도 같은 여유를 적용했다.

### 4. 연출이 조용히 정적 문서로 내려앉는 두 경로

임원 지적. 둘 다 회의실에서 실제로 일어나며 **발표자는 모른 채 시연을 시작한다.**

**조치** — GSAP을 `assets/`에 동봉해 오프라인·사내망 차단에서도 돌게 했고,
축소 모션이면 이유를 띄우고 `그래도 재생` 버튼을 준다. 정적 폴백 자체는
네 명 모두 잘 만들어졌다고 봤으므로 그대로 두었다.

### 5. 질문창이 무엇을 입력하든 같은 답을 냈다

기획자가 최우선으로 꼽았다. "32초 동안 설득해 놓고 관객이 확인하려
손을 대는 바로 그 순간 제품이 거짓말을 한다."

**조치** — 답한 질문을 되받아 적고, 샘플과 다른 걸 물었으면 한 줄로 밝힌다.
못 하는 걸 숨기는 것보다 덜 깎인다.

### 6. 표가 증명한 것과 답의 근거가 어긋났다

실무자·기획자 공통. 답 칩에 `WMS`가 있는데 표에는 WMS 열도 재고 열도 없다.
**표를 유심히 본 사람일수록 잡아낸다. 이 문서의 관객이 정확히 그런 사람들이다.**

**조치** — 답의 근거를 표에 있는 프로그램(`영업관리`)으로 맞췄다.
깔린 `ops.jpg`가 실제로 재고 필드를 담은 영업관리 화면이므로 사실에도 맞는다.

### 7. 디자이너가 픽셀 실측으로 짚은 다섯 가지

- **명패에 스프레드시트 얼룩** — `.gcard__shot`의 `transition:opacity`가
  `row-mode`의 `opacity:0`을 무력화해 computed가 `.72`로 남아 있었다.
  주석이 "이런 사고를 막는다"고 적어 둔 바로 그 사고가 두 줄 아래에서
  일어나고 있었다. 트랜지션 제거.
- **열 머리 출처 라벨 대비 1.88:1** — 캡션이 대놓고 읽으라고 지시하는 줄인데
  이 문서에서 가장 안 읽혔다. 중성 먹으로 약 5.5:1 확보.
- **비행의 결론이 표에 남지 않음** — 카드의 색 띠가 열 머리 괘선에 내려앉는
  0.3초가 이 연출 최고의 디테일인데, 카드를 지우며 색까지 지워 완성된 표는
  전 열 균일한 회색이었다. **보여준 다음 도로 가져간 셈.** 색 밑줄을 남겼다.
  클래스가 아니라 `--keyed`를 트윈하므로 딥링크(`tl.seek`)에서도 재현된다.
- **세로가 긴 화면에서 퇴장 중인 글자가 열 머리를 덮음** — `AXIS 2.45→2.90`.
- **다섯 판이 동시 착지해 하나의 회색 띠** — `FLYS .085→.17`,
  면 해체를 비행 40% 지점부터 시작.

### 8. 214분 장의 엑셀이 사실상 보이지 않았다

실무자·디자이너 공통. 디자이너 실측으로 원인이 밝기가 아니라 **방사형 스크림
바깥 stop**(`.48`)임이 밝혀졌다 — 가장자리 진폭이 4/255밖에 남지 않았다
(카드는 112, 28배 차이). 중앙은 그대로 덮고 바깥만 열었다.

### 9. 개발팀장이 CDP 실측으로 짚은 것

- **수렴 장 중반 리사이즈에서 명패가 흩어진 자리로 순간이동** (블로커) —
  `placeCards()` 가 이 장을 "흩어진 상태" 하나로만 취급했다. 장을 합치면서
  시작과 끝이 달라졌는데 진입 상태는 하나뿐이었고, `abortFlight()` 는 비행이
  시작된 뒤에만 개입해 **1.45~3.62초 사이 1.8초가 비어 있었다.**
  모바일에서는 주소창이 접히는 것만으로 상시 재현된다.
  장 안에서는 `tl.time()` 으로 상태를 가르도록 고쳤다.
- **폰트 CDN 이 렌더 차단이라 응답이 느리면 21초 백지** (블로커) —
  GSAP 은 사본으로 옮겼지만 Pretendard 는 `<head>` 의 차단 stylesheet 였다.
  연결 거부(즉시 실패)에서만 빨랐던 것이고, **응답 없는 지연에서는 뒤따르는
  인라인 스크립트까지 막혀 자구책도 못 돌았다.** 비차단 로드로 바꿨다.
- **축소모션 우회** — 내가 이번 라운드에 넣은 `forcePlay` 에 `step=` 이 들어가
  **공유된 `#step=4` 를 여는 것만으로** 축소모션 사용자에게 연출이 강제됐다.
  딥링크는 정확히 "메신저로 돌려 보는 주소"다. `#play` 로만 되돌리도록 좁혔다.
- **`document.write` GSAP 폴백 제거** · **재생 1회당 GSAP 경고 17건 제거**
  (이 소음이 정작 필요한 경고를 묻는다).

### 10. 세로 흐름 전면 재작업

개발팀장이 비블로커로 기록한 두 가지가 같은 뿌리였다.
**JS 의 모바일 경계(640)와 CSS 의 900 사이가 어느 쪽 처리도 못 받아**
768(아이패드 세로)에서 카드가 헤드라인을 덮었고, 세로 자리를 `fy*H` 로 잡은 탓에
화면이 짧을수록 간격만 줄어 카드가 겹쳤다(실측 iPhone SE 42~47px).

경계를 CSS 에 맞추고, 세로 자리와 **카드 높이 자체를 남은 띠에서 계산**하도록
바꿨다. 667 높이에서도 다섯 장이 겹치지도 잘리지도 않는다. 넓은 폭은 손대지 않았다.

## 반영하지 않은 것과 이유

| 지적 | 판단 |
|---|---|
| 표의 `오류/DB로그` 열을 `재고/WMS`로 교체 (기획자 권장안) | 다섯 카드와 다섯 열의 1:1 짝이 비행 연출의 근거다. 이걸 깨는 대신 답 칩을 표 안의 프로그램으로 맞췄다 — 기획자가 제시한 대안 쪽 |
| "연출 중 홈 카드 윗변 5px 누출" (기획자) | 확대해 확인한 결과 **하단 진행 표시줄**이었다. 의도된 UI이고 결함이 아니다 |
| 214분의 돈·인원 환산 (임원, 2회 요청) | 실제 월 질의 건수와 인건비 기준이 필요하다. **발주자 확인 사항으로 남긴다** — 경영 회의에 들고 갈 것이라면 이 한 줄의 값이 가장 크다 |
| `beh`·`mon` 캡처 재촬영 (디자이너) | "어느 회사에나 있는 옅은 표"로 보여 고유성을 못 낸다는 지적. 재촬영이 필요해 **다음 판으로** |
| 폴백 경로의 낭비 전송 157KB (개발팀장) | 축소모션 폴백에서 한 번도 안 쓰는 캡처·GSAP 을 그대로 받는다. 조건부 로드는 정적 우선 구조를 복잡하게 만들어 **이득 대비 위험이 크다고 판단** |
| 임베드 불가 (개발팀장) | 전면 `position:fixed` 구조상 포털 셸에 못 끼운다. 단독 온보딩 티저 용도에는 문제없어 그대로 둔다 |

### 검증하지 못한 것

**응답 없는 CDN 에서의 개선 효과를 수치로 재현하지 못했다.** 헤드리스의
가상 시간은 응답 없는 요청에서 그대로 멈춰 스크린샷 자체가 나오지 않는다.
비차단 로드는 표준 패턴이고 구조적으로는 확실하지만, **21초가 몇 초로 줄었는지는
실제 환경에서 한 번 확인이 필요하다.**

## 개발팀장 6라운드에서 닫힌 배포 차단 (요약)

| 라운드 | 차단 | 조치 |
|---|---|---|
| 1 | 홈 질문창이 **마우스로 조작 불가** — 키보드로는 멀쩡해 다섯 라운드가 통과시켰다 | `.stage` 의 `pointer-events:none` 을 질문창에만 되살리고, 전면 `#nodes` 컨테이너는 클릭을 통과시키고 카드만 받게 함 |
| 1 | 비행 중 리사이즈에서 **색 밑줄 영구 소실** | `abortFlight()` 가 `--keyed` 를 복구 |
| 1 | 901~1024 에서 카드가 헤드라인 침범 | `flowDown` 경계를 `matchMedia` 로 CSS 와 통합 |
| 2 | **폰트 CDN 이 렌더 차단** — 무응답 시 45초에도 백지 | 비차단 로드. 실측 first paint 184ms |
| 3 | 1366×768 에서 답을 열면 **입구 3개가 화면 밖**(스크롤 불가) | 남은 세로에서 열 구성·카드 크기를 함께 고름 |
| 5 | 폰(375×667·360×640)에서 **입구 2개가 화면 밖** | 세로 맞춤을 모바일에도 적용 |
| 6 | 배율 하한 `.70` 이 가로·세로 맞춤을 무효화해 **8개 해상도에서 화면 밖** | 하한을 후보 선택 단계로 이동 |

### 이 중 절반은 내가 만든 결함이다

`.70` 하한 · `ResizeObserver` 충돌 · 8px 경계 어긋냄 · "답 높이는 잴 수 없다"는
잘못된 진단이 그렇다. 특히 마지막 것은 `display:none` 인 요소의 높이가 0 으로
나오는 것을 "구조적으로 불가능"으로 일반화한 것이었고, 이 파일의 `measureFly()`
가 이미 쓰던 기법(클래스를 잠깐 켜고 동기 레이아웃을 강제해 재기)으로 간단히
풀렸다. **한 번 실패한 측정을 일반화하기 전에 같은 파일 안의 선례를 먼저 볼 것.**

또 하나 — 5차에서 보고한 "답 카드 겹침 45~66px" 은 **없는 결함이었다.**
`moveNodes` 가 0.6초 트윈이라 클릭 직후에 읽으면 출발점이 나온다.
계측할 때는 `gsap.getTweensOf(node).length === 0` 을 기다려야 한다.

## 남은 항목 (전부 "낮음" · 배포를 막지 않음)

1. **`aria-live` 무음** — 답 카드 내용이 안 바뀌면 스크린리더가 아무것도 안 읽는다.
   샘플 질문 그대로 물었을 때가 그렇다
2. **스파크라인** — JS 차단 문서에서 빈 칸으로 남는다
3. **죽은 버튼** — `noGsap`·JS 차단 경로에서 `샘플 답` 버튼이 눌려도 아무 일이 없다
   (답은 이미 떠 있고 `readonly` 라 오해 소지는 낮다)
