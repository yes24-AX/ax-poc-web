# 크레마클럽 이용권 폐기·환불 CS 조회 (Datahub 조회 메뉴) — POC 사양

CS로 접수되는 "크레마클럽 이용권 폐기/환불" 문의를 담당자가 관리프로그램에 직접 들어가지 않고
판단할 수 있도록, 필요한 이용권 상태와 도서 다운로드 이력을 **한 화면에서 조회**하는 Datahub 메뉴 샘플.

- 실행: `crema_pass_cs/index.html` 을 브라우저로 열면 됨 (빌드 불필요, 데이터는 전부 목업)
- 범위: **조회 전용**. 이용권 삭제·복구·환불 등 데이터 변경과 CS 자동 처리는 포함하지 않음

## 1. 화면 구성

### ① 이용권 상태 조회 (기본 화면)
1. **조회 조건** — 회원 ID/번호 · 이용권 번호 · CS 접수번호 중 하나로 조회. 샘플 칩 제공
2. **고객 / 문의 정보** — 마스킹된 회원 정보, 접수번호·접수일시·채널, 등록 단말, 문의 원문,
   AI 문의 분류 결과(`크레마클럽 > 이용권 폐기·환불` + confidence)
3. **담당자 판단 지원 요약** — 자동 판정(예: *예외 환불 검토 가능*) + 근거 문장 +
   `조회로 확인된 사실` / `담당자 확인 필요` 2열
4. **이용권 상태** — 요청서 항목 그대로 (관리프로그램 > 이용권 관리 > 이용권 목록과 동일 항목)
   - 이용권(종류) / 이용권 번호 / 등록 여부(등록일) / 이용 상태 / 다운로드 이력 / 등록일 / 유효기간 / 지급·구매 경로
   - 하단에 `발급 → 등록 → 이용 개시 → 다운로드 → 만료` 라이프사이클 타임라인
5. **이 이용권으로 다운로드한 도서** — 도서명·다운로드 일시·기기·상품번호. 없으면 "없음"을 명시적으로 표시
6. **회원 보유 이용권 목록** — 여러 장 보유 시 행 클릭으로 상세 전환 (이용권별 판정이 달라지는 케이스 대응)
7. **CS 처리 메모용 요약** — 요청서에 적힌 형식 그대로 텍스트 복사

```
[이용권 상태] CS-20260901-0142
- 이용권 : 크레마클럽 사은품 이용권 (1개월)
- 이용권 번호 : CRM-2608-8821-4417
- 이용권 등록 여부 : 등록 (2026.08.28)
- 이용 상태 : 사용
- 다운로드 이력 : 없음
- 등록일 : 2026.08.28
- 유효기간 : 2026.08.28 ~ 2026.09.27
- 자동 판정 : 예외 환불 검토 가능 (R2)
```

### ② 문의 접수 큐
AI 문의 분류가 대상 문의로 판정한 건 목록. 접수 즉시 자동 조회가 끝난 상태로 판정 배지가 붙고,
행 클릭 시 해당 건의 조회 결과로 이동. 상단 KPI: 오늘 접수 / 자동 조회 완료 / 판단 대기 / 조회 소요시간 절감.

### ③ 자동 판정 기준
규칙표(R1~R6)와 연동 필요 데이터 목록. 자동 판정은 **참고용**이며 최종 판단은 담당자가 한다는 점을 화면에 명시.

## 2. 자동 판정 규칙

| 규칙 | 조건 | 자동 판정 | 담당자 안내 |
|---|---|---|---|
| R1 | 미등록 (발급만 된 상태) | 폐기·환불 가능 | 유상 구매면 원거래 취소, 무상 지급이면 회수만 |
| R2 | 등록 + 다운로드 0건 + 등록 후 7일 이내 | 예외 환불 검토 가능 | 실사용 이력 없음. 담당자 승인 후 진행 |
| R3 | 등록 + 다운로드 0건 + 등록 후 7일 초과 | 예외 환불 검토 필요 | 잔여 기간·지급 경로 확인 후 판단 |
| R4 | 등록 + 다운로드 1건 이상 | 환불 불가 | 다운로드 목록을 근거로 안내 |
| R5 | 유효기간 만료 | 환불·연장 불가 | 만료일·만료 사유 안내 |
| R6 | 이미 폐기 처리됨 | 처리 완료 건 | 폐기 일시·처리자 확인 |

> 7일 기준은 예시값. 실제 운영 기준(예외 처리 허용 기간)은 CS 정책 확정 후 조정 필요.

## 3. 연동 필요 데이터

| 필요 항목 | 예상 소스 | 비고 |
|---|---|---|
| 이용권 종류 / 번호 | 크레마클럽 이용권 마스터 | 유형(사은품·프로모션·구매) 코드 매핑 필요 |
| 등록 여부 / 등록일 | 크레마클럽 이용권 등록 이력 | 미등록 건은 등록일 NULL |
| 이용 상태 / 개시일 / 만료일 | 크레마클럽 이용권 상태 | 미등록·사용·만료·폐기 4개 상태로 정규화 |
| 도서 다운로드 이력 | 크레마클럽 대출·다운로드 로그 | **이용권 번호 기준 조인 가능 여부가 핵심 확인 사항** |
| 회원 정보 / 구독 상태 | YES24 회원 · 크레마클럽 구독 | 마스킹 후 표기 |
| 결제·주문 정보 | eBook 주문 | 유상 구매 건 환불 시 원거래 확인용 |
| 문의 원문 / 문의 분류 | CS 접수 · AI 문의 분류 | 분류 결과가 대상 문의일 때만 자동 조회 트리거 |

## 4. 확인 필요 사항

1. **다운로드 이력을 이용권 번호로 특정 가능한지** — 회원이 여러 이용권을 순차 사용한 경우
   "이 이용권으로 받은 책"을 구분할 수 있어야 R2/R4 판정이 성립. 불가하면 기간 기준(등록~만료) 매칭으로 대체.
2. 크레마클럽 데이터가 Datahub로 적재되어 있는지 / 실시간 API 조회인지 (조회 지연 허용 범위)
3. 이용권 "폐기" 상태 값의 실제 코드 체계와 폐기 처리 이력(처리자·일시) 보관 여부
4. 예외 환불 허용 기준(등록 후 N일, 지급 경로별 차등) 정책 확정
5. 개인정보 노출 범위 — 회원 ID·주문번호 마스킹 수준, 조회 로그 적재 필요 여부
