AI 집계가 끝날 때마다 자동 생성
시안 메모 — 구현 조건과 판정 규칙
  • 데이터 원천: 쿠팡 발주서 목록 API(미출고 발주서, INSTRUCT). 출고예정일=estimatedShippingDate, 자사 상품번호=externalVendorSkuCode, 출고일=inTrasitDateTime.
  • 당일 출고 대상 = 출고예정일이 오늘이고 아직 출고되지 않은 주문. 출고 지연 = 출고예정일이 지났는데 출고되지 않았거나, 지연된 뒤 출고된 주문.
  • 지연일수 (쿠팡 방식): 출고예정일 다음 날부터 실제 출고일(미출고면 기준일)까지 세되 토요일은 포함, 일요일·공휴일은 제외, 단 출고일이 일요일이면 그날은 포함. 예) 9/11(금)→9/13(일) 출고 = 2일, 9/10(목)→9/16(수) 출고 = 5일.
  • 물류센터: 기존 사내 API /orders/fulfillment-centers/resolve(자사 주문번호 → 출고 센터, 1회 최대 1만 건). 001 파주 · 003 영남 · 004 SLC.
  • 쿠팡·자사 모두 경과: 쿠팡 주문시 출고예정일과 자사 출고예정일이 모두 지난 미출고 주문 — 물류팀 공유용 목록.
  • 자사 주문번호·공개주문번호: 쿠팡 API에는 없어 사내 주문번호 조회 API(신규)로 채웁니다. 쿠팡 주문번호 목록을 넘기면 자사 주문(PR_ORD_M)의 제휴사주문ID로 찾아 주문번호·공개주문번호를 돌려주는 방식입니다. 매핑이 늦은 주문은 다음 집계에서 채웁니다.
  • 일자별 추이·AI의 반복 지연 판단: 집계 이력이 쌓여야 정확해집니다.
  • AI의 상품군: 쿠팡 카테고리(productCategoryLevel1/2) 기준입니다. 실제 값은 첫 수집 후 확인합니다.
  • 갱신 주기: 요청서의 1순위는 10~30분 간격입니다. 30분 수집이 가능한지는 영업관리시스템과 함께 쓰는 API 호출 한도를 확인한 뒤 정합니다.
  • 구매자·수취인 정보는 수집 즉시 버리고 저장하지 않습니다. 별도 알림(메일·메신저)은 두지 않습니다(요청서 기준).
